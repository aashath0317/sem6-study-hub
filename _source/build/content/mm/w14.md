## Authoring turns assets into an application

:::key Authoring
**Multimedia authoring** integrates and orchestrates text, graphics, sound, video and animation into a planned title. The title may be interactive, partly interactive or non-interactive. Its structure, timing and controls should follow the intended message and audience needs.
:::

Creating a sound file or drawing is asset production. Authoring places those assets into an organised experience. A developer decides when a narration begins, which picture it explains, what a button does, and what happens after a user answers a question. Good authoring coordinates these relationships instead of merely collecting unrelated files.

An **authoring system** supplies pre-programmed elements and facilities for building multimedia titles. Templates, components, wizards and APIs can reduce the amount of low-level programming. An **authoring paradigm** or **metaphor** is the organising approach used by the system. Different paradigms suit different content and interaction needs.

The PDF names Flash, Animate, Dreamweaver, Captivate and Composica. It also describes historical Authorware and Director, and gives PowerPoint, Keynote, Moodle and Joomla as tools with authoring-related capabilities. These are the lesson's examples, not a claim that every named product is currently available, identical in purpose or suitable for every project. A system can combine paradigms.

Authoring can speed up development of computer-based training compared with building every feature from scratch. It does not eliminate research, asset preparation, design, testing or technical judgement. Select a tool for its output compatibility, supported media, interaction model and the skills of the development team.

## Storyboards and navigation

A **storyboard** is a screen-by-screen or shot-by-shot plan. It describes layout, content, media, timing, narration, effects and interaction. **Navigation** describes the routes between content units. A well-drawn screen is incomplete if the developer cannot tell what its controls should do.

For each screen, record its identifier, purpose, visual arrangement, assets, written or spoken text, controls and destinations. Note entry conditions and what happens when an action finishes. Include accessibility requirements such as readable text, captions and keyboard operation. The authored result should implement this plan consistently.

:::example Sri Lankan learning title
A road-safety lesson opens with a menu. The learner chooses a crossing demonstration, watches a short animation with narration, and answers a question. A wrong answer gives a specific explanation and a retry. A correct answer offers the next topic. A Home control returns to the menu. The storyboard must describe each screen and both feedback paths.
:::

## Four authoring paradigms and Activity 14.1

| Paradigm | How it organises work | Useful situation | Course example |
|---|---|---|---|
| Structure-based | Groups content through hierarchy, network or associations | A linked information title | Dreamweaver |
| Timeline-based | Places media along a time axis on tracks | A synchronised animated presentation | Flash/Animate |
| Scripting-language-based | Uses instructions for media, events, conditions and timing | Custom interactive behaviour | ActionScript |
| Flow-control-based | Connects action or interaction icons with a flow line | Rapid e-learning prototypes | Authorware or IconAuthor |

**Structure-based:** organise concepts into groups and subgroups. A high-level concept can link to several media items. Hierarchical, network and associative structures can represent different routes through a title. The focus is the organisation of the information, rather than one compulsory playback duration.

**Timeline-based:** give an item a start, end and track. Parallel tracks can show which objects play simultaneously. Changing one item's duration does not necessarily change another item's timing; check the resulting synchronisation. Navigation and interactive control can still be added to a timeline-based title.

**Scripting-language-based:** describe positions, events, hotspots, sequencing and synchronisation in a programming language. Conditions, variables and functions can support complex interaction. It is close to conventional programming and can take more development effort, while offering flexible control. The source describes interpreted and object-oriented scripting features; do not assume that every language or runtime uses the same execution method.

**Flow control:** choose operations from an icon palette and connect them to show the program's flow. It can be effective for a prototype or a short development cycle. A visual branch still requires a sensible condition, complete feedback paths and testing. The PDF calls this the speediest style; actual speed depends on the project and the developer.

**Activity 14.1 question:** find and describe tools exhibiting the four categories.

**Model answer:** use Dreamweaver to organise linked web content; its structure and links implement information relationships. Use Animate's timeline to position media and control when it appears. Use ActionScript in a suitable authoring environment to specify event-driven actions and conditional navigation. Use historical Authorware or IconAuthor to connect presentation and interaction icons into a flow. These explain the four features using the source's examples; a modern application may combine several features rather than belong exclusively to one category.

## Multimedia script writing

A multimedia script precisely describes the intended presentation. It can include visual, narrative, action and expression information. A script may exist without drawings, while a storyboard adds visual planning. Begin by thinking visually: link an idea to a graphic, action or other concrete way to communicate it. A mind map helps explore relationships, but the final production needs a clear sequence and usable directions.

The PDF's script-writing process has these stages:

1. **Program idea:** discuss the message, insight and possible way to express it.
2. **Program brief:** specify title, audience, objectives and content outline; include the rationale and beneficiaries where useful.
3. **Research:** investigate the topic and audience, checking accuracy and suitability.
4. **Identify and select content elements:** choose assets and plan their organisation and navigation.
5. **Interface design and layout:** make the appearance and actions fit the idea and audience.
6. **Prepare the storyboard:** describe every shot or screen in enough detail for production.

A vague script such as “show something interesting” leaves important decisions unresolved. A useful instruction says what appears, what the audience hears, what changes, and what triggers the next step. Match narration with the relevant image and leave time for the audience to understand it. Read narration aloud to detect awkward wording.

|---|---|---|
| Visual | Plan the road view, crossing position and readable labels | Framing and displayed content |
| Narrative | Write the explanation of checking before crossing | Exact spoken wording |
| Action | State when the person stops, looks and crosses | Observable movement and order |
| Expression | Specify a calm, clear delivery and attentive behaviour | Intended tone and performance |

Turn the brief into a script, then put the information into storyboard panels. Review whether the picture genuinely demonstrates the spoken instruction. Do not use an expressive performance that contradicts the intended safe action. In an interactive version, add the trigger for each event, the available user choices and feedback for each outcome.

## Asset orchestration and libraries

**Orchestration** coordinates imported assets according to the story. A library stores reusable symbols, bitmaps, video and sound. Place an **instance** of an asset where it is needed, then set its position, timing and behaviour. Keep meaningful names and group related items so the team can find and revise them.

The linked [Adobe library guide](https://helpx.adobe.com/animate/using/library.html) explains that Animate libraries contain created or imported assets and reusable symbols. Library folders and previews help organisation. A reusable item and an instance placed in a scene are different objects in the workflow; changing shared source content can affect its uses. Check replacement and naming conflicts carefully.

A useful inventory records filename, purpose, source, permitted use, format and the screens that use it. Check external links and referenced media after moving or packaging a project. An editor's working copy may use local absolute paths that fail on another device. Package the actual required media and use appropriate references in the published output.

## Distribution and Activity 14.3

**Distribution** shares, publishes and promotes the title through an appropriate medium. Select the route for the audience, then generate a supported output. Test throughout development and on the actual target hardware, software and playback mode. A successful authoring preview does not prove that a packaged title works elsewhere.

Check complete assets, navigation, event paths, timing, audio/video sync, readable text, supported media formats and installation instructions. Test a fresh packaged copy without relying on editor-only resources. Then prepare the final files and delivery documentation. The PDF lists optical disks, ZIP disks, servers, networks, broadcasts, social media and web pages; some are historical distribution examples.

**Activity 14.3 question:** research distribution constraints for web/social media, CD/DVD, intranet, VPN and television.

| Medium | Complete model answer: main constraints |
|---|---|
| Web and social media | Network rate, accepted codecs/containers, file-size and duration limits, aspect ratio, phone readability, captions and platform processing |
| CD or DVD | Fixed storage capacity, compatible disk/file formats, availability of drives, player compatibility and an update/replacement process |
| Intranet | Organisational network capacity, internal server configuration, authentication, approved browsers and access permissions |
| VPN | Remote access configuration, authentication, encryption overhead, connection reliability and effective bandwidth; a VPN is an access route, not a multimedia file format |
| Television broadcast | Broadcaster-specified picture, frame/scanning, colour, sound, caption and programme-delivery requirements; exact specifications must come from that broadcaster |

These constraints guide packaging. A local training disk must carry its needed assets; a network title needs working server paths; a broadcast master must match the receiving specification. Retain an editable master project and document the delivered version so later corrections can be made consistently.
