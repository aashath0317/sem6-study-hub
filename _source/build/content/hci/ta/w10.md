## செயலாக்கி சார்ந்த மற்றும் முன்கணிப்பாளர் சார்ந்த மாதிரிகள்

விரிவுரை, காணக்கூடிய உள்ளீடு/வெளியீட்டில் **செயலாக்கி செலுத்தும் கவனத்தையும்**, உள் பகுத்தறிதலில் **முன்கணிப்பாளர் செலுத்தும் கவனத்தையும்** வேறுபடுத்துகிறது. GOMS/KLM-இலும் அறிவாற்றல் செயல்கள் உள்ளன; அவை மனக் கூறுகள் இல்லாத மாதிரிகள் அல்ல. உண்மையான பகுத்தறிதல் **மறைமுகமானது, நுணுக்கமானது, அறிவாற்றல் சுமை நிறைந்தது**.

| | ⚙️ **செயலாக்கி சார்ந்தது** | 🧠 **முன்கணிப்பாளர் சார்ந்தது** |
|---|---|---|
| **வேர்கள்** | **நடத்தைவாதம்** | **அறிவாற்றல்வாதம்** |
| **கவனிப்பது** | **வெளியில் காணக்கூடிய செயல்கள்:** விசை அழுத்தங்கள், சுட்டி நகர்வுகள் | **காண முடியாத உள் பகுத்தறிதல்:** நினைவிலிருந்து மீட்டல், தேர்ந்தெடுத்த கவனம், முடிவுக் கிளைகள், மனச் சோர்வு |
| **மனிதரைப் பார்ப்பது** | இயந்திரக் கணக்கீட்டு அலகாக | சிந்திக்கும், உணரும், பகுத்தறியும் நபராக |
| **எடுத்துக்காட்டு முறை** | GOMS, KLM (9ஆம் வாரம்) | **அறிவாற்றல் பணி ஆய்வு** (இந்த வாரம்) |

## அறிவாற்றல் பணி ஆய்வு (CTA) — 5 படிகள்

**CTA**, சிக்கலான பணிகளை முடிக்கத் தேவையான **காண முடியாத அறிவாற்றல் செயல்முறைகளை முறையாகப் பிரித்தெடுத்து, கட்டமைத்து, உறுதிப்படுத்துகிறது**.

:::flow
1. தொடக்க அறிவைச் சேகரித்தல்
2. அறிவுப் பிரதிநிதித்துவங்களை அடையாளம் காணுதல்
3. பிரதிநிதித்துவங்களை நிரப்புதல்
4. பகுப்பாய்வு செய்து சரிபார்த்தல்
5. வடிவமைப்புக்கேற்ப அமைத்தல்
:::

| படி | செய்வது |
|---|---|
| **1. தொடக்க அறிவைச் சேகரித்தல்** | பயன்பாட்டுத் துறையை அறிய **உண்மையான பயனர்களை அவர்களது இயல்பான சூழலில் கவனித்தல்**. அத்துறையில் வல்லுநராக இருக்க வேண்டியதில்லை |
| **2. அறிவுப் பிரதிநிதித்துவங்களை அடையாளம் காணுதல்** | அறிவின் **வடிவத்தை** முடிவு செய்தல்: **கண்டிப்பான நேரியல் வரிசை**, **வரிசையற்ற பணித் தொகுப்பு**, அல்லது **இணைக்கப்பட்ட கருத்துகளின் வலையமைப்பு** |
| **3. பிரதிநிதித்துவங்களை நிரப்புதல்** | **உரக்கச் சிந்திக்கும் முறைகள்** மூலம் பயனர்கள் உண்மையில் **சிந்திப்பது, அறிந்திருப்பது, உணர்வதைச்** சேகரித்தல்; **இடையூறுகளிலிருந்து மீள்வதும்**, பயன்படுத்தும் **சூழல் குறிப்புகளும்** இதில் அடங்கும் |
| **4. பகுப்பாய்வு செய்து சரிபார்த்தல்** | மாதிரி அவர்களது **உண்மையான பணிப்பாய்வுடன்** பொருந்துகிறதா என்பதை உறுதிசெய்ய **உண்மையான பயனர்களுடன் முடிவுகளை மீளாய்வு செய்தல்** |
| **5. முடிவுகளை வடிவமைப்புக்கேற்ப அமைத்தல்** | உறுதிப்படுத்தப்பட்ட பாய்வுகளை **UI கட்டமைப்புகள், திட்டவரைபடங்கள், படிநிலை மரங்களாக** மாற்றுதல் |

## ஆய்வு: வாடிக்கையாளர் பின்னூட்டச் சிந்தனை ஓட்டம்

**வெளிப்பார்வையில்**, பின்னூட்டம் வழங்குவது மூன்று எளிய படிகளாகத் தெரிகிறது:

:::flow
பின்னூட்ட முறையைத் தேர்ந்தெடு
பின்னூட்டத்தை எழுது / கூறு
பின்னூட்டத்தைச் சமர்ப்பி
:::

**உண்மையில்**, “பின்னூட்டம் எழுதுதல்” என்பதற்குள் **பல அடுக்கு அறிவாற்றல் சுழற்சி** மறைந்துள்ளது:

<figure><img src="Figure%2010.2.PNG" alt="பின்னூட்டம் எழுதுவதற்குப் பின்னாலுள்ள அறிவாற்றல் ஓட்டம்"><figcaption>படம் 10.2: “பின்னூட்டத்தை எழுது/கூறு” என்பதற்குள்ளுள்ள உண்மையான அறிவாற்றல் ஓட்டம்</figcaption></figure>

1. **சேவை அனுபவத்தை நினைவுகூர்தல்** (நினைவு)
2. **சேவைத் தரத்தை மதிப்பிடுதல்** (பகுத்தறிதலும் உணர்ச்சியும்)
3. **கூற வேண்டியவற்றை மனதில் முடிவுசெய்து ஒழுங்குபடுத்துதல்** (முடிவு)

பயனர் இவற்றைப் பலமுறை சுற்றிவரலாம். செயலாக்கி மாதிரி “தட்டச்சு செய்தல்” என்பதை மட்டுமே காணும். நல்ல வடிவமைப்பு ஆதரிக்க வேண்டிய சிந்தனையை CTA வெளிப்படுத்துகிறது; எடுத்துக்காட்டாக, *“விநியோக வேகம் எப்படி இருந்தது?”* போன்ற வழிகாட்டும் கேள்விகள் மூலம்.

## படிநிலை பணி ஆய்வு (HTA)

<figure><img src="Figure%2010.1.PNG" alt="பின்னூட்டப் பணியின் மேல்நிலை"><figcaption>படம் 10.1: “பின்னூட்டம் வழங்கு” என்பதன் மேல்நிலை: முறையைத் தேர்ந்தெடு → எழுது/கூறு → சமர்ப்பி</figcaption></figure>

**HTA உயர்நிலை இலக்குகளை ஒன்றினுள் ஒன்றாக உள்ள துணைப் பணிகள், அடிப்படைச் செயல்பாடுகள், திட்டங்களாகப் பிரிக்கிறது.** இதை **உரையாக எழுதலாம்** அல்லது **மர வரைபடமாக வரையலாம்**. பொதுவாக முதலில் **உரை வடிவத்தை** உருவாக்குவீர்கள் [[v2 00:00]].

### உரை வடிவ HTA

```
0. பின்னூட்டம் வழங்கு
   1. பின்னூட்ட முறையைத் தேர்ந்தெடு
   2. பின்னூட்டத்தை எழுது / கூறு
      2.1 மின்னஞ்சலைத் திற      ┐ மின்னஞ்சல் கிளை
      2.2 மின்னஞ்சலை எழுது      ┘
      2.3 படிவத்தைத் திற         ┐ படிவக் கிளை
      2.4 படிவத்தை நிரப்பு       ┘
   3. பின்னூட்டத்தைச் சமர்ப்பி
      3.1 மின்னஞ்சலை அனுப்பு (அனுப்பு என்பதைச் சொடுக்கு)
      3.2 படிவத்தைச் சமர்ப்பி (சமர்ப்பி என்பதைச் சொடுக்கு)

திட்டம் 0: 1 – 2 – 3ஐ வரிசையாகச் செய்
திட்டம் 2: முறை = மின்னஞ்சல் எனில் 2.1, 2.2ஐ வரிசையாகச் செய்; இல்லையெனில் 2.3, 2.4ஐ வரிசையாகச் செய்
திட்டம் 3: முறை = மின்னஞ்சல் எனில் 3.1ஐச் செய்; இல்லையெனில் 3.2ஐச் செய்
```

:::key திட்டங்கள்
**எந்த வரிசையில், எந்த நிபந்தனையில்** துணைப் பணிகள் செய்யப்படுகின்றன என்பதை **திட்டம்** கூறுகிறது. ஒரு நேரத்தில் **2.1 + 2.2 அல்லது 2.3 + 2.4** மட்டுமே செய்யப்படும்; இரண்டும் அல்ல [[v2 02:35]].
:::

<figure><img src="Figure%2010.4.PNG" alt="HTA வரைபடம்: பார்வை 1"><figcaption>படம் 10.4: திட்டங்களுடன் பாடத்தின் HTA வரைபடம்: மின்னஞ்சல் எனில் 2.1, 2.2; இல்லையெனில் 2.3, 2.4; மின்னஞ்சல் எனில் 3.1; இல்லையெனில் 3.2</figcaption></figure>

### வரைபடத்தை வாசித்தல்: மேலிருந்து கீழாக, இடமிருந்து வலமாக [[v2 03:51]]
இந்த வரைபடத்தில் வேரிலிருந்து கீழாக வாசித்து, வரிசையையும் நிபந்தனைகளையும் தீர்மானிக்க எழுதப்பட்ட **திட்டங்களைப்** பயன்படுத்துங்கள். தொடருமுன் தேர்ந்தெடுத்த துணைப் பணிக் கிளையை முடிக்கவும். இடமிருந்து வலமான அமைப்பு மட்டும் ஒவ்வொரு HTA திட்டத்தையும் வரையறுப்பதில்லை.

:::html
{{tool:hta}}
:::

### மாற்றுப் பிரிப்பு (பார்வை 2)

<figure><img src="Figure%2010.6.PNG" alt="HTA வரைபடம்: பார்வை 2"><figcaption>படம் 10.6: மாற்றுப் பிரிப்பு: பின்னூட்டத்தைச் சமர்ப்பித்தலுக்குள் ஆறு துணைப் பணிகளும் உள்ளன; திட்டம் மின்னஞ்சலை (2.1 முதல் 2.3 வரை) அல்லது படிவத்தை (2.4 முதல் 2.6 வரை) தேர்ந்தெடுக்கிறது</figcaption></figure>

ஒரே இலக்கை வெவ்வேறு விதமாகப் பிரிக்கலாம். PDF-இன் இரண்டாவது பார்வை **எழுதுவதைச் சமர்ப்பிப்பதற்குள்** வைக்கிறது:

```
0. பின்னூட்டம் வழங்கு
   1. பின்னூட்ட முறையைத் தேர்ந்தெடு
   2. பின்னூட்டத்தைச் சமர்ப்பி
      2.1 மின்னஞ்சலைத் திற   2.2 மின்னஞ்சலை எழுது   2.3 மின்னஞ்சலை அனுப்பு
      2.4 படிவத்தைத் திற      2.5 படிவத்தை நிரப்பு    2.6 படிவத்தைச் சமர்ப்பி
திட்டம் 2: மின்னஞ்சல் எனில் 2.1–2.3ஐச் செய்; இல்லையெனில் 2.4–2.6ஐச் செய்
```

:::tip ஒரே ஒரு “சரியான” HTA இல்லை
வெவ்வேறு ஆய்வாளர்கள் வெவ்வேறான, ஆனால் செல்லுபடியாகும் படிநிலைகளை உருவாக்குகிறார்கள். பிரிப்பு **முழுமையாகவும்**, **திட்டங்கள் தெளிவாகவும்**, **பயனர்கள் உண்மையில் வேலை செய்யும் விதத்துடன்** பொருந்துவதாகவும் இருப்பதே முக்கியம்.
:::

## கூறுநிலைத்தன்மையும் பிரித்து வெல்லுதலும்

பணிகளைக் கட்டமைக்கப்பட்ட துணைப் பணிகளாகப் பிரிப்பது, **பயன்பாடுகளுக்கிடையே மாற்றிப் பயன்படுத்தக்கூடிய பொதுவான கூறு வடிவங்களை** வெளிப்படுத்துகிறது:

**🛒 மின்வணிகக் கொள்முதல் நிறைவு**

ஒவ்வொரு இணையக் கடையும் **பொருள் வண்டி**, **கட்டண மேசை** என்ற இயற்பொருள் ஒப்புமைகளைப் பயன்படுத்துகிறது. இந்தத் துணைப் பணி **தரப்படுத்தப்பட்டிருப்பதால்**, விற்பனையாளர்கள் புதிதாக உருவாக்குவதற்குப் பதில் **இருக்கும் கட்டணக் கருவிகளை** (PayPal, Stripe) **உட்பொதிக்கலாம்**.
+++
**🧩 UI வடிவமைப்பில் பிரித்து வெல்லுதல்**

படிநிலை **கருத்தியல் பிரித்தெடுப்பை** இயலச் செய்கிறது. வடிவமைப்பாளர்கள் **தீர்க்கப்பட்ட துணைச் சிக்கல்களை** (உள்நுழைவு, தேடல், கொள்முதல் நிறைவு) பிரித்தெடுத்து மீண்டும் பயன்படுத்தலாம்; **தமது தயாரிப்பைத் தனித்துவமாக்குவதில்** படைப்பாற்றலைச் செலவிடலாம்.
:::

:::exam தேர்வில் கவனம் செலுத்த வேண்டியவை
வழக்கமான கேள்விகள்:

- “செயலாக்கி சார்ந்த மற்றும் முன்கணிப்பாளர் சார்ந்த மாதிரிகளை வேறுபடுத்துக”
- “CTA-இன் 5 படிகளை விளக்குக”
- “X பணிக்கான உரை **மற்றும்** வரைபட வடிவ HTA-ஐத் திட்டங்களுடன் வரைக”; எ.கா. ATM-இல் பணம் எடுத்தல் அல்லது பயணச்சீட்டு பதிவு செய்தல்

முனைகளுக்கு எப்போதும் எண்களிடுங்கள் (1, 1.1, 1.2…); **திட்டங்களை** எழுதுங்கள்; **மேலிருந்து கீழாக, இடமிருந்து வலமாக** என்பதை நினைவில் கொள்ளுங்கள்.
:::

## விரைவு மீளாய்வுத் தாள்

| கருத்து | இவ்வாறு நினைவில் கொள்க |
|---|---|
| செயலாக்கி சார்ந்தது | நடத்தைவாதம்; காணக்கூடிய செயல்கள் (GOMS) |
| முன்கணிப்பாளர் சார்ந்தது | அறிவாற்றல்வாதம்; மறைந்த பகுத்தறிதல், நினைவு, கவனம் |
| CTA | காண முடியாத அறிவாற்றலை வெளிப்படுத்துகிறது |
| 5 படிகள் | சேகரி → பிரதிநிதித்துவங்களை அடையாளம் காண் → நிரப்பு (உரக்கச் சிந்தித்தல்) → பயனர்களுடன் சரிபார் → வடிவமைப்புக்கேற்ப அமை |
| பின்னூட்ட ஓட்டம் | அனுபவத்தை நினைவுகூர் → தரத்தை மதிப்பிடு → கூற வேண்டியதை ஒழுங்குபடுத்து |
| HTA | இலக்கு → துணைப் பணிகள் → செயல்பாடுகள் + திட்டங்கள்; முதலில் உரை, பின்னர் வரைபடம் |
| திட்டம் | வரிசையும் நிபந்தனைகளும் (மின்னஞ்சல் எனில் 2.1, 2.2; இல்லையெனில் 2.3, 2.4) |
| மரத்தில் பயணம் | மேலிருந்து கீழாக, இடமிருந்து வலமாக; துணைக் கிளைகளை முதலில் முடி |
| கூறுநிலைத்தன்மை | தரமான துணைப் பணிகளை (கொள்முதல் நிறைவு, உள்நுழைவு) மீண்டும் பயன்படுத்தலாம் (PayPal, Stripe) |
