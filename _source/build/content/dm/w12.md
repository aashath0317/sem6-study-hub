## Bayesian classifiers — overview

- **Bayesian classifiers are statistical classifiers.** They predict **class membership probabilities**, i.e. the probability that a tuple belongs to a class.
- They're based on **Bayes' theorem**.
- The simple **naïve Bayesian classifier** performs **comparably to decision trees and some neural networks**, with **high accuracy and speed on large databases**.

:::key Why "naïve"?
It assumes that **the effect of an attribute value on a class is independent of the other attributes' values**. This is called **class-conditional independence**. The assumption simplifies computation, which is why it's called "naïve".
:::

**Bayesian belief networks** are **graphical models** that, unlike naïve Bayes, **can represent dependencies** among subsets of attributes. They can also be used for classification.

## Bayes' theorem

Named after **Thomas Bayes**, an 18th-century English nonconformist clergyman who worked on probability and decision theory.

| Symbol | Name | Example meaning (customer aged 35, income $40,000) |
|---|---|---|
| **X** | **Evidence**: the data tuple | The customer's age and income |
| **H** | **Hypothesis**: X belongs to class C | "Will buy a computer" |
| **P(H\|X)** | **Posterior** (a posteriori) probability of H given X | Probability **this** customer buys a computer |
| **P(H)** | **Prior** probability of H | Probability **any** customer buys a computer |
| **P(X\|H)** | Posterior of X given H (**likelihood**) | Probability a buyer is 35 and earns $40,000 |
| **P(X)** | **Prior** probability of X | Probability a customer is 35 and earns $40,000 |

:::formula
**P(H | X) = P(X | H) · P(H) / P(X)**
:::

:::example Meningitis
- Meningitis (M) causes a stiff neck (S) 50% of the time: P(S|M) = 0.5
- P(M) = 1/50,000
- P(S) = 1/20

If a patient has a stiff neck, what is the probability of meningitis?

P(M|S) = P(S|M)·P(M) / P(S) = 0.5 × (1/50,000) / (1/20) = **0.0002**

So even with a stiff neck, meningitis is very unlikely, because its prior is tiny.
:::

## The naïve Bayesian classifier

**Setup:**

- Training set D. Each tuple is X = (x₁, …, xₙ) over attributes A₁ … Aₙ.
- There are m classes C₁ … Cₘ.

:::key Decision rule
Predict the class Cᵢ with the **highest posterior probability**, the **maximum posterior hypothesis**:

P(Cᵢ|X) > P(Cⱼ|X) for all j ≠ i
:::

By Bayes: P(Cᵢ|X) = P(X|Cᵢ)P(Cᵢ) / P(X).

1. **P(X) is the same for every class**, so maximise only **P(X|Cᵢ)·P(Cᵢ)**.
2. If class priors are **unknown**, assume all classes are **equally likely** and maximise **P(X|Cᵢ)**. Otherwise estimate **P(Cᵢ) = |Cᵢ,D| / |D|**.
3. Computing P(X|Cᵢ) directly is too expensive with many attributes. **Class-conditional independence** gives:

:::formula
P(X | Cᵢ) = Π<sub>k=1..n</sub> P(x<sub>k</sub> | Cᵢ) = P(x₁|Cᵢ) × P(x₂|Cᵢ) × … × P(xₙ|Cᵢ)
:::

### Estimating P(xₖ|Cᵢ)

:::grid
**Categorical attribute**

P(xₖ|Cᵢ) = (number of class-Cᵢ tuples with value xₖ) / |Cᵢ,D|
+++
**Continuous attribute**

Assume a **Gaussian (normal)** distribution with mean μ and standard deviation σ for that class:

g(x, μ, σ) = 1/(√(2π)·σ) · e<sup>−(x−μ)² / (2σ²)</sup>

P(xₖ|Cᵢ) = g(xₖ, μ<sub>Cᵢ</sub>, σ<sub>Cᵢ</sub>)
:::

:::example Gaussian example
Buyers' ages are 38 ± 12 (μ = 38, σ = 12). For X with age = 35:

P(age = 35 | yes) = 1/(√(2π)·12) · e<sup>−(35−38)²/(2·12²)</sup> = 0.0332 × e<sup>−0.03125</sup> ≈ **0.0322**
:::

## Worked example — will X buy a computer?

Same 14-tuple training set as Week 11 (9 yes, 5 no). Classify:

:::formula
X = (age = youth, income = medium, student = yes, credit_rating = fair)
:::

**Priors**

- P(yes) = 9/14 = **0.643**
- P(no) = 5/14 = **0.357**

**Conditional probabilities**

| | P(·\|yes) | P(·\|no) |
|---|---|---|
| age = youth | 2/9 = 0.222 | 3/5 = 0.600 |
| income = medium | 4/9 = 0.444 | 2/5 = 0.400 |
| student = yes | 6/9 = 0.667 | 1/5 = 0.200 |
| credit_rating = fair | 6/9 = 0.667 | 2/5 = 0.400 |

**Multiply**

- P(X|yes) = 0.222 × 0.444 × 0.667 × 0.667 = **0.044**
- P(X|no) = 0.600 × 0.400 × 0.200 × 0.400 = **0.019**

**Times the priors**

- P(X|yes)·P(yes) = 0.044 × 0.643 = **0.028**
- P(X|no)·P(no) = 0.019 × 0.357 = **0.007**

0.028 > 0.007, so the prediction is **buys_computer = yes**.

## Rule-based classification

A **rule-based classifier** uses a set of **IF-THEN rules**:

:::formula
**R1: IF** age = youth **AND** student = yes **THEN** buys_computer = yes
(age = youth) ∧ (student = yes) ⇒ (buys_computer = yes)
:::

| Part | Name |
|---|---|
| IF part (left-hand side) | **Rule antecedent** or **precondition**: one or more attribute tests **ANDed** together |
| THEN part (right-hand side) | **Rule consequent**: the **class prediction** |

If all the tests in the antecedent hold for a tuple, the rule is **satisfied** and **covers** the tuple.

### Coverage and accuracy

:::formula
**coverage(R)** = n<sub>covers</sub> / |D|      **accuracy(R)** = n<sub>correct</sub> / n<sub>covers</sub>
:::

- **n<sub>covers</sub>** = number of tuples the rule covers
- **n<sub>correct</sub>** = number of those it classifies correctly
- **|D|** = total number of tuples

:::example R1 on the 14-tuple data
R1 covers **2** tuples (RIDs 9 and 11, both youth students) and gets **both** right.

- coverage = 2/14 = **14.28%**
- accuracy = 2/2 = **100%**
:::

## Extracting rules from a decision tree

Decision trees are accurate and easy to understand, but **large trees get hard to interpret**. IF-THEN rules can be **easier for humans**, especially when the tree is very big.

:::key How to extract
- Create **one rule per path from the root to a leaf**.
- The **splitting criteria along the path are ANDed** to form the antecedent.
- The **leaf's class** is the consequent.
:::

From the buys_computer tree (age → student / yes / credit_rating):

| Rule | IF | THEN |
|---|---|---|
| R1 | age = youth AND student = no | buys_computer = **no** |
| R2 | age = youth AND student = yes | buys_computer = **yes** |
| R3 | age = middle_aged | buys_computer = **yes** |
| R4 | age = senior AND credit_rating = excellent | buys_computer = **no** |
| R5 | age = senior AND credit_rating = fair | buys_computer = **yes** |

:::warn Careful: the PDF swaps R4 and R5
The lesson PDF says senior + excellent → yes and senior + fair → no. The data says otherwise. The senior + excellent tuples (RIDs 6 and 14) are both **no**, and the senior + fair tuples (4, 5, 10) are all **yes**. Use the table above. You can check it in the rule evaluator.
:::

Properties of rules extracted from a tree:

- **Mutually exclusive**: no two rules cover the same tuple.
- **Exhaustive**: there's a rule for every combination of attribute values.

## Quick revision sheet

| Concept | Remember it as |
|---|---|
| Bayesian classifier | Statistical; predicts class membership probabilities |
| Naïve | Class-conditional independence |
| Bayes' theorem | P(H\|X) = P(X\|H)P(H) / P(X); posterior vs prior |
| Meningitis | 0.5 × (1/50000) / (1/20) = 0.0002 |
| Decision | Maximise P(X\|Cᵢ)·P(Cᵢ) (P(X) is constant) |

| Tree → rules | One rule per root-to-leaf path; mutually exclusive and exhaustive |
| Belief networks | Graphical; allow dependencies between attributes |
