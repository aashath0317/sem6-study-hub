1Why preprocessing is needed

தரவை ஏன் முதலில் தயார் செய்ய வேண்டும்?

காணாத மதிப்பு, தவறான வயது, ஒரே நபரின் இரட்டைப் பதிவு போன்றவை முடிவை மாற்றும். இவற்றைச் சரிசெய்து algorithm-க்கு ஏற்றதாக்குவதே Preprocessing. நல்ல model-க்கு நல்ல input தேவை.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Incomplete=missing; noisy=பிழை/measurement variation; inconsistent=codes/formats முரண்பாடு. Entry, instruments, transmission, duplicates, பழைய data, source differences காரணமாகலாம். Cleaning, integration, transformation, reduction நான்கு preprocessing குடும்பங்கள். “70–80% effort” பாடத்தில் சொல்லப்படும் rough estimate; ஒவ்வொரு project-க்கும் fixed அளவு அல்ல.

Real-world databases and data warehouses are commonly incomplete, noisy and inconsistent. Mining dirty data gives poor results, and users don't trust results from data they believe is dirty.

Incomplete (missing values)

  • Attribute of interest not available (e.g. customer info on sales records)
  • Not considered important at entry time
  • Misunderstanding or equipment malfunction
  • Inconsistent data deleted
  • History / modifications not recorded

Noisy (incorrect values)

  • Faulty data collection instruments
  • Human or computer errors at data entry
  • Transmission errors
  • Technical limits (e.g. limited buffer size)
  • Inconsistent naming conventions / codes, incompatible formats (dates)
  • Duplicate tuples
Two numbers to remember
  • In the KDD life cycle, data preprocessing comes after data understanding.
  • Data preparation takes about 70–80 % of the time and effort of a knowledge discovery project.

Mining routines do have some ways of handling incomplete or noisy data, but they are not always robust. They focus mostly on avoiding overfitting. So it is useful to run the data through data cleaning routines first.

The four preprocessing techniques

Technique Purpose
Data cleaning Fill missing values, smooth noise, identify/remove outliers, resolve inconsistencies
Data integration Merge multiple sources into one coherent store (e.g. a data warehouse)
Data transformation e.g. normalization, which improves accuracy and efficiency of distance-based algorithms
Data reduction Reduce size by aggregating, removing redundant features, clustering (Week 4)

2Data cleaning — handling missing values

காணாத மதிப்பை நிரப்புதல்

காலியான cell-ஐ எப்போதும் பூஜ்யமாக மாற்றக்கூடாது. Mean, அதே class-இன் mean, அல்லது பொருத்தமான prediction பயன்படுத்தலாம். எந்த முறை சரி என்பது missing value ஏற்பட்ட காரணத்தையும் தரவின் வகையையும் பொறுத்தது.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Missing values-க்கு: record-ஐ விலக்குதல்; மனிதர் நிரப்புதல்; global constant; attribute mean; அதே class mean; probable value prediction ஆகிய வழிகள் உண்டு. குறைந்த records என்றால் manual சாத்தியம்; அதிகமானால் செலவு அதிகம். Class label missing என்றால் supervised training-இல் சிக்கல்; mean நிரப்புவது class label-க்கு பொருத்தமில்லை. Test data-வின் தகவலால் training imputation-ஐ அமைக்காதீர்கள்; leakage ஏற்படும்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

ஆறு missing-value வழிகள்: row drop; manual fill; Unknown போன்ற constant; overall mean; same-class mean; பிற attributes கொண்டு predicted value. உதாரண incomes 80k,70k,30k,44k→overall 56k; Low-risk 80k,70k→75k. Unknown-ஐ meaningful category என model தவறாகக் கருதலாம். Predicted 76k toy value; actual fitted model இல்லாமல் அது கணக்கிடப்பட்ட உண்மை அல்ல. Evaluation-இல் imputation/scaling training data-இல் மட்டும் fit செய்யவும்; test label தெரியாதபோது class-mean பயன்படுத்த முடியாது.

Six methods, from simplest to smartest:

# Method How Weakness / note
1 Ignore the tuple Drop the row. Usually done when the class label is missing Not useful unless the tuple has several missing attributes; weak when % missing varies a lot per attribute
2 Fill in manually A person enters each value Time-consuming; not feasible for large data
3 Global constant Replace all missing values with e.g. "Unknown" or −∞ The algorithm may think "Unknown" is an interesting concept because many tuples share it, so it is not foolproof
4 Attribute mean Use the mean of the attribute, e.g. average income Rs 56,000 Ignores the class of the tuple
5 Attribute mean for the same class Use the mean of tuples in the same class, e.g. average income of customers in the same credit-risk category Smarter than 4
6 Most probable value Predict with regression, Bayesian inference or a decision tree Uses information from other attributes; suitability depends on missingness and the model

3Noisy data and smoothing

Noise-ஐக் குறைத்தல்

வழக்கமான வடிவத்தை மறைக்கும் சிறிய சீரற்ற மாற்றங்கள் Noise. அருகிலுள்ள மதிப்புகளை bins-ஆகப் பிரித்து mean அல்லது boundary-ஆல் மாற்றுவது smoothing. உண்மையான அரிய நிகழ்வைத் தவறாக நீக்காதீர்கள்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Mean smoothing ஒவ்வொரு bin-ஐ mean-ஆல்; median நடு மதிப்பால்; boundary அருகிலுள்ள minimum/maximum-ஆல் மாற்றும். Tie வந்தால் தேர்ந்த policy-ஐச் சொல்லுங்கள். Regression trend line-க்கு ஏற்ற மதிப்புகளைத் தரும்; clustering தனியாக நிற்கும் outliers-ஐக் காட்டலாம். உண்மையான extreme event-ஐ noise என நீக்குவதற்கு முன் domain காரணம் பார்க்க வேண்டும்.

Noise is a random error or variance in a measured variable. Three smoothing techniques:

1. Binning

Binning smooths a sorted value by consulting its neighbourhood (the values around it). This is local smoothing.

The notes' example: equal-frequency bins of size 3

Sorted prices: 4, 8, 15, 21, 21, 24, 25, 28, 34

Bin 1 Bin 2 Bin 3
Partition 4, 8, 15 21, 21, 24 25, 28, 34
By bin means 9, 9, 9 22, 22, 22 29, 29, 29
By bin boundaries 4, 4, 15 21, 21, 24 25, 25, 34
  • Bin 1 mean = (4 + 8 + 15) / 3 = 27 / 3 = 9
  • Bin 2 mean = 66 / 3 = 22
  • Bin 3 mean = 87 / 3 = 29
  • Boundaries: each value goes to the closer of min/max. In bin 1, 8 is closer to 4 (gap 4) than to 15 (gap 7). In bin 3, 28 is closer to 25 (3) than to 34 (6).
  • Smoothing by bin medians replaces each value with the bin's median.
  • The larger the bin width, the stronger the smoothing effect.
  • Bins can also be equal-width (constant interval range). There's an interactive binning lab in Week 4.

2. Regression

Fit the data to a function. Linear regression finds the best line to fit two attributes so one can predict the other. Multiple linear regression uses more than two attributes and fits a multidimensional surface.

3. Clustering

Group similar values into clusters. Values that fall outside all clusters can be considered outliers.

தரவை ஒரு சார்புக்குப் பொருத்தவும். நேரியல் பின்னடைவு, ஒரு பண்புக்கூறால் மற்றொன்றை முன்னறிவிக்க ஏற்றவாறு இரண்டு பண்புக்கூறுகளுக்குப் பொருந்தும் சிறந்த கோட்டைக் கண்டறிகிறது. பல நேரியல் பின்னடைவு, இரண்டுக்கும் மேற்பட்ட பண்புக்கூறுகளைப் பயன்படுத்தி பல்பரிமாண மேற்பரப்பைப் பொருத்துகிறது.

3. குழுமமாக்கல்

ஒத்த பெறுமதிகளைக் குழுமங்களாகத் தொகுக்கவும். அனைத்துக் குழுமங்களுக்கும் வெளியே உள்ள பெறுமதிகளை புறநிலைகளாகக் கருதலாம்.

4Data cleaning as a process

Data cleaning ஒரு தொடர்ச்சியான வேலை

முதலில் முரண்பாட்டைக் கண்டுபிடித்து, காரணத்தை ஆராய்ந்து, விதிப்படி சரிசெய்து, மீண்டும் சோதிக்க வேண்டும். வருடம் தவறாக உள்ளதா, unit வேறுபட்டதா என்று பார்க்காமல் ஒரு எண்ணை மட்டும் மாற்றுவது ஆபத்து.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Discrepancy detection: metadata range/type-க்கு பொருந்துகிறதா, unique ID மீண்டுள்ளதா, sequence numbers தவறியுள்ளனவா, null அனுமதியா என்று பாருங்கள். Date format, currency, units மாறுபாடும் தவறாகத் தோன்றலாம். Correction: transformation rules அல்லது ETL pipeline மூலம் சீராக்கி, மாற்றத்தைச் சரிபார்க்கவும். Data migration tools sources இடையே மாற்றும்; ETL extract→transform→load செய்கிறது. பிழையின் மூல காரணத்தையும் திருத்தினால்தான் மீண்டும் வராமல் தடுக்கலாம்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Detect→fix→check again. Metadata-வில் type/domain/range/dependencies/null coding பார்த்து discrepancies கண்டுபிடி. Unique rule ID repeat ஆகாதது; consecutive rule இடையில் missing/duplicate வராத வரிசை; null rule missing-ஐ எப்படிக் குறிக்கிறோம். Zero உண்மையான value ஆக இருக்கலாம்; missing-க்கு தானாக zero நிரப்பாதீர்கள். Migration/ETL/scripts fixes செய்யலாம்; transformation புதிய பிரச்சினை உருவாக்கலாம். Interactive cleaning உதாரணம் Potter’s Wheel detection+transformation+undo; இது பாடத்தின் வரலாற்றுக் கருவி உதாரணம்.

So far we've looked at techniques. In practice cleaning is a two-step iterative process:

Discrepancy detectionData transformation (fix)Check again ↺

Step 1 — Discrepancy detection

Causes of discrepancies: - Poorly designed data-entry forms with many optional fields - Human error in data entry - Deliberate errors (respondents hiding personal information) - Data decay (outdated addresses) - Inconsistent representations and inconsistent use of codes - Instrument and system errors - Data used for purposes other than originally intended - Integration inconsistencies (the same attribute has different names in different DBs)

How to detect them: start with metadata ("data about data"). Ask: what is the domain and data type of each attribute? What are the acceptable values? Do all values fall in the expected range? Are there known dependencies?

Look out for: - Inconsistent representations: "2004/12/25" vs "25/12/2004" - Field overloading: developers squeeze new attribute definitions into unused bits of existing attributes (e.g. using the unused bit of a 32-bit field that only needs 31)

Check the data against three kinds of rules:

Rule Says Example
Unique rule Every value of the attribute must be different from all others Customer ID
Consecutive rule No missing values between the lowest and highest, and all values unique Cheque numbers
Null rule How blanks, "?", special characters etc. indicate null and how to handle them Use an explicit, consistent missing-value representation; do not silently replace missing numbers with 0 when 0 is a valid value

Reasons for missing values (the null rule must handle these): 1. The person refuses to give the value, or it is not applicable (e.g. licence number left blank by non-drivers) 2. The data-entry person doesn't know the correct value 3. The value will be provided by a later step

Step 2 — Data transformation (to correct discrepancies)

Tool What it does
Data migration tools Simple transforms, e.g. replace the string "gender" with "sex"
ETL tools (Extraction / Transformation / Loading) Specify transforms through a GUI. Only a restricted set of transforms, so custom scripts are often needed too
Why this process is painful
  • It is error-prone and time-consuming.
  • Some transformations introduce new discrepancies.
  • Nested discrepancies only appear after others are fixed. For example, a typo "20004" in a year field only shows up once all dates are in a uniform format.
  • Transforms run as batch jobs with no feedback. Failed tuples are written to a file without explanation.
  • So the process lacks interactivity and needs many iterations.

Newer, interactive approaches

  • Potter's Wheel is a publicly available cleaning tool that integrates discrepancy detection and transformation:
  • You build transformations one step at a time on a spreadsheet-like interface, either graphically or by giving examples.
  • Results show immediately, you can undo, and discrepancy checking runs in the background.
  • Declarative languages: powerful extensions to SQL for specifying data-cleaning operations.
  • Keep updating the metadata as you learn about the data. This speeds up cleaning of future versions.

படி 1 — முரண்பாட்டைக் கண்டறிதல்

முரண்பாடுகளுக்கான காரணங்கள்: - பல விருப்பப் புலங்களுடன் மோசமாக வடிவமைக்கப்பட்ட தரவு உள்ளீட்டுப் படிவங்கள் - தரவு உள்ளீட்டில் மனிதப் பிழை - வேண்டுமென்றே செய்யப்படும் பிழைகள் (பதிலளிப்போர் தனிப்பட்ட தகவலை மறைத்தல்) - தரவு காலாவதியாதல் (பழைய முகவரிகள்) - முரண்பாடான பிரதிநிதித்துவங்களும் குறியீடுகளின் சீரற்ற பயன்பாடும் - கருவி மற்றும் முறைமைப் பிழைகள் - முதலில் நோக்கப்பட்டதைவிட வேறு நோக்கங்களுக்குத் தரவு பயன்படுத்தப்படுதல் - ஒருங்கிணைப்பு முரண்பாடுகள் (ஒரே பண்புக்கூறுக்கு வெவ்வேறு தரவுத்தளங்களில் வெவ்வேறு பெயர்கள்)

கண்டறிவது எவ்வாறு: மேல்தரவிலிருந்து ("தரவு பற்றிய தரவு") தொடங்கவும். ஒவ்வொரு பண்புக்கூறின் ஆட்களமும் தரவு வகையும் என்ன? ஏற்கத்தக்க பெறுமதிகள் எவை? அனைத்தும் எதிர்பார்க்கப்படும் வீச்சிற்குள் உள்ளனவா? அறியப்பட்ட சார்புகள் உள்ளனவா? எனக் கேட்கவும்.

கவனிக்க வேண்டியவை: - முரண்பாடான பிரதிநிதித்துவங்கள்: "2004/12/25" மற்றும் "25/12/2004" - புல மிகையேற்றம்: ஏற்கெனவேயுள்ள பண்புக்கூறுகளின் பயன்படுத்தப்படாத பிட்களில் புதிய பண்புக்கூறு வரையறைகளை உருவாக்குநர்கள் திணிக்கின்றனர் (எ.கா. 31 பிட்கள் மட்டுமே தேவைப்படும் 32-பிட் புலத்தின் பயன்படுத்தப்படாத பிட்டைப் பயன்படுத்துதல்)

மூன்று வகை விதிகளுடன் தரவைச் சரிபார்க்கவும்:

விதி கூறுவது எடுத்துக்காட்டு
தனித்துவ விதி பண்புக்கூறின் ஒவ்வொரு பெறுமதியும் மற்ற அனைத்திலிருந்தும் வேறுபட வேண்டும் வாடிக்கையாளர் ID
தொடர்ச்சி விதி குறைந்ததற்கும் உயர்ந்ததற்கும் இடையே விடுபட்ட பெறுமதிகள் இல்லை; அனைத்துப் பெறுமதிகளும் தனித்துவமானவை காசோலை எண்கள்
வெற்று விதி இடைவெளிகள், "?", சிறப்புக் குறிகள் போன்றவை வெற்றைக் குறிப்பதும் அவற்றைக் கையாளுவதும் எவ்வாறு வெளிப்படையான, சீரான விடுபட்ட-பெறுமதிப் பிரதிநிதித்துவத்தைப் பயன்படுத்தவும்; 0 செல்லுபடியாகும் பெறுமதியாக இருக்கும்போது விடுபட்ட எண்களை அறிவிக்காமல் 0 ஆக்க வேண்டாம்

பெறுமதிகள் விடுபடுவதற்கான காரணங்கள் (வெற்று விதி இவற்றைக் கையாள வேண்டும்): 1. நபர் பெறுமதியை வழங்க மறுக்கிறார், அல்லது அது பொருந்தாது (எ.கா. வாகனம் ஓட்டாதோர் உரிம எண்ணை வெறுமையாக விடுதல்) 2. தரவு உள்ளிடுபவருக்குச் சரியான பெறுமதி தெரியாது 3. பெறுமதி பின்னர் வரும் படியால் வழங்கப்படும்

படி 2 — தரவு உருமாற்றம் (முரண்பாடுகளைத் திருத்த)

கருவி செய்வது
தரவு இடம்பெயர்வுக் கருவிகள் எளிய உருமாற்றங்கள்; எ.கா. "gender" என்ற சரத்தை "sex" என மாற்றுதல்
ETL கருவிகள் (பிரித்தெடுத்தல் / உருமாற்றம் / ஏற்றுதல்) வரைகலைப் பயனர் இடைமுகம் மூலம் உருமாற்றங்களைக் குறிப்பிடுதல். வரையறுக்கப்பட்ட உருமாற்றங்கள் மட்டுமே உள்ளதால் தனிப்பயன் நிரல்களும் அடிக்கடி தேவை
இந்தச் செயல்முறை ஏன் சிரமமானது

5Data integration

பல இடங்களின் தரவை இணைத்தல்

இரண்டு files-இல் இருக்கும் பெயர்கள் ஒரே நபரையா குறிக்கின்றன என்று Entity identification பார்க்கும். ஒரே தகவல் இரண்டு attributes-இல் இருந்தால் redundancy. Correlation தொடர்பைக் காட்டும்; காரணத்தைக் காட்டாது. r = 0 என்பது linear தொடர்பு இல்லை என்பதே.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Pearson r = Σ(aᵢ−ā)(bᵢ−b̄)/√[Σ(aᵢ−ā)² Σ(bᵢ−b̄)²], −1≤r≤1. r=+1 முழு positive linear தொடர்பு; −1 முழு negative linear தொடர்பு; 0 linear correlation இல்லை. முக்கிய திருத்தம்: r=0 என்பதால் பொதுவாக statistical independence என்று முடிவு செய்ய முடியாது; nonlinear தொடர்பு இருக்கலாம். |r| அதிகமாக இருப்பது direction-ஐப் பொருட்படுத்தாமல் வலுவான linear தொடர்பைக் காட்டும். Attribute constant என்றால் denominator 0; r undefined.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Pearson r −1 முதல்1; sign direction, absolute size linear strength. r=0 என்றால் independence உறுதி இல்லை; correlation காரணத்தை நிரூபிக்காது. Formula-இல் N உடன் population σ பயன்படுத்துகிறோமா அல்லது N−1 sample σ-ஆ என்று consistent ஆக இருக்கவேண்டும். Constant attribute-க்கு r undefined.

Data integration combines data from multiple sources (databases, data cubes, flat files) into a coherent data store, as in data warehousing.

Issue 1 — Entity identification problem

How do we match equivalent real-world entities from different sources? Is customer_id in one DB the same attribute as cust_number in another? This is schema integration and object matching.

Solution: metadata for each attribute (name, meaning, data type, permitted range, null rules). Metadata also helps transform codes. For example, pay type may be "H"/"S" in one DB and 1/2 in another, so integration overlaps with cleaning.

Issue 2 — Redundancy

An attribute is redundant if it can be derived from other attributes (e.g. annual revenue). Inconsistent attribute naming can also create redundancy. Many redundancies can be found with correlation analysis.

Correlation coefficient (Pearson's product-moment)

For numerical attributes A and B over N tuples:

rA,B = Σ (ai − Ā)(bi − B̄) / (N σA σB) = [ Σ(aibi) − N Ā B̄ ] / (N σA σB)

where Ā, B̄ are the means, σA, σB are the standard deviations, Σ(aibi) is the sum of the cross-products, and −1 ≤ r ≤ +1.

r value Meaning
r > 0 Positively correlated: A increases as B increases. A larger absolute value of r means a stronger linear relationship; assess redundancy before removing an attribute
r = 0 No linear correlation; variables can still have a nonlinear relationship, so independence is not guaranteed
r < 0 Negatively correlated: one increases as the other decreases

6Data transformation

அளவுகளை மாற்றுதல்

சம்பளம் ஆயிரங்களில், வயது பத்துகளில் இருந்தால் சில algorithms சம்பளத்திற்கே அதிக எடை தரலாம். Normalization அவற்றை ஒப்பிடக்கூடிய அளவிற்கு மாற்றும். Training data-வில் கற்ற scale-ஐ test data-க்கும் பயன்படுத்த வேண்டும்.

Mean 54,000; SD 16,000 என்றால் அதே value 1.225 — mean-ஐவிட 1.225 SD மேலே. Decimal scaling: v/10ʲ; எல்லா transformed |values|<1 ஆகும் மிகச் சிறிய j. −986 என்றால் j=3 → −0.986. Data are transformed or consolidated into forms suitable for mining. Four kinds:

Kind What Example
Smoothing Remove noise: binning, regression, clustering As above
Aggregation Summary operations, used in building data cubes Daily sales → monthly and annual totals
Generalization Replace raw values with higher-level concepts via concept hierarchies street → city → country; age → youth / middle-aged / senior
Normalization Scale values into a small range such as [−1.0, 1.0] or [0.0, 1.0] income → 0.716

Min-max normalization

A linear transformation. It maps value v of A from [minA, maxA] into [new_minA, new_maxA]:

v′ = (v − minA) / (maxA − minA) × (new_maxA − new_minA) + new_minA
Notes example

Income min = $12,000, max = $98,000, map to [0.0, 1.0]. Value $73,600:

v′ = (73,600 − 12,000) / (98,000 − 12,000) × (1.0 − 0) + 0 = 61,600 / 86,000 = 0.716

Z-score (zero-mean) normalization

Uses the mean Ā and standard deviation σA:

v′ = (v − Ā) / σA

Z-score scaling uses estimated mean and standard deviation rather than fixed bounds. It is not robust to outliers either: extreme values influence both statistics. Fit scaling on training data only when evaluating a predictive model.

Notes example

Mean income = $54,000, σ = $16,000. Value $73,600:

v′ = (73,600 − 54,000) / 16,000 = 19,600 / 16,000 = 1.225

Decimal scaling (extra, from the textbook)

Move the decimal point: v′ = v / 10j, where j is the smallest integer such that max(|v′|) < 1. For example, if values range from −986 to 917, j = 3, so −986 → −0.986.

சராசரி Ā மற்றும் நியம விலகல் σA ஆகியவற்றைப் பயன்படுத்துகிறது:

v′ = (v − Ā) / σA

Z-மதிப்பெண் அளவுமாற்றம் நிலையான எல்லைகளுக்குப் பதிலாக மதிப்பிடப்பட்ட சராசரியையும் நியம விலகலையும் பயன்படுத்துகிறது. இதுவும் புறநிலைகளுக்கு உறுதியானதல்ல: தீவிரப் பெறுமதிகள் இரு புள்ளிவிவரங்களையும் பாதிக்கின்றன. முன்னறிவிப்பு மாதிரியை மதிப்பிடும்போது பயிற்சித் தரவில் மட்டுமே அளவுமாற்றத்தைப் பொருத்தவும்.

குறிப்புகளின் எடுத்துக்காட்டு

சராசரி வருமானம் = $54,000, σ = $16,000. பெறுமதி $73,600:

v′ = (73,600 − 54,000) / 16,000 = 19,600 / 16,000 = 1.225

தசம அளவுமாற்றம் (பாடநூலிலிருந்து கூடுதலாக)

தசமப் புள்ளியை நகர்த்தவும்: v′ = v / 10j; இங்கு j என்பது max(|v′|) < 1 ஆகும் மிகச்சிறிய முழு எண். எ.கா. பெறுமதிகள் −986 முதல் 917 வரை இருந்தால் j = 3; எனவே −986 → −0.986.

Noise-ஐக் குறைத்தல்

வழக்கமான வடிவத்தை மறைக்கும் சிறிய சீரற்ற மாற்றங்கள் Noise. அருகிலுள்ள மதிப்புகளை bins-ஆகப் பிரித்து mean அல்லது boundary-ஆல் மாற்றுவது smoothing. உண்மையான அரிய நிகழ்வைத் தவறாக நீக்காதீர்கள்.

Mean smoothing ஒவ்வொரு bin-ஐ mean-ஆல்; median நடு மதிப்பால்; boundary அருகிலுள்ள minimum/maximum-ஆல் மாற்றும். Tie வந்தால் தேர்ந்த policy-ஐச் சொல்லுங்கள். Regression trend line-க்கு ஏற்ற மதிப்புகளைத் தரும்; clustering தனியாக நிற்கும் outliers-ஐக் காட்டலாம். உண்மையான extreme event-ஐ noise என நீக்குவதற்கு முன் domain காரணம் பார்க்க வேண்டும்.

Data cleaning ஒரு தொடர்ச்சியான வேலை

முதலில் முரண்பாட்டைக் கண்டுபிடித்து, காரணத்தை ஆராய்ந்து, விதிப்படி சரிசெய்து, மீண்டும் சோதிக்க வேண்டும். வருடம் தவறாக உள்ளதா, unit வேறுபட்டதா என்று பார்க்காமல் ஒரு எண்ணை மட்டும் மாற்றுவது ஆபத்து.

Discrepancy detection: metadata range/type-க்கு பொருந்துகிறதா, unique ID மீண்டுள்ளதா, sequence numbers தவறியுள்ளனவா, null அனுமதியா என்று பாருங்கள். Date format, currency, units மாறுபாடும் தவறாகத் தோன்றலாம். Correction: transformation rules அல்லது ETL pipeline மூலம் சீராக்கி, மாற்றத்தைச் சரிபார்க்கவும். Data migration tools sources இடையே மாற்றும்; ETL extract→transform→load செய்கிறது. பிழையின் மூல காரணத்தையும் திருத்தினால்தான் மீண்டும் வராமல் தடுக்கலாம்.

Detect→fix→check again. Metadata-வில் type/domain/range/dependencies/null coding பார்த்து discrepancies கண்டுபிடி. Unique rule ID repeat ஆகாதது; consecutive rule இடையில் missing/duplicate வராத வரிசை; null rule missing-ஐ எப்படிக் குறிக்கிறோம். Zero உண்மையான value ஆக இருக்கலாம்; missing-க்கு தானாக zero நிரப்பாதீர்கள். Migration/ETL/scripts fixes செய்யலாம்; transformation புதிய பிரச்சினை உருவாக்கலாம். Interactive cleaning உதாரணம் Potter’s Wheel detection+transformation+undo; இது பாடத்தின் வரலாற்றுக் கருவி உதாரணம்.

பல இடங்களின் தரவை இணைத்தல்

இரண்டு files-இல் இருக்கும் பெயர்கள் ஒரே நபரையா குறிக்கின்றன என்று Entity identification பார்க்கும். ஒரே தகவல் இரண்டு attributes-இல் இருந்தால் redundancy. Correlation தொடர்பைக் காட்டும்; காரணத்தைக் காட்டாது. r = 0 என்பது linear தொடர்பு இல்லை என்பதே.

Pearson r = Σ(aᵢ−ā)(bᵢ−b̄)/√[Σ(aᵢ−ā)² Σ(bᵢ−b̄)²], −1≤r≤1. r=+1 முழு positive linear தொடர்பு; −1 முழு negative linear தொடர்பு; 0 linear correlation இல்லை. முக்கிய திருத்தம்: r=0 என்பதால் பொதுவாக statistical independence என்று முடிவு செய்ய முடியாது; nonlinear தொடர்பு இருக்கலாம். |r| அதிகமாக இருப்பது direction-ஐப் பொருட்படுத்தாமல் வலுவான linear தொடர்பைக் காட்டும். Attribute constant என்றால் denominator 0; r undefined.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Entity matching: customer_id/cust_number ஒரே real customer-ஆ என metadata மற்றும் keys மூலம் சோதி. Redundancy: annual total மற்ற fields-இலிருந்து derive ஆகிறதா? Pearson r −1 முதல்1; sign direction, absolute size linear strength. r=0 என்றால் independence உறுதி இல்லை; correlation காரணத்தை நிரூபிக்காது. Formula-இல் N உடன் population σ பயன்படுத்துகிறோமா அல்லது N−1 sample σ-ஆ என்று consistent ஆக இருக்கவேண்டும். Constant attribute-க்கு r undefined.

அளவுகளை மாற்றுதல்

சம்பளம் ஆயிரங்களில், வயது பத்துகளில் இருந்தால் சில algorithms சம்பளத்திற்கே அதிக எடை தரலாம். Normalization அவற்றை ஒப்பிடக்கூடிய அளவிற்கு மாற்றும். Training data-வில் கற்ற scale-ஐ test data-க்கும் பயன்படுத்த வேண்டும்.

Min–max: v′=(v−min)/(max−min)×(new_max−new_min)+new_min. 73,600-ஐ 12,000…98,000-இலிருந்து 0…1-க்கு மாற்றினால் 0.716. Z-score: v′=(v−mean)/SD. Mean 54,000; SD 16,000 என்றால் அதே value 1.225 — mean-ஐவிட 1.225 SD மேலே. Decimal scaling: v/10ʲ; எல்லா transformed |values|<1 ஆகும் மிகச் சிறிய j. −986 என்றால் j=3 → −0.986. Min=max அல்லது SD=0 என்றால் சாதாரண division formula வரையறுக்கப்படாது.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Transformation நான்கு: smoothing, aggregation (daily→monthly), generalisation (street→city), normalisation. Min–max (73600−12000)/(98000−12000)=0.716279…≈0.716; z-score (73600−54000)/16000=1.225; decimal scaling max absolute986 என்றால் j=3, −986→−0.986. Min=max அல்லது σ=0 என்றால் denominator zero. Z-score-உம் outliers-ஆல் பாதிக்கப்படும்; robust alternative தேவைப்படலாம். Fit bounds/mean/σ training set-இலிருந்து; test-ஐத் தனியே மறுபடி fit செய்யாதீர்கள்.
