## Pictures, images, raster and vector graphics

The lesson calls a visual scene a **picture**, its digitised reproduction an **image**, and uses **graphic** as a broad term including photographs, drawings and line art. **Computer graphics** creates, stores and manipulates visual models and generates images of real or synthetic worlds. A camera or scanner captures a scene; a drawing program can construct one from shapes.

**Raster/bitmap graphics** store a grid of pixels. A pixel has a position and colour value. Editing a raster changes pixels. Raster representation suits continuous-tone photographs and painting because it records subtle colour changes. Its fixed pixel dimensions make it resolution-dependent: enlarging it can expose blocks or jagged boundaries. Higher pixel counts generally require more uncompressed storage.

**Vector graphics** store objects described by mathematical commands: positions, lines, curves, circles, fills and strokes. Editing changes an object rather than individually selecting its screen pixels. A bicycle tyre can be described by a circle with a centre, radius, stroke and fill. It can be resized without changing that geometric definition.

| Property | Raster | Vector |
|---|---|---|
| Stored description | Pixel colours | Geometric objects and parameters |
| Editing unit | Pixels or selected pixel regions | Independent objects and paths |
| Scaling | Fixed detail; enlargement can pixelate | Geometry scales cleanly; display still has finite resolution |
| Typical use | Photograph, texture, digital painting | Logo, symbol, diagram, lettering |
| Common formats | BMP, GIF, JPEG, PNG, TIFF, TGA | SVG, AI, CDR, EPS; PDF can contain vectors |
| Example tools in the PDF | Photoshop, GIMP, PhotoPaint | Illustrator, CorelDRAW; InDesign is mainly page layout |

:::warn Avoid absolute source claims
The PDF says vectors cannot contain texture and always use little memory. Complex vector art can be large and can include patterns, effects or embedded raster content. Simple geometric art is often compact; photographs usually suit raster representation. PDF and EPS can contain mixed content, so an extension alone does not prove that every element is vector.
:::

## Resolution, aspect ratio and Activity 4.1

**Image resolution** describes image detail, commonly stated as width × height in pixels. **Display resolution** describes the display's pixel capability. **Colour resolution/colour depth** is the number of bits allocated to a pixel's colour representation. They measure different things. A larger pixel count does not automatically increase colour depth.

Pixel dimensions, physical print size and pixel density are connected. Enlarging a fixed-pixel image on paper spreads the same pixels over more space. In calculations, distinguish pixels from inches and bits from bytes. This PDF does not prescribe a KB conversion convention; examples here state **1 KiB = 1024 bytes**, while **1 kB = 1000 bytes** when decimal units are requested.

:::formula
Pixels = width × height
Aspect ratio = width : height, reduced by a common factor
Pixel density (ppi) = pixels along an edge ÷ printed inches along that edge
Printed inches = pixels along an edge ÷ ppi
:::

**Activity 4.1 question:** Survey raster and vector graphic devices and compare their features, starting with LCD or LED displays.

**Model answer:** An LCD or LED-backlit flat-panel screen displays a fixed pixel grid. A scanner or digital camera captures a raster image with pixel dimensions and colour depth. A raster printer converts the page into dots. A pen plotter can follow vector paths with a physical pen, making lines suitable for technical drawings. Compare addressable resolution, supported size, colour capability and intended use. A modern screen can show vector artwork only after rasterization: storing vectors does not turn an LCD into a vector-display device. Record actual device specifications when conducting a real survey; these are representative device classes, not invented measurements.

## RGB, CMYK, HSB and grey colour

Visible light is the approximate **400–700 nm** region in the PDF's spectrum diagram. Colour is a perception produced by the visual system; a **colour model** represents colour using parameters suited to a task.

**RGB** mixes red, green and blue light additively. Equal maximum components produce white; zero components produce black. With 8 bits per channel, each component ranges from 0 to 255. Three channels use 24 bits per pixel and allow 16,777,216 combinations. Equal components lie along the grey diagonal of the RGB cube. Displays use additive light.

**CMYK** uses cyan, magenta, yellow and black inks. It is subtractive: inks absorb parts of white light and reflect the remainder. Ideal CMY could combine to black, but real inks produce an imperfect dark mixture. K supplies a useful black component. Four-colour printing is suited to print production. RGB and CMY primaries are complementary; screen and printed colours may differ.

**HSB** describes hue, saturation and brightness. Hue locates a colour around the wheel; saturation describes its strength relative to grey; brightness describes its light/dark value. The lesson's wheel places red at 0°, yellow at 60°, green at 120°, cyan at 180°, blue at 240° and magenta at 300°, returning to red at 360°. Saturation runs from 0% grey to 100% fully saturated.

:::warn HSB wording in the PDF
HSB is often called HSV, but HSL and HSI are related models with different definitions, not identical names for exactly the same coordinates. In HSV, 100% value does not force white: fully saturated red can also have maximum value. The source's “100% white” wording is an oversimplification.
:::

**Grey mode** in this lesson uses 8 bits per pixel and up to 256 brightness levels: 0 is black and 255 is white. Ink coverage reverses the interpretation: 0% black ink means white paper; 100% means black. Grayscale contains tonal information without independent hue channels.

**Activity 4.2 question: List RGB/grey differences.** RGB stores separate red, green and blue channels and can represent colour. The lesson's RGB example uses 24 bits per pixel. Grey stores one brightness channel and uses 8 bits per pixel in the lesson. For equal pixel dimensions and no overhead, that RGB pixel data occupies three times the grayscale data. Grey suits monochrome documents or tonal work; RGB suits screen colour images.

## Image data, colour depth and worked calculations

Figure 4.7 contrasts direct raster pixel information with vector mathematical models. Both eventually need a colour model and an output resolution. A raster's storage depends on width, height and bits per pixel.

:::formula
Maximum distinct codes/colours = 2^b, for b bits per pixel
Minimum index depth for N colours = ceil(log₂ N)
Uncompressed pixel-data bits = W × H × b
Uncompressed pixel-data bytes = W × H × b ÷ 8
:::

These formulas exclude headers, palettes, metadata, row padding, compression and extra channels unless stated. A format's actual disk size can differ. For packed data, a non-whole byte result must be rounded up, and format row-alignment rules may add more.

### Image size: three solved examples

**Example 1, from the PDF:** 30 × 40 pixels at 8 bits per pixel. Formula: bytes = W × H × b ÷ 8. Substitute: 30 × 40 × 8 ÷ 8. Work: 1200 × 1. **Answer: 1200 bytes** of uncompressed pixel data.

**Example 2, Activity 4.3:** Calculate storage for 240 × 320 pixels at 8-bit depth. Formula: bytes = W × H × b ÷ 8. Substitute: 240 × 320 × 8 ÷ 8 = 76,800. Convert: 76,800 ÷ 1024 = 75. **Answer: 76,800 bytes = 75 KiB**, excluding overhead.

**Example 3:** A 640 × 480 RGB image uses 24 bits per pixel. Formula: bytes = W × H × b ÷ 8. Substitute: 640 × 480 × 24 ÷ 8 = 307,200 × 3. **Answer: 921,600 bytes = 900 KiB**, excluding overhead.

### Colour depth: three solved examples

**Example 1:** How many codes at 1 bit? Formula: N = 2^b. Substitute: 2^1. **Answer: 2 colour codes**. They can represent black/white or another chosen pair, as Figure 4.8 shows.

**Example 2:** How many codes at 8 bits? Formula: N = 2^b. Substitute: 2^8. **Answer: 256 codes**, not 8 colours.

**Example 3:** Minimum index depth for 100 palette colours? Formula: b = ceil(log₂ N). Since 2^6 = 64 < 100 and 2^7 = 128 ≥ 100, **answer: 7 bits per index** in an ideal packed representation. The palette itself also occupies storage.

### Resolution: three solved examples

**Example 1:** Find the pixel count of 800 × 600. Formula: pixels = W × H. Substitute: 800 × 600. **Answer: 480,000 pixels**.

**Example 2:** A 1200-pixel-wide photograph is printed 4 inches wide. Formula: ppi = pixels ÷ inches. Substitute: 1200 ÷ 4. **Answer: 300 ppi** along that edge.

**Example 3:** Print an 1800 × 1200 image at 300 ppi. Formula: inches = pixels ÷ ppi. Substitute: 1800 ÷ 300 = 6 and 1200 ÷ 300 = 4. **Answer: 6 × 4 inches**. No new pixels are created by this size calculation.

### Aspect ratio: three solved examples

**Example 1:** 800 × 600 has ratio 800:600. Divide both by 200. **Answer: 4:3**, or width/height = 4/3.

**Example 2:** 1920 × 1080 has ratio 1920:1080. Divide both by 120. **Answer: 16:9**.

**Example 3:** Preserve 16:9 at width 1280 pixels. Formula: H = W × 9/16. Substitute: 1280 × 9/16 = 80 × 9. **Answer: 720 pixels high**. Stretching to a different ratio would distort the picture.

## Palettes, codecs, compression and dithering

A **colour lookup table (CLUT)** stores palette entries, and pixel indices refer to those entries. This can reduce storage when an image uses few distinct colours. Exact palette representation can be lossless if it preserves all required colours; limiting the palette can lose colour information. A palette is not necessarily an external file, does not inherently describe colour transitions, and its indices are not always less than a byte. Those claims on page 13 depend on the particular representation.

A **codec** encodes data into a stored representation and decodes it for use. Figure 4.9's useful flow is original bitmap → encoder → coded file → decoder → reconstructed bitmap. A compatible decoder is needed; it need not be the same physical software instance.

**Lossless compression** restores the represented data exactly. RLE encodes runs; LZW reuses patterns; GIF and PNG support lossless compression. **Lossy compression** permanently discards information. JPEG's usual photographic compression trades smaller storage against distortion. Higher compression can reveal visible artefacts. Reducing a photograph to a limited GIF palette may already lose colours even though GIF's subsequent compression is lossless.

**Activity 4.4 question: Distinguish lossless and lossy methods.** Lossless is reversible and suits text-like graphics, exact diagrams and editing masters. Lossy is irreversible and often gives smaller files for photographs, video and sound where some distortion is acceptable. Repeated lossy re-encoding can add degradation. Choose by acceptable error and delivery needs, not by file size alone.

**Dithering** simulates unavailable colours or tones with patterns of available colours. It helps a low-colour display or printing system suggest a richer image. Simply replacing each colour by its nearest palette colour is quantisation; dithering also distributes approximation spatially, using dots, lines or other patterns. The output depends on palette and algorithm. A black-and-white dot pattern can suggest grey without adding a new ink.

## Formats, manipulation and Activity 4.5

Image software can be proprietary or open source and can concentrate on raster or vector work. Operations include drawing, editing, filtering, compositing, geometric transformation, format conversion and text creation. Raster tools cut, copy, colour and paste pixel selections; vector tools manipulate shapes.

| Format | Useful characteristics and limits |
|---|---|
| GIF | Indexed palette of up to 256 entries per table; lossless compression, simple transparency and animation; useful for limited-colour art |
| BMP | Bitmap pixel format, often uncompressed; the PDF's claim that compression is impossible is incorrect because some BMP variants support RLE |
| JPEG | Usually lossy photographic storage with adjustable quality; progressive encoding is a JPEG term, while the PDF's “interlaced” wording is imprecise |
| PNG | Lossless raster storage with indexed, grey and truecolour modes and optional alpha; the [PNG specification](https://www.w3.org/TR/png-3/) defines valid depth/mode combinations |
| RAW | Raw sample/byte data; interpretation needs dimensions, depth, channel ordering and other conventions; not one universal self-describing format |
| TIFF | Flexible interchange/container format; may use LZW and other compression; capabilities depend on its contents |
| TGA | Raster format used in graphics workflows; exact features depend on its variant |
| SVG / AI | Scalable vector description / Illustrator authoring format |
| PDF / EPS | Page-description/interchange formats that can carry vector and raster content |

**Activity 4.5 question: Write notes comparing the listed vector formats.** CDR is CorelDRAW's authoring format. EMF and WMF are Windows metafile formats carrying drawing commands and potentially bitmap content. EPS means Encapsulated PostScript and commonly uses `.eps`; the PDF labels it `.ps`, which normally identifies a PostScript file more generally. FreeHand `.fh` is a historical application format. Macintosh PICT `.pic`/`.pct` can carry drawing and bitmap data. SWF was used for vector animation and interaction; it is a historical delivery format, not a general modern-browser choice. Compare editability, target application, supported effects and print/web use; retain an editable master and export an appropriate delivery copy.

## All four PDF review answers

**1. Compare vector and raster formats.** Raster formats record pixel data and suit photographs and tonal painting; scaling is limited by stored detail. Vector formats record objects and mathematical paths, making logos and diagrams easy to edit and resize. Some containers hold both, so inspect the actual artwork rather than infer everything from its extension.

**2. CLUT compared with JPEG compression.** CLUT stores palette entries and pixel indices. It can preserve the image exactly when all its required colours fit; a restricted palette can discard colour detail. Usual JPEG compression instead discards some photographic information to reduce size, with quality chosen as a trade-off. Indexed line art and a richly shaded photograph have different needs.

**3. Advantages of HSV compared with RGB.** Hue, saturation and value let a designer adjust colour family, strength and brightness separately in a way closer to common colour descriptions. RGB directly controls the intensities of display primaries. HSV does not automatically contain more colours or make an image more accurate; it provides another useful coordinate system.

**4. Briefly describe JPEG compression and decompression.** At the PDF's level: an encoder converts an original bitmap to a smaller coded representation, and a compatible decoder reconstructs pixel data for display. Typical lossy JPEG changes colour representation, processes blocks using a frequency transform, quantises coefficients and encodes them. Decoding reverses the coding and transform steps, but quantisation losses cannot be restored. This detailed sequence extends the PDF's general codec diagram; it is not a diagram present in the lecture.

:::exam English answer frame
“Uncompressed pixel data equals width × height × bits per pixel. Divide by 8 for bytes and state any unit conversion. This excludes format overhead and compression. Raster stores pixel colours; vector stores mathematical objects. RGB is additive display light, CMYK is subtractive ink, and indexed colour uses a palette. Lossless compression restores represented data exactly; lossy compression trades information for reduced size.”
:::
