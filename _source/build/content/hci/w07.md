## Principles, guidelines and standards

Design rules are classified on **two dimensions**:

- **Authority**: how **mandatory** the rule is.
- **Generality**: how **broadly** it applies.

<figure><img src="Figure%207.1.PNG" alt="Authority vs generality"><figcaption>Figure 7.1: Authority vs generality of design rules</figcaption></figure>

| Rule type | Generality | Authority | Nature | Examples |
|---|---|---|---|---|
| 🌟 **Principles** | **High** | **Low** | High-level, abstract ideas; apply to **all domains** without fixing an implementation | "**Provide feedback**", "be consistent" |
| 📋 **Guidelines** | Moderate | **Advisory** | Recommended best practice and practical heuristics | **Apple Human Interface Guidelines**, Google **Material Design** |
| ⚖️ **Standards** | **Low** | **High** | **Strictly binding**, precise requirements | **ISO 9241** (usability), **W3C WCAG 2.1** (accessibility) |

:::tip Memory picture
As you go **Principles → Guidelines → Standards**, rules get **more specific and more mandatory**. A principle says "be readable". A guideline says "use 16 px body text". A standard says "text contrast **must** be at least 4.5 : 1".
:::

## Three classic frameworks

Different HCI pioneers proposed rule sets that **overlap heavily**.

### 📖 Don Norman's design principles
| Principle | Meaning |
|---|---|
| **Discoverability** | Make possible actions **visible** |
| **Feedback** | Clear, immediate **confirmation** |
| **Affordances** | Properties that show **how an object can be used** |
| **Signifiers** | **Explicit cues** showing **where and how** to act |
| **Mappings** | Intuitive relationships between **controls and effects** |
| **Constraints** | **Restrict** wrong options |
| **Conceptual models** | A coherent **mental simulation** of how the system works |

### 🏆 Jakob Nielsen's 10 usability heuristics
1. **Visibility of system status**
2. **Match between system and the real world**
3. **User control and freedom**
4. **Consistency and standards**
5. **Error prevention**
6. **Recognition rather than recall**
7. **Flexibility and efficiency of use**
8. **Aesthetic and minimalist design**
9. **Help users recognise, diagnose and recover from errors**
10. **Help and documentation**

### ⚡ Ben Shneiderman's 8 golden rules
1. **Strive for consistency**
2. **Enable frequent users to use shortcuts**
3. **Offer informative feedback**
4. **Design dialogs to yield closure** (clear beginning, middle, end)
5. **Offer simple error handling**
6. **Permit easy reversal of actions**
7. **Support internal locus of control** (the user feels in charge)
8. **Reduce short-term memory load**

:::key Where they all agree
All three converge on **visibility, feedback, consistency, error prevention and reducing memory load**.
:::

:::tip Memory hooks
- **Nielsen's 10:** "**V**ery **M**any **U**sers **C**onsider **E**rrors **R**eally **F**rustrating, **A**sk **H**elp **H**ere" (Visibility, Match, User control, Consistency, Error prevention, Recognition, Flexibility, Aesthetic, Help with errors, Help docs).
- **Shneiderman's 8:** "**C**onsistent **S**hortcuts **F**eed **C**losure; **E**rrors **R**eversible, **L**ocus, **M**emory".
:::

## The 15 universal design principles

| # | Principle | Meaning | Example |
|---|---|---|---|
| 1 | 🔍 **Discoverability** | Users can easily find what actions and tools exist and where | Visible toolbar instead of hidden gestures |
| 2 | 📢 **Feedback** | Immediate, perceptible, unambiguous confirmation of state changes | "Message sent ✓" |
| 3 | 🛑 **Constraints** | **Limit options** to prevent errors | Greyed-out invalid fields; date pickers |
| 4 | 🗺️ **Mapping** | Natural spatial and functional match between controls and results | Stove knobs laid out like the burners |
| 5 | 🔄 **Consistency** | Same terms, placement, icons and behaviour everywhere | "Save" always top-right with the same icon |
| 6 | 🚪 **Affordance & signifiers** | Visual traits show how an element is operated (push, slide, rotate) | A raised button looks pressable |
| 7 | 🏗️ **Structure** | Information organised **hierarchically** with logical grouping | Settings grouped into sections |
| 8 | ✨ **Simplicity** | Remove unnecessary widgets, steps and clutter | One-field search page |
| 9 | 🛡️ **Tolerance** (error grace) | **Forgiving**: undo/redo, trash can, safe recovery | Gmail "Undo send" |
| 10 | 🤝 **Equity & inclusivity** | Accessible to diverse abilities, colour-blind and elderly users | Screen-reader support, scalable text |
| 11 | 🎛️ **Flexibility** | Several pathways: wizards for novices, hotkeys for experts | Menu *and* Ctrl+S |
| 12 | 👁️ **Perceptibility** | Present crucial data through **redundant channels** (text + icon + sound + contrast) | Error = red **and** ⚠ icon **and** message |
| 13 | 🚀 **Ease of use** | Minimise cognitive load, physical steps and friction | One-tap reorder |
| 14 | 🛋️ **Comfort & ergonomics** | Reduce eye fatigue (dark/paper themes), RSI, mental exhaustion | Dark mode, comfortable font sizes |
| 15 | 📚 **Documentation & help** | Searchable, concise, task-focused help when edge cases arise | Contextual "?" help |

:::exam
Expect:

- "Differentiate principles, guidelines and standards with examples"
- "List Nielsen's 10 heuristics" or "Shneiderman's 8 golden rules"
- "Explain N design principles with examples"

For each principle give **meaning + example**. Mapping (stove), constraints (date picker), tolerance (undo) and perceptibility (colour + icon) are easy, solid examples.
:::

## Quick revision sheet

| Concept | Remember it as |
|---|---|
| Principles | High generality, low authority ("provide feedback") |
| Guidelines | Moderate, advisory (Apple HIG, Material Design) |
| Standards | Low generality, high authority, binding (ISO 9241, WCAG 2.1) |
| Norman | Discoverability, feedback, affordances, signifiers, mappings, constraints, conceptual models |
| Nielsen (10) | Visibility · Match real world · Control & freedom · Consistency · Error prevention · Recognition > recall · Flexibility · Minimalist · Error recovery · Help |
| Shneiderman (8) | Consistency · Shortcuts · Feedback · Closure · Error handling · Reversal · Locus of control · Memory load |
| Common core | Visibility, feedback, consistency, error prevention, memory load |
| 15 universal | Discoverability, Feedback, Constraints, Mapping, Consistency, Affordance, Structure, Simplicity, Tolerance, Equity, Flexibility, Perceptibility, Ease, Comfort, Documentation |
| Defensive design | Undo, non-destructive paths, confirm irreversible actions |
| Multi-modal | Never rely on colour alone |
