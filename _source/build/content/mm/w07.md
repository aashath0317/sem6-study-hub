## Animation, frames and perceived movement

:::key Definition
Animation is a rapid sequence of still images or model poses that creates the impression of change or movement. A **frame** is one image in the sequence. **Frame rate** is the number shown per second, measured in fps.
:::

The lesson describes animation as changing pixel positions and colours in the 2D Cartesian plane. Figure 7.1 shows the same red ball at successive heights. Each picture is still; their ordered display communicates the bounce. The PDF gives **12–30 fps** as an illustrative range, not a universal restriction. Higher or lower rates can be chosen for a particular style, medium and device.

The source explains the illusion using **persistence of vision** and the **phi phenomenon**. For the course, remember that the first concerns the brief persistence of a visual impression, while the second concerns perceived motion from changing stimuli. Its description of a chemically mapped retinal image and a mind “completing” an action is a simplified teaching account, not a complete explanation of visual perception.

Use animation to explain a change, direct attention or express a character. A moving arrow in a Sri Lankan bus-route lesson can show direction better than a decorative spinning title. Animation should support the message; constant unrelated motion competes with reading.

## Basic animation methods and parameters

| Method | How it works | Main consequence |
|---|---|---|
| Full image-frame change | Replace the displayed picture with the next picture | Simple concept; each picture can contain much data |
| Delta-frame animation | Store or update changes after an initial frame | Can reduce the repeated data needed |
| Palette animation | Change colour-table entries or colours associated with pixels | Can suggest change without moving geometry |
| Visual effects (VFX) | Integrate artificial imagery with a captured scene | Requires the added content to fit the live scene |
| Character animation | Animate an expressive character | Poses, movement and timing communicate mood and physical effects |

The PDF also mentions **bit-blitting**: transferring or combining bitmap regions, such as foreground and background. Distinguish changing pixel positions from changing palette colours; both can make a display look animated.

| Parameter family | Examples | Design decision |
|---|---|---|
| Visual | Stage size, colour, bitmap/vector representation | What will the audience see, and at what size? |
| Timing | Frame rate, duration, playback or flow control | When will it happen and how long will it take? |
| Motion | Path, position, shape, scale, colour change | What property changes between frames? |

Set parameters deliberately rather than accepting defaults. A wide stage may suit a desktop demonstration but require adaptation for a phone. A slower movement can help a learner follow a diagram; a fast impact can communicate weight. Timing and spacing differ: timing is how long the action takes, while spacing is how far the object moves between displayed poses.

## Bitmap, vector, keyframes and tweening

The lesson's **bitmap animation** model preloads frame bitmaps and displays them sequentially. Memory can be large because many pixel colours are stored. Its **vector animation** model computes frames from mathematical descriptions; simple graphics can need less stored data, but rendering requires computation. These are trade-offs, not an absolute rule that every vector file is smaller or every bitmap player must preload its entire movie. Complexity, caching, compression and implementation matter.

A **keyframe** records an important state, such as a ball at the top or bottom of a bounce. **Tweening** generates the intermediate states. The animator controls the meaningful poses and the software interpolates the gaps. Frame-by-frame drawing instead creates each pose individually; it offers detailed control but needs more drawing work.

:::example A position tween
Choose start x = 20 and end x = 220. At progress t = 0.25, linear interpolation gives x = 20 + 0.25(220−20) = 70. At t = 0.5, x = 120. The path is straight and the progress is uniform; easing changes the speed distribution while preserving the chosen endpoints.
:::

A tween is not automatically convincing. Check acceleration, contact poses and the object's weight. Use extra keyframes when a change of direction or a specific pose matters. If the intermediate frames take an unwanted route, inspect the path, pivot, rotation direction and easing.

## Cel, path and shape animation

**Cel animation** separates changing drawings from a reusable background. Traditionally, transparent cels carried drawings that were layered and photographed. The linked [cel-animation explanation](https://conceptartempire.com/cel-animation/) adds that planning starts with a script and storyboard, key poses establish action, in-between drawings smooth it, and photographed layers form the sequence. Digital layers retain the useful separation between moving objects and background. The linked article's embedded demonstration was not watched here; the written process was accessible.

**Path animation** moves an object along a predetermined straight or curved path. Its shape need not change. A bitmap bird can follow a curved route while keeping the same image, or use a separate wing-flap animation. A motion tween can combine position, rotation or scale with that route.

**Shape animation** morphs one vector shape into another. The software interpolates the geometry between key shapes. Good correspondence between elements avoids tangled or unexpected intermediate forms. Position and colour can also change. A bitmap photograph does not become a shape tween merely because its position changes.

The original PowerPoint link in the PDF could not be opened, but the [current Microsoft guide](https://support.microsoft.com/en-us/powerpoint/add-a-motion-path-animation-effect) was found. Its method is to select the object, choose an animation motion path, adjust the route and preview it. A custom route can be drawn. Use the animation controls to set start behaviour and duration. This is useful for a process arrow in a lesson; the path should communicate the intended sequence.

## Principles, timing, sound, layers and backgrounds

The PDF names these topics but refers their detailed teaching to external tutorials that are not supplied as separate files. Use the following practical explanations to complete its outline. The [Adobe animation-principles guide](https://www.adobe.com/creativecloud/animation/discover/principles-of-animation.html) is a further reference.

| Principle | Apply it to a bouncing ball |
|---|---|
| Squash and stretch | Flatten at impact and lengthen during fast motion while suggesting consistent volume |
| Anticipation | Prepare the viewer for an important action |
| Staging | Keep the important movement clearly visible |
| Straight ahead / pose to pose | Draw successive actions or plan key poses first |
| Follow through / overlap | Let attached details settle after the main body |
| Slow in / slow out | Put poses closer near slower parts of the action |
| Arcs | Use curved paths for natural movement |
| Secondary action | Add a supporting detail without hiding the main action |
| Timing | Use duration to communicate speed and weight |
| Exaggeration | Emphasise a feature to make the action readable |
| Solid drawing | Keep forms and perspective coherent |
| Appeal | Make the design and performance clear and engaging |

Plan actions on a timeline. Put dialogue, music and sound effects on separate tracks so they can be aligned and adjusted. An impact sound should match the contact frame; speech should remain intelligible over music. Use layer names such as background, shadow, ball and sound. Lock an unchanged background to avoid accidental edits. Effects should match the scene's light, perspective and intended style. Preview the result at its intended size and frame rate, rather than judging only isolated keyframes.

## Web and CSS animation

For the web, [CSS animation](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Animations/Using) combines keyframes describing property values with a rule describing duration, timing and repetition. Use transform for movement or scale, and opacity for fading. An animation can be a one-off action or repeat. A transition is useful when a property changes between states, while keyframes can describe several stages.

```css
@keyframes mmBall {
  from { transform: translateY(0); }
  to { transform: translateY(-80px); }
}
.ball { animation: mmBall 1s ease-in-out 2 alternate; }
@media (prefers-reduced-motion: reduce) {
  .ball { animation: none; }
}
```

This example moves the element upward and then back, using alternate direction. The reduced-motion rule removes the animation for users who request less motion. Provide a pause or step control for instructional motion; do not make critical information available only while it is moving. Test the final experience on a phone and with keyboard controls. CSS motion is suitable for interface feedback and simple teaching diagrams; a complex character scene may need an animation package or another rendering approach.

## Activity 6.1 as numbered in the PDF: full model workflows

The Week 07 PDF labels this task **Activity 6.1**; this is a numbering carry-over, not an additional Week 06 activity.

### (i) Create a bouncing ball with a shadow using tweening

Create a stage with a ground line. Put the ball and shadow on separate layers and set their pivots sensibly. Set keyframes for contact, upward motion, the apex and the return contact. Tween between the keyframes. Adjust easing so motion slows near the apex and accelerates towards impact. Squash the ball at contact and stretch during faster movement without an obvious volume jump. Keep the shadow under the ball; make it smaller and fainter when the ball is higher, then wider and darker near the ground. Preview the full loop and check for an abrupt jump at its boundary. Save the editable file and export a separate playback copy.

### (ii) Animate a bitmap bird along a path

Import the bird bitmap, remove or mask an unwanted background and convert the reusable object to the symbol type required by the chosen package. Place a start keyframe and an end keyframe, draw or choose a curved path, then attach the object to it using a motion tween. Set the duration and position its registration point consistently. If orientation-to-path is used, inspect sudden rotations on sharp bends. A still bird image can travel along the path; wing-flapping needs additional frames or a nested animation. Preview from beginning to end and check the image is not cropped offstage.

### (iii) Deform a circle into a triangle

Draw a vector circle on its own layer. Create a later keyframe with the triangle. Apply a shape tween, using raw vector shapes or the package's supported morph representation. Scrub the intermediate frames. If the shape twists, reduce complexity or use shape hints/corresponding control points. Set timing and, if desired, colour change. A motion tween moving a circle is not the required deformation. The model result is a continuous transformation of the circle's outline into the triangle's outline.

These are complete model production procedures. The folder has no separate Adobe tutorial recordings for the tasks, so no claim is made about matching an unavailable demonstration's exact visual result.
