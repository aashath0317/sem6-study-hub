1What is interaction?

Interaction என்றால் என்ன?

பயனர் ஒரு இலக்கை அடைய system-உடன் செயலும் பதிலும் பரிமாறுவது Interaction. இலக்கு பசி தீர்ப்பது; task உணவை order செய்வது; interface button அதன் ஒரு பகுதி மட்டுமே.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

Domain–Goal–Task வேறுபாடு: Domain = நாம் பார்க்கும் செயல்துறை; Goal = அடைய வேண்டிய முடிவு; Tasks = அதை அடையச் செய்யும் செயல்கள்.

Taxi app உதாரணம்: domain வாகனப் பதிவு; goal பயணத்திற்கு வாகனம் பெறுதல்; tasks app திறத்தல் → pickup/destination/time/passengers உள்ளிடல் → விலை/வாகனம் ஒப்பிடல் → உறுதிப்படுத்தல் அல்லது மாற்றல். Input click/typing/voice ஆகலாம்; output screen/sound/vibration ஆகலாம். System feedback-ஐ வைத்தே பயனர் அடுத்த செயலைத் தீர்மானிக்கிறார்.

Interaction is the communication dialogue between two or more parties. In HCI it is the back-and-forth exchange between the user and the system.

  • Between people, communication uses natural language, body language, facial gestures and emotional cues.
  • In HCI, it goes through input actions (clicks, keystrokes, touch, voice) and system outputs (displays, audio feedback, haptics).

Three dimensions of interaction

Dimension Meaning Example: online vehicle hiring
Domain (context) The real-world area under consideration Online vehicle hiring service
Goal (objective) What the user ultimately wants to achieve Hire a vehicle online for transport
Task(s) (operations) The concrete step-by-step actions to reach the goal 1. Open the app or website
2. Enter pickup, destination, passengers, time, vehicle type
3. Review options and prices
4. Confirm, or reject/modify

A back-and-forth series of interactions between user and system achieves the goal.

இடைவினை என்பது இரண்டு அல்லது அதற்கு மேற்பட்ட தரப்புகளுக்கிடையிலான தகவல் தொடர்பு உரையாடல். HCI-இல் இது பயனருக்கும் முறைமைக்கும் இடையிலான முன்னும் பின்னுமான பரிமாற்றம் ஆகும்.

  • மனிதர்களுக்கிடையே, இயல்பான மொழி, உடல் மொழி, முகச் சைகைகள், உணர்ச்சிக் குறிப்புகள் மூலம் தொடர்பு நடைபெறுகிறது.
  • HCI-இல், உள்ளீட்டுச் செயல்கள் (சொடுக்குதல், விசை அழுத்துதல், தொடுதல், குரல்), முறைமை வெளியீடுகள் (காட்சிகள், ஒலிப் பின்னூட்டம், தொடு உணர்வு) மூலம் நடைபெறுகிறது.

இடைவினையின் மூன்று பரிமாணங்கள்

பரிமாணம் பொருள் எடுத்துக்காட்டு: இணையவழி வாகன வாடகை
பயன்பாட்டுத் துறை (சூழல்) கருத்தில் கொள்ளப்படும் நிஜ உலகப் பகுதி இணையவழி வாகன வாடகைச் சேவை
இலக்கு (குறிக்கோள்) பயனர் இறுதியாக அடைய விரும்புவது போக்குவரத்துக்காக இணையத்தில் வாகனத்தை வாடகைக்கு எடுப்பது
பணி(கள்) (செயல்பாடுகள்) இலக்கை அடைவதற்கான குறிப்பிட்ட படிப்படியான செயல்கள் 1. செயலி அல்லது வலைத்தளத்தைத் திறத்தல்
2. ஏறும் இடம், செல்லுமிடம், பயணிகள், நேரம், வாகன வகையை உள்ளிடுதல்
3. வாய்ப்புகளையும் விலைகளையும் பரிசீலித்தல்
4. உறுதிப்படுத்துதல் அல்லது நிராகரித்தல்/மாற்றுதல்

பயனருக்கும் முறைமைக்கும் இடையே நடைபெறும் முன்னும் பின்னுமான இடைவினைகளின் தொடர் இலக்கை அடையச் செய்கிறது.

2Donald Norman's model — 7 stages

Norman-இன் ஏழு படிகள்

இலக்கு → நோக்கம் → செயல் திட்டம் → செயல்படுத்தல் → முடிவைப் பார்த்தல் → பொருள் புரிதல் → இலக்குடன் ஒப்பிடுதல். ஒரு payment-இல் “எப்படி செலுத்துவது?” முதல் “செலுத்திவிட்டேனா?” வரை இந்தச் சுற்று பொருந்தும்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

ஏழு stages-ஐ ஒரு bank transfer-க்கு பொருத்துங்கள்: பணம் அனுப்ப வேண்டும் → transfer முறை தேர்வு → beneficiary/amount உள்ளிடத் திட்டம் → submit → confirmation பார்க்க → “successful” பொருள் புரிய → சரியானவருக்கு சென்றதா சரிபார். Goal/plan/specify/execute execution பக்கம்; perceive/interpret/evaluate evaluation பக்கம். சொற்களின் பட்டியல் மட்டுமல்ல; எந்த stage-இல் தடையுள்ளது என்று கண்டறிய வேண்டும்.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

AC உதாரணத்தை ஏழு படிகளுடன் எழுதுங்கள்: அறை குளிரவேண்டும் (goal) → AC temperature குறைக்க முடிவு (intention) → down-arrow அழுத்தத் திட்டம் (specify) → அழுத்துதல் (execute) → beep/display காணுதல் (perceive) → 22°C ஆக மாறியதைப் புரிதல் (interpret) → அறை போதுமான அளவு குளிர்ந்ததா ஒப்பிடல் (evaluate).

Remote கையில் இருந்தால் நேரடியாக அழுத்தலாம்; மற்றவரிடம் இருந்தால் அவரிடம் கேட்கலாம்; தூரத்தில் இருந்தால் நடந்து எடுக்கலாம். Goal ஒரேதாக இருந்தாலும் action sequence context-க்கு ஏற்ப மாறும். AC பழுதானால் feedback-ஐப் பார்த்து fan பயன்படுத்தும் புதிய intention உருவாகலாம்.

Norman's model looks at interaction from the user's cognitive perspective. The user is at the centre. It has two loops:

⚙️ Execution loop

How the user turns an internal goal into concrete actions and executes them on the interface.

🔍 Evaluation loop

How the user perceives the new system state, interprets the feedback and evaluates whether the goal was achieved.

# Stage AC example Loop
1 Establish the goal "Make the room cooler" —
2 Form the intention "Reduce the AC temperature" Execution
3 Specify the action sequence "Press the down-arrow button on the remote" Execution
4 Execute the action Physically press it Execution
5 Perceive the system state Hear the beep, see the display, feel cool air Evaluation
6 Interpret the system state "The display now reads 22 °C" Evaluation
7 Evaluate against the goal "Is the room cool enough now?" Evaluation
🧪 Try it — Walk Norman's action cycle

Action specification depends on the situation

Goal = cool the room, intention = adjust the AC. The specified actions change with the physical situation:

# Situation Action sequence
1 Remote within reach Pick it up and press temperature-down
2 Remote near another person Ask that person to adjust it
3 Remote across the room, you're alone Stand up, walk across, get the remote, adjust

Iterative evaluation: if the room doesn't cool (e.g. the AC is broken), evaluation fails. The user revisits the goal and forms a new intention, such as switching on the fan or moving to another room.

நார்மனின் மாதிரி இடைவினையை பயனரின் அறிவாற்றல் கண்ணோட்டத்தில் பார்க்கிறது. பயனர் மையத்தில் இருக்கிறார். இதில் இரண்டு சுழற்சிகள் உள்ளன:

⚙️ செயலாக்கச் சுழற்சி

பயனர் தனது உள்ளார்ந்த இலக்கைக் குறிப்பிட்ட செயல்களாக மாற்றி அவற்றை இடைமுகத்தில் செயல்படுத்தும் விதம்.

🔍 மதிப்பீட்டுச் சுழற்சி

புதிய முறைமை நிலையைப் பயனர் உணர்ந்து, பின்னூட்டத்துக்குப் பொருள் கொடுத்து, இலக்கு அடையப்பட்டதா என்று மதிப்பிடும் விதம்.

# நிலை குளிரூட்டி எடுத்துக்காட்டு சுழற்சி
1 இலக்கை நிறுவுதல் “அறையை மேலும் குளிராக்குதல்” —
2 எண்ணத்தை உருவாக்குதல் “குளிரூட்டியின் வெப்பநிலையைக் குறைத்தல்” செயலாக்கம்
3 செயல் வரிசையைக் குறிப்பிடுதல் “தொலைவியக்கியின் கீழ் அம்புப் பொத்தானை அழுத்துதல்” செயலாக்கம்
4 செயலைச் செயல்படுத்துதல் உண்மையில் அதை அழுத்துதல் செயலாக்கம்
5 முறைமை நிலையை உணர்தல் ஒலியைக் கேட்டல், திரையைப் பார்த்தல், குளிர்ந்த காற்றை உணர்தல் மதிப்பீடு
6 முறைமை நிலைக்குப் பொருள் கொள்ளுதல் “திரை இப்போது 22 °C காட்டுகிறது” மதிப்பீடு
7 இலக்குடன் ஒப்பிட்டு மதிப்பிடுதல் “அறை இப்போது போதுமான அளவு குளிர்ந்துள்ளதா?” மதிப்பீடு

செயலைக் குறிப்பிடுவது சூழ்நிலையைச் சார்ந்தது

இலக்கு = அறையைக் குளிராக்குதல்; எண்ணம் = குளிரூட்டியைச் சரிசெய்தல். உடல்சார் சூழ்நிலைக்கு ஏற்ப குறிப்பிடப்படும் செயல்கள் மாறுகின்றன:

# சூழ்நிலை செயல் வரிசை
1 தொலைவியக்கி கைக்கு எட்டும் தொலைவில் உள்ளது அதை எடுத்து வெப்பநிலையைக் குறைக்கும் பொத்தானை அழுத்துதல்
2 தொலைவியக்கி மற்றொருவருக்கு அருகில் உள்ளது அதைச் சரிசெய்ய அவரிடம் கேட்டல்
3 தொலைவியக்கி அறையின் மறுபுறம் உள்ளது; நீங்கள் தனியாக இருக்கிறீர்கள் எழுந்து, நடந்து சென்று, தொலைவியக்கியை எடுத்து, சரிசெய்தல்

மீள்முறை மதிப்பீடு: அறை குளிரவில்லை என்றால் (எ.கா. குளிரூட்டி பழுதடைந்திருந்தால்), மதிப்பீடு தோல்வியடைகிறது. பயனர் இலக்கை மீண்டும் பரிசீலித்து, மின்விசிறியை இயக்குதல் அல்லது வேறு அறைக்குச் செல்லுதல் போன்ற புதிய எண்ணத்தை உருவாக்குகிறார்.

3The two gulfs

இரண்டு Gulfs

Gulf of execution: என்ன செய்ய வேண்டும் தெரியும்; system-இல் எப்படி செய்வது தெரியவில்லை. Gulf of evaluation: செய்தபின் என்ன நடந்தது தெரியவில்லை. தெளிவான controls, உடனடி feedback இந்த இடைவெளிகளைக் குறைக்கும்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Execution gulf உதாரணம்: volume குறைக்க வேண்டும்; எந்தக் knob என்று தெரியவில்லை. தீர்வு: clear labels, natural mapping, visible actions. Evaluation gulf: payment button அழுத்தியபின் success/failure தெரியவில்லை. தீர்வு: progress, clear status, receipt. Feedback இருப்பது மட்டும் போதாது; பயனர் அதன் பொருளைப் புரிந்துகொள்ளவும் வேண்டும்.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

Execution-க்கு “எப்படிச் செய்வது?”, evaluation-க்கு “என்ன நடந்தது; என் goal நிறைவேறியதா?” என்று நினைவில் வையுங்கள். Label இல்லாத microwave-இல் 1 minute heating தேர்வு தெரியாதது முதல் gulf; upload முடிந்ததா காட்டாதது இரண்டாவது. Progress காட்டினாலும் “uploading” என்பதை “saved” என்று தவறாகப் புரியவிட்டால் evaluation gulf இன்னும் உள்ளது.

Norman's key insight is where interaction breaks down:

⚡ Gulf of Execution

The gap between the user's intended actions and the actions the interface actually supports.

"Does the interface give me controls to easily do what I want?"

📊 Gulf of Evaluation

The gap between the system's actual state and the user's ability to perceive and interpret it against the goal.

"Can I easily tell what state the system is in, and whether I succeeded?"

Design objective

Good UI/UX bridges both gulfs:

  • Execution gulf: narrow it with clear affordances and intuitive mapping.
  • Evaluation gulf: narrow it with immediate, informative feedback.
Everyday examples
  • Wide gulf of execution: a microwave with 20 unlabeled buttons. You know you want to "reheat 1 minute" but can't see how.
  • Wide gulf of evaluation: a file upload with no progress bar. Did it work? Is it still going?

4Human errors: slips vs mistakes

Slip மற்றும் Mistake

சரியான திட்டம் இருந்தும் தவறான button அழுத்துவது Slip. தவறாகப் புரிந்துகொண்டு தவறான செயலைத் திட்டமிடுவது Mistake. முதலாவதற்கு undo போன்ற பாதுகாப்பு; இரண்டாவதற்கு தெளிவான விளக்கமும் நல்ல mental model-உம் தேவை.

Slip குறைய பெரிய targets, இடைவெளி, constraints, undo உதவும். Mistake குறைய தெளிவான labels, conceptual model, வழிகாட்டல், feedback, பயிற்சி உதவும். இந்த வகைகள் பிழையின் காரணத்தைக் குறிக்கும்; ஆபத்தின் அளவைக் குறிக்காது. Slip கூட மோசமான விளைவு தரலாம்; mistake-ஐச் சரிசெய்வதும் பயனரைக் குறைசொல்வது அல்ல, design-ஐப் புரியவைத்தலும் ஆகும்.

⚠️ Slip (execution failure) ❌ Mistake (planning / mental failure)
Goal and plan Correct goal, correct plan Wrong goal or intention
What goes wrong The action is performed wrongly: motor error, distraction, poor ergonomics The user misunderstands the system or has a wrong mental model or lacks knowledge

One-liner

A slip = right plan, wrong execution. A mistake = wrong plan or understanding. Improve controls, feedback, conceptual models, guidance and recovery according to the cause; do not assume the user alone is at fault.

5The Abowd & Beale framework

Abowd–Beale தொடர்பாடல் கட்டமைப்பு

User → Input → System → Output → User என நான்கு பகுதிகள். பயனர் நினைப்பது input மொழியாகவும் system நிலை output-ஆகவும் மாறுகிறது. எந்த translation-இல் சிக்கல் என்பதைக் கண்டறிய இந்த framework உதவும்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

நான்கு Translations: Articulation U→I — நோக்கத்தை input-ஆக வெளிப்படுத்தல்; Performance I→S — input system state-ஐ மாற்றல்; Presentation S→O — நிலையை output-ஆகக் காட்டல்; Observation O→U — output-ஐப் பயனர் உணர்தல். Norman user-side action cycle-ஐ விளக்கும். Abowd–Beale user, input, system, output languages இடையேயான translation-ஐ வெளிப்படையாகப் பார்க்கிறது.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

நான்கு மொழிகள்: User-இன் task language; Input controls-இன் input language; System logic/data-வின் core language; Output-இன் display language.

Novice-க்கு input தேர்விலும் output பொருள் புரிவதிலும் அதிக உதவி தேவை.

To address limitations in Norman's model (which focuses only on the user), Gregory Abowd and Russell Beale proposed a 4-component framework. It treats interaction as translations between languages:

Component Language
U – User Task language (psychological)
I – Input Input language (hardware and controls)
S – System Core language (data and logic)
O – Output Output language (display and presentation)

The four translations

# Translation Direction Meaning Cycle
1 Articulation U → I User expresses an intention in the input language (typing, dragging) Execution
2 Performance I → S Input changes the system core's state Execution
3 Presentation S → O The state change is shown through the output language Evaluation
4 Observation O → U User perceives the output and evaluates it against the goal Evaluation

7Direct vs indirect manipulation

Direct மற்றும் Indirect

ஒரு file-ஐப் பிடித்து folder-க்கு இழுப்பது Direct manipulation. Command மூலம் move செய்வது indirect. Direct-இல் பொருள், செயல், விளைவு கண்ணுக்குத் தெரிந்து எளிதாகத் திரும்பச் செய்ய முடிவது முக்கியம்.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

Direct manipulation: வேலைக்கான object-ஐத் திரையில் நேரடியாகச் செயல்படுத்துவதாக உணர்தல் — word தேர்வு செய்து Bold, photo pinch-zoom, file drag. Indirect manipulation: வேறு control/command வழியாகச் செயலைக் குறிப்பிடுதல் — zoom percentage menu-இல் உள்ளிடல் அல்லது simulator control மூலம் வெளியிலுள்ள wall painting செயலை நடத்தல்.

Direct என்றால் touchscreen மட்டுமே அல்ல; mouse drag-உம் direct manipulation ஆகலாம். பார்க்கக்கூடிய objects, செயல்–விளைவு தொடர்பு, உடனடி feedback ஆகியவை முக்கியம். “Mouse என்றால் indirect” என்று கருவியின் பெயரால் மட்டும் வகைப்படுத்தாதீர்கள்.

9Quick revision sheet

விரைவாக நினைவுபடுத்திக்கொள்ள

Interaction என்றால் என்ன?

பயனர் ஒரு இலக்கை அடைய system-உடன் செயலும் பதிலும் பரிமாறுவது Interaction. இலக்கு பசி தீர்ப்பது; task உணவை order செய்வது; interface button அதன் ஒரு பகுதி மட்டுமே.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

Domain–Goal–Task வேறுபாடு: Domain = நாம் பார்க்கும் செயல்துறை; Goal = அடைய வேண்டிய முடிவு; Tasks = அதை அடையச் செய்யும் செயல்கள்.

Taxi app உதாரணம்: domain வாகனப் பதிவு; goal பயணத்திற்கு வாகனம் பெறுதல்; tasks app திறத்தல் → pickup/destination/time/passengers உள்ளிடல் → விலை/வாகனம் ஒப்பிடல் → உறுதிப்படுத்தல் அல்லது மாற்றல். Input click/typing/voice ஆகலாம்; output screen/sound/vibration ஆகலாம். System feedback-ஐ வைத்தே பயனர் அடுத்த செயலைத் தீர்மானிக்கிறார்.

Norman-இன் ஏழு படிகள்

இலக்கு → நோக்கம் → செயல் திட்டம் → செயல்படுத்தல் → முடிவைப் பார்த்தல் → பொருள் புரிதல் → இலக்குடன் ஒப்பிடுதல். ஒரு payment-இல் “எப்படி செலுத்துவது?” முதல் “செலுத்திவிட்டேனா?” வரை இந்தச் சுற்று பொருந்தும்.

ஏழு stages-ஐ ஒரு bank transfer-க்கு பொருத்துங்கள்: பணம் அனுப்ப வேண்டும் → transfer முறை தேர்வு → beneficiary/amount உள்ளிடத் திட்டம் → submit → confirmation பார்க்க → “successful” பொருள் புரிய → சரியானவருக்கு சென்றதா சரிபார். Goal/plan/specify/execute execution பக்கம்; perceive/interpret/evaluate evaluation பக்கம். சொற்களின் பட்டியல் மட்டுமல்ல; எந்த stage-இல் தடையுள்ளது என்று கண்டறிய வேண்டும்.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

AC உதாரணத்தை ஏழு படிகளுடன் எழுதுங்கள்: அறை குளிரவேண்டும் (goal) → AC temperature குறைக்க முடிவு (intention) → down-arrow அழுத்தத் திட்டம் (specify) → அழுத்துதல் (execute) → beep/display காணுதல் (perceive) → 22°C ஆக மாறியதைப் புரிதல் (interpret) → அறை போதுமான அளவு குளிர்ந்ததா ஒப்பிடல் (evaluate).

Remote கையில் இருந்தால் நேரடியாக அழுத்தலாம்; மற்றவரிடம் இருந்தால் அவரிடம் கேட்கலாம்; தூரத்தில் இருந்தால் நடந்து எடுக்கலாம். Goal ஒரேதாக இருந்தாலும் action sequence context-க்கு ஏற்ப மாறும். AC பழுதானால் feedback-ஐப் பார்த்து fan பயன்படுத்தும் புதிய intention உருவாகலாம்.

இரண்டு Gulfs

Gulf of execution: என்ன செய்ய வேண்டும் தெரியும்; system-இல் எப்படி செய்வது தெரியவில்லை. Gulf of evaluation: செய்தபின் என்ன நடந்தது தெரியவில்லை. தெளிவான controls, உடனடி feedback இந்த இடைவெளிகளைக் குறைக்கும்.

Execution gulf உதாரணம்: volume குறைக்க வேண்டும்; எந்தக் knob என்று தெரியவில்லை. தீர்வு: clear labels, natural mapping, visible actions. Evaluation gulf: payment button அழுத்தியபின் success/failure தெரியவில்லை. தீர்வு: progress, clear status, receipt. Feedback இருப்பது மட்டும் போதாது; பயனர் அதன் பொருளைப் புரிந்துகொள்ளவும் வேண்டும்.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

Execution-க்கு “எப்படிச் செய்வது?”, evaluation-க்கு “என்ன நடந்தது; என் goal நிறைவேறியதா?” என்று நினைவில் வையுங்கள். Label இல்லாத microwave-இல் 1 minute heating தேர்வு தெரியாதது முதல் gulf; upload முடிந்ததா காட்டாதது இரண்டாவது. Progress காட்டினாலும் “uploading” என்பதை “saved” என்று தவறாகப் புரியவிட்டால் evaluation gulf இன்னும் உள்ளது.

Slip மற்றும் Mistake

சரியான திட்டம் இருந்தும் தவறான button அழுத்துவது Slip. தவறாகப் புரிந்துகொண்டு தவறான செயலைத் திட்டமிடுவது Mistake. முதலாவதற்கு undo போன்ற பாதுகாப்பு; இரண்டாவதற்கு தெளிவான விளக்கமும் நல்ல mental model-உம் தேவை.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

Slip: channel 8 வேண்டும், எந்த button என்பதும் தெரியும்; கவனம் சிதறி 9 அழுத்துகிறேன். Mistake: channels மாற்றலாம் என்பதே தெரியாத தவறான புரிதல் இருப்பதால் தவறான திட்டம் செய்கிறேன்.

Slip குறைய பெரிய targets, இடைவெளி, constraints, undo உதவும். Mistake குறைய தெளிவான labels, conceptual model, வழிகாட்டல், feedback, பயிற்சி உதவும். இந்த வகைகள் பிழையின் காரணத்தைக் குறிக்கும்; ஆபத்தின் அளவைக் குறிக்காது. Slip கூட மோசமான விளைவு தரலாம்; mistake-ஐச் சரிசெய்வதும் பயனரைக் குறைசொல்வது அல்ல, design-ஐப் புரியவைத்தலும் ஆகும்.

Abowd–Beale தொடர்பாடல் கட்டமைப்பு

User → Input → System → Output → User என நான்கு பகுதிகள். பயனர் நினைப்பது input மொழியாகவும் system நிலை output-ஆகவும் மாறுகிறது. எந்த translation-இல் சிக்கல் என்பதைக் கண்டறிய இந்த framework உதவும்.

நான்கு Translations: Articulation U→I — நோக்கத்தை input-ஆக வெளிப்படுத்தல்; Performance I→S — input system state-ஐ மாற்றல்; Presentation S→O — நிலையை output-ஆகக் காட்டல்; Observation O→U — output-ஐப் பயனர் உணர்தல். Norman user-side action cycle-ஐ விளக்கும். Abowd–Beale user, input, system, output languages இடையேயான translation-ஐ வெளிப்படையாகப் பார்க்கிறது.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

நான்கு மொழிகள்: User-இன் task language; Input controls-இன் input language; System logic/data-வின் core language; Output-இன் display language.

Text bold உதாரணம்: “இதைத் தடித்த எழுத்தாக்கவேண்டும்” → select + Ctrl+B (articulation) → document state bold ஆகிறது (performance) → திரையில் bold render ஆகிறது (presentation) → பயனர் பார்த்து சரியா அறிகிறார் (observation). முதல் இரண்டு execution; கடைசி இரண்டு evaluation. Novice-க்கு input தேர்விலும் output பொருள் புரிவதிலும் அதிக உதவி தேவை.

உடலுக்கு வசதியான வடிவமைப்பு

கணினியை உடல் வசதியுடன் பயன்படுத்தும் வகையில் வடிவமைத்தல். Screen உயரம், எழுத்தளவு, chair, repeated movement எல்லாம் முக்கியம். வேகமாகச் செய்ய முடிவது மட்டும் போதாது; வலி, சோர்வு வரக்கூடாது.

Controls/displays-இன் அமைப்பு; lighting, noise, temperature; posture/repetitive strain; colour/contrast ஆகியவை ergonomics-இல் வரும். Emergency control-ஐ எளிதில் அடைய முடியுமா என்பதும் முக்கியம். அதே வடிவம் எல்லா உடல் அளவு/திறன்களுக்கும் பொருந்தாது. Adjustable setup, readable display, பெரிய targets போன்றவை உடல் உழைப்பையும் பிழையையும் குறைக்கலாம்.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

ஒரு emergency button அழகாக இருந்தாலும் எட்டாத இடத்தில் இருந்தால் ergonomics தோல்வி. தொடர்புடைய controls அருகில் இருக்கட்டும்; முக்கிய controls-க்கு முன்னுரிமை; screen glare, noise, வெப்பம், உட்காரும் நிலை, repeated movements கவனிக்கப்படவேண்டும். நிறம் மட்டும் status-ஐக் காட்டாமல் text/icon-உம் சேர்க்கவும். சூழலும் உடல் திறனும் மாறுவதால் adjustment வசதி முக்கியம்.

Direct மற்றும் Indirect

ஒரு file-ஐப் பிடித்து folder-க்கு இழுப்பது Direct manipulation. Command மூலம் move செய்வது indirect. Direct-இல் பொருள், செயல், விளைவு கண்ணுக்குத் தெரிந்து எளிதாகத் திரும்பச் செய்ய முடிவது முக்கியம்.

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

Direct manipulation: வேலைக்கான object-ஐத் திரையில் நேரடியாகச் செயல்படுத்துவதாக உணர்தல் — word தேர்வு செய்து Bold, photo pinch-zoom, file drag. Indirect manipulation: வேறு control/command வழியாகச் செயலைக் குறிப்பிடுதல் — zoom percentage menu-இல் உள்ளிடல் அல்லது simulator control மூலம் வெளியிலுள்ள wall painting செயலை நடத்தல்.

Direct என்றால் touchscreen மட்டுமே அல்ல; mouse drag-உம் direct manipulation ஆகலாம். பார்க்கக்கூடிய objects, செயல்–விளைவு தொடர்பு, உடனடி feedback ஆகியவை முக்கியம். “Mouse என்றால் indirect” என்று கருவியின் பெயரால் மட்டும் வகைப்படுத்தாதீர்கள்.

கணினியுடன் தொடர்புகொள்ளும் முறைகள்

Menu, form, command, conversation போன்றவை வெவ்வேறு வேலைகளுக்கு ஏற்றவை. Beginner-க்கு menu உதவலாம்; expert-க்கு command வேகமாக இருக்கலாம். யார், எந்த வேலை, எந்த context என்பதைக் கொண்டு தேர்வு செய்யுங்கள்.

எட்டு Styles: command line; menus; natural language; question/answer & query; forms/spreadsheets; WIMP=Windows, Icons, Menus, Pointer; 3D; kinetic/haptic. Menu recognition-க்கு உதவும்; CLI நினைவில் வைத்த commands மூலம் expert-க்கு வேகம். Haptic என்பது vibration/force போன்ற தொடு feedback; speech மட்டும் haptic அல்ல. Context, learning effort, flexibility ஒப்பிடுங்கள்.
