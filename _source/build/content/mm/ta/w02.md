## Stages மற்றும் திருத்தும் cycle

ஒரு multimedia title-ஐ முறையாகத் திட்டமிட்டு உருவாக்க வேண்டும். இதில் பல வேலைகள், நபர்கள், tools, assets சேர்கின்றன. Media உருவாக்க நேரம் தேவை. ஆரம்பத்தில் தெளிவாகத் திட்டமிட்டால் பெரிய திருத்தங்களைப் பிறகு செய்ய வேண்டிய நிலை குறையும். Software-இல் உள்ள எல்லா effects-ஐயும் காட்டுவதைவிட audience-க்கு வேண்டியதைச் செய்வதே நோக்கம்.

## Planning, requirements மற்றும் cost

Idea ஒருவரிடமிருந்தோ குழுவிடமிருந்தோ வரலாம். **Brainstorming**-இல் முதலில் பல ideas உருவாக்குகிறோம். பின்னர் நோக்கம் மற்றும் constraints-க்கு எவை பொருந்தும் என்று பார்க்கிறோம். நல்ல idea இருந்தாலும் audience, treatment, நடைமுறை specification வேண்டும்.

1. **Concept உருவாக்குதல்:** vision மற்றும் சொல்ல வேண்டிய message-ஐ விளக்குங்கள்.
2. **Goals/objectives எழுதுதல்:** title மூலம் என்ன அடைய வேண்டும் என்று சொல்லுங்கள்.
3. **Audience அடையாளம்:** பயன்படுத்தப் போகிறவர்கள் யார் என்று விளக்குங்கள்.
4. **Treatment முடிவு:** guided lesson-ஆ, தேடிப் பார்க்கும் story-ஆ என்று presentation முறையைத் தீர்மானியுங்கள்.
5. **Specifications:** title-இல் என்ன இருக்கும், எப்படி வேலை செய்ய வேண்டும் என்று எழுதுங்கள்.
6. **Storyboard/navigation:** screens மற்றும் அவற்றின் இணைப்புகளைக் காட்டுங்கள்.

**Scope** என்பது project-இன் எல்லை. சேரும் content, சேராத content, கிடைக்கும் நேரம், தேவைப்படும் skills, application organisation ஆகியவற்றை வரையறுக்க வேண்டும். எல்லை இல்லாவிட்டால் ஒவ்வொரு புதிய idea-வும் புதிய வேலையாகிவிடும். Scope ஆசையையும் resources-ஐயும் சமப்படுத்துகிறது.

Audience-இன் age group, முன் அறிவு/கல்வி, technology அனுபவம், language, gender, பொருளாதாரப் பின்னணி, profession ஆகியவற்றை ஆராயுங்கள். தகவலை வைத்து பொருத்தமாக வடிவமைக்க வேண்டும்; ஒரே demographic குழுவில் எல்லோருக்கும் ஒரே தேவைகள் இருக்கும் என்று நினைக்க வேண்டாம். மாணவர், சுற்றுலாப் பயணி, அனுபவமுள்ள technician ஆகியோருக்கு வேறு சொற்களும் navigation-உம் தேவைப்படலாம்.

**Content analysis**-இல் எவ்வளவு விரிவாகவும் ஆழமாகவும் சொல்ல வேண்டும் என்று முடிவெடுக்கிறோம். எதை reuse செய்யலாம், புதிதாக எதை உருவாக்க வேண்டும், எதற்கு permission வேண்டும், எதை digitise செய்ய வேண்டும் என்று பாருங்கள். Photo/audio/video capture, text/graphics/sound effects/animation உருவாக்கம் எல்லாவற்றுக்கும் நேரமும் திறனும் தேவை. Audience எதிர்பார்ப்புடன் content-ஐச் சமப்படுத்துங்கள்.

PDF-இல் **time, money, people** estimate-ஐ மாற்றும் மூன்று அம்சங்கள். Content அல்லது interaction அதிகமானால் production வேலை அதிகரிக்கலாம். Delivery தேதியைச் சொல்வதற்கு முன் specialist வேலைகளையும் review இடங்களையும் திட்டமிடுங்கள்.

| Team role | பொறுப்பு |
|---|---|
| Project manager | Development/implementation-ஐ வழிநடத்தி தினசரி வேலைகளை ஒருங்கிணைக்கிறார்; management மற்றும் technical புரிதல் வேண்டும் |
| Multimedia designer | Visuals, illustration, animation, interface, storyboard மற்றும் சீரான information flow உருவாக்குகிறார் |
| Video specialist | Video shoot/capture/edit செய்கிறார் |
| Audio specialist | Speech, music, narration, sound effects உருவாக்குகிறார் |
| Multimedia programmer | Authoring system அல்லது programming language மூலம் assets-ஐச் சேர்த்து வேலை செய்யும் title உருவாக்குகிறார் |

## Activity 2.1: முழுமையான title plan

**கேள்வி:** Idea, goal/objectives, audience, delivery/playback medium, team roles, tools/equipment கொண்ட multimedia title ஒன்றைத் திட்டமிடுங்கள்.

:::example மாதிரி விடை: “இலங்கை Bus Route-ஐப் படிப்போம்”
**Idea:** சரியான bus-ஐத் தேர்ந்தெடுத்து route number-ஐ அறியச் சிறிய interactive title. **Goal:** முதன்முறையாகப் பயணிப்பவர்கள் route தகவலை நம்பிக்கையுடன் பயன்படுத்த உதவுவது. **Objectives:** origin/destination-ஐ அடையாளம் காணுதல், எளிய map-இல் route தேர்ந்தெடுத்தல், route number எங்கே பார்ப்பது என்று விளக்குதல்.

**Audience:** Phone பயன்படுத்தத் தெரிந்தாலும் உள்ளூர் பயண அனுபவம் குறைந்த புதிய university மாணவர்கள். Tamil/Sinhala/English விருப்பம் இருக்கலாம். எளிய மொழி, படிக்கக்கூடிய text, மீண்டும் கேட்கும் narration கொடுக்க வேண்டும்.

**Delivery/play:** Phone browser-இல் இயங்கும் lightweight website. Download version-இல் முக்கிய text/diagrams-ஐ local-ஆக வைக்கலாம். Optional video-ஐ compress செய்து connection குறைந்தவர்களுக்கு text விளக்கமும் கொடுக்கலாம்.

**Roles:** Manager scope/review-ஐப் பார்ப்பார்; designer maps/screens உருவாக்குவார்; video specialist demonstration பதிவு செய்வார்; audio specialist narration செய்வார்; programmer screens/feedback-ஐ இணைப்பார். போக்குவரத்து தெரிந்த reviewer accuracy பார்ப்பார்.

**Tools/equipment:** Phone camera/microphone, processing computer, map-க்கான vector/image editor, audio/video editors, web authoring environment, test phones, storage, distribution server.

**Scope/checks:** நாடு முழுவதற்கான live timetable என்று வாக்குறுதி தராமல் ஒரு fictional training route மட்டும். உண்மையான புதிய மாணவர்களிடம் menu choices, labels, narration controls, feedback ஆகியவற்றைச் சோதிக்க வேண்டும். Language choice மற்றும் குறைந்த bandwidth பயன்பாட்டையும் பார்க்க வேண்டும்.
:::

## Design principles மற்றும் விரிவான process

Multimedia design பல media assets-ஐ ஒரே அர்த்தமுள்ள presentation-ஆக இணைக்கிறது. Message-க்கு உதவும் principles-ஐப் பயன்படுத்துங்கள்; எல்லா இடத்திலும் effects சேர்க்க வேண்டியதில்லை.

| Principle | பொருள் | Bus lesson-இல் பயன்பாடு |
|---|---|---|
| Balance | ஒரு பகுதி தேவையில்லாமல் அதிகமாகத் தெரியாதபடி visual weight-ஐப் பகிர்தல் | Map/instructions இடையே சமநிலை |
| Harmony | எல்லா elements-உம் ஒரே presentation-ஆகப் பொருந்துதல் | ஒரே visual/narration style |
| Emphasis | முக்கியமானதை நோக்கிக் கவனம் ஈர்த்தல் | கேள்விக்கு முன் destination highlight |
| Movement | கண் பார்க்கும் வரிசையை வழிநடத்துதல் | Route label → map → answer |
| Rhythm/pattern | Elements-ஐ மீண்டும் பயன்படுத்தி ஒழுங்கு கொடுத்தல் | Headings/navigation ஒரே இடத்தில் |
| Contrast | திட்டமிட்ட வேறுபாட்டால் முக்கியத்துவம் காட்டுதல் | தேர்ந்த route-ஐ வேறுபடுத்துதல் |
| Hierarchy/proportion | முக்கியத்துவத்திற்கேற்ப அளவு/வலிமை கொடுத்தல் | Main heading-க்கு detail-ஐவிட அதிக முக்கியத்துவம் |

Balance என்றால் எல்லாவற்றுக்கும் ஒரே முக்கியத்துவம் என்பது இல்லை. எல்லாமே ஒரே அளவில் கவனம் ஈர்த்தால் emphasis இருக்காது. Source-இன் “equal emphasis” என்பதை visual weight சமநிலை என்று புரிந்துகொள்ளுங்கள்.

Requirements/goals-க்குப் பிறகு **content definition**, **content outline** உருவாக்குங்கள். Logic flow, navigation map, storyboard செய்யுங்கள். Figure 2.2-இல் மேலே requirements/goals; அடுத்து content definition/outlining மற்றும் logical flow/navigation; அடுத்து asset capture/storyboarding; கீழே implementation. Client வேலை, client/developer இணைவேலை, developer வேலை என்று பிரிக்கிறது.

:::flow Development dependency-ஐ மீண்டும் வரைதல்
Requirements capture மற்றும் goals
Content definition + outline + logic flow/navigation map
Client ஒப்புக்கொண்ட asset capture + storyboard
Development team செய்யும் implementation
:::

## Storyboard, navigation map மற்றும் script

**Storyboard** presentation எப்படி இருக்கும் என்பதை ஒழுங்குபடுத்துகிறது. Video-வில் scene உருவாக்கும் shots; application-இல் screens, media, transitions ஆகியவற்றை sketch செய்கிறது. Project goals-இலிருந்து தொடங்கி ஆரம்ப specification உருவாக்க உதவுகிறது. Figure 2.3 college title-இன் welcome, main menu, information, courses, registration, services screens-ஐக் காட்டுகிறது.

**Navigation map** scenes/content components இடையிலான links-ஐக் காட்டுகிறது. Logical-flow definition-உடன் சேர்த்தோ தனியாகவோ கொடுக்கலாம். Figure 2.4 college screens இடையிலான routes-ஐச் சேர்க்கிறது; Courses-இலிருந்து credit/non-credit தகவல் பிரிகிறது. Storyboard “screen-இல் என்ன?” என்றும் map “screen-களுக்கிடையே எப்படிச் செல்வது?” என்றும் விளக்குகிறது.

**Script** விரிவான textual instructions கொடுக்கிறது. Layout sketch, narration, dialogue இருக்கலாம். வேறு team member அதைப் பார்த்து implement செய்யக்கூடிய தெளிவு வேண்டும்.

- சிறிய screens-ஆகப் பிரித்து sequence number கொடுங்கள்.
- ஒவ்வொரு media element/interaction-ஐயும் தெளிவாக எழுதுங்கள்.
- உற்சாகமான conversational tone மற்றும் active sentences பயன்படுத்துங்கள்.
- சரி/தவறு இரண்டுக்கும் feedback கொடுங்கள்.
- Audience கவனத்தை எப்படிப் பெறுவது என்று சொல்லுங்கள்.
- User action மற்றும் application response இரண்டையும் வடிவமைக்குங்கள்.

## Production, hardware மற்றும் authoring metaphors

Implementation storyboard/script-ஐப் பின்பற்றுகிறது. தேவையான assets-ஐ முதலில் அடையாளம் கண்டு capture/create செய்யுங்கள். **Authoring** தயாரான text/images/audio/animation/video-ஐ ஒரே title-ஆக ஒருங்கிணைக்கிறது. பெரிய media files வெளியே linked files-ஆக இருக்கலாம். Package-இல் அவை வேலை செய்கிறதா பார்க்க வேண்டும்; developer computer-இல் file இருப்பது மட்டும் போதாது.

Capturing devices media பெறும்; processing devices edit/encode செய்யும்; playing devices காட்டும்/ஒலிக்கச் செய்யும்; distribution devices வழங்கும்/copy செய்யும். Camera/microphone, computer, display/speaker, server/network/disc-copying equipment உதாரணங்கள். Media data-வின் volume, density, speed, variety காரணமாக அதிக performance தேவைப்படலாம்.

Authoring programs drawing/text/animation tools, templates, hyperlinks, interaction கொடுக்கலாம். PDF-இல் உள்ள authoring metaphors என்பது வேலையை ஒழுங்குபடுத்தும் முறைகள்:

| Metaphor | அமைப்பு மற்றும் உதாரணம் |
|---|---|
| Scripting language | Conditions/jumps/loops/functions-க்கு commands; ActionScript, Lingo, AWScripts |
| Slide show | வரிசையான slides; jumps-உம் இருக்கலாம்; PowerPoint |
| Hierarchical | Tree அமைப்பில் user choices/menus |
| Iconic/flow-control | Toolbox icons மூலம் flowchart; Authorware |
| Frames | Icons இடையே execution flow மட்டுமின்றி conceptual தொடர்பு |
| Card/scripting | Hypertext/hypermedia-க்கான index-card அமைப்பு; HyperCard, SuperCard |
| Cast/score/scripting | Horizontal time; tracks-இல் cast media instances; event procedures; Director/Lingo |
| Timeline-based | Text/graphics/animation/video/sound timing இணைப்பு; source வெளிப்புற playback devices-ஐ script மூலம் control செய்வதையும் சொல்கிறது |

இந்த software பெயர்கள் course-இன் பழைய உதாரணங்கள். Metaphor-ஐக் கற்றுக்கொண்டு interaction/delivery platform-க்கு ஏற்ற tool-ஐத் தேர்ந்தெடுங்கள்.

## Testing, delivery மற்றும் review விடைகள்

Testing accuracy, functionality, appearance, நோக்கம் அடைதல் ஆகியவற்றைப் பார்க்கிறது. ஒவ்வொரு feature/button/link-ஐயும் சோதியுங்கள். வேறு hardware/conditions-இலும் இயக்குங்கள். Fault-ஐ மீண்டும் உருவாக்கத் தேவையான விவரம் எழுதுங்கள்; திருத்திய பிறகு மீண்டும் check செய்யுங்கள்.

| Alpha testing | Beta testing |
|---|---|
| Implementation ஆரம்பத்தில்; content/features முடியாமல் இருக்கலாம் | Final release அருகில்; title முழுமையாக இயங்க வேண்டும் |
| பொதுவாக team/தேர்ந்த users/நண்பர்கள் | Team-க்கு வெளியே உண்மையான target users |
| Concept/format/interface/layout review | மீதமுள்ள defects/content problems கண்டறிதல் |
| ஆரம்பத் திருத்தங்களுக்கு உதவும் | விரிவான reports இறுதித் திருத்தங்களுக்கு உதவும் |

Delivery/deployment தேர்ந்த medium-க்கு ஏற்றதாக இருக்க வேண்டும். Hardware/software/plugins/installation-ஐ ஏற்பாடு செய்யுங்கள். Numbered installation/startup steps, வரக்கூடிய problems/solutions கொடுங்கள். Development copy மட்டும் பார்க்காமல் linked files உட்பட delivered copy-ஐச் சோதியுங்கள்.

**Review question 1: Title type-க்கு ஏற்ப development approach எப்படி மாறும்?** Educational title-இல் learning objectives, விளக்கம், learner control, feedback முக்கியம். Entertainment-இல் story/timing/immersion/responsive interaction முக்கியம். Linear film-க்கு shot storyboard மற்றும் timed script; interactive title-க்கு navigation routes/events/branching tests கூடுதலாக வேண்டும். எல்லாவற்றிலும் planning, design/production, testing, delivery தேவை; assets/audience-க்கு ஏற்ப வேலை அளவு மாறும்.

**Review question 2: Education/entertainment authoring software விளக்குங்கள்.** Slide tool guided lesson/hyperlinks உருவாக்கலாம். Card/hierarchical authoring topic choices-க்கு உதவும். Scripting answer checking/game rules-க்கு உதவும். Timeline/cast-score narration/animation/video-ஐ நேரத்துடன் இணைக்கும். PowerPoint, HyperCard/SuperCard, Authorware, Director PDF examples. பெயர் மட்டும் எழுதாமல் metaphor மற்றும் ஏன் பொருந்தும் என்றும் விளக்குங்கள்.

:::exam English answer frame
“First analyse the purpose, audience, content and scope. Estimate time, cost and team roles. Define the outline, logical flow, navigation map, storyboard and script. Capture or create the assets and integrate them with suitable authoring software. Conduct alpha and beta testing, correct defects, and deliver a complete package with installation and troubleshooting instructions. Use evaluation feedback for improvement.”
