## சோடிகளிலிருந்து n-உறுப்புச் சோடிகளுக்கு

தொடர்புகளில் பெரும்பாலும் **இரண்டுக்கும் மேற்பட்ட** விடயங்கள் உள்ளன:

- நோயாளியின் **பெயர், உயரம், நிறை**
- தயாரிப்பின் **பெயர், பொருள் எண், உற்பத்தித் திகதி, காலாவதித் திகதி, விலை**
- **ஏறுவரிசையிலுள்ள** மூன்று முழு எண்கள்

இவை குறிப்பாக **தரவுத்தள முகாமைத்துவ முறைமைகளில்** பொதுவானவை.

:::video "கூட்டினால் கிடைக்கும்" தொடர்பு [[01:09]]
"சிறியது" என்பது (0, 1) போன்ற **சோடிகளின்** கணம். ஆனால் தொடர்பில் **மூன்றுறுப்புச் சோடிகளும்** இருக்கலாம். **a + b = c** எனில் (a, b, c)-க்கு **கூட்டினால் கிடைக்கும்** தொடர்பு S பொருந்துகிறது:

- (2, 2, 4) ∈ S
- (0, 1, 1) ∈ S
- (5, −2.1, 2.9) ∈ S

S ⊆ ℝ × ℝ × ℝ. **ஒரு தொடர்புக்குள் ஒவ்வொரு உறுப்புச் சோடியும் ஒரே நீளம் கொண்டது** [[02:27]].
:::

:::key வரையறை 1
A₁, A₂, …, Aₙ கணங்களாக இருக்கட்டும். இக்கணங்களின் **n-உறுப்புத் தொடர்பு**, **A₁ × A₂ × ⋯ × Aₙ-இன் உட்கணம்**.

- A₁, …, Aₙ கணங்கள் தொடர்பின் **ஆட்களங்கள்**.
- **n** அதன் **படி**.
- மூலகங்கள் **வரிசைப்படுத்தப்பட்ட n-உறுப்புச் சோடிகள்**.
:::

ஆட்களங்கள் **ஒரே கணமாக இருக்க வேண்டியதில்லை**. தொலைபேசித் தொடர்புப் பட்டியல் **பெயர்களைத் தொலைபேசி எண்களுடன்** தொடர்புபடுத்துகிறது; பெயர்கள் × எண்களின் உட்கணம் [[03:00]].

## தரவுத்தளங்களும் தொடர்புநிலைத் தரவு மாதிரியும்

- தரவுத்தளங்கள் நாள்தோறும் ஆயிரக்கணக்கான முறை பதிவுகளைத் தொடர்ந்து **சேர்த்து, நீக்கி, புதுப்பித்து, தேடி, இணைக்கின்றன**. **தரவு சேமிக்கப்படும் முறை** அதன் வேகத்தைத் தீர்மானிக்கிறது.
- **தொடர்புநிலைத் தரவு மாதிரி**, தரவுத்தளத்தை **n-உறுப்புத் தொடர்பாக** பிரதிநிதித்துவப்படுத்துகிறது.

## முதன்மைச் சாவிகள், கூட்டுச் சாவிகள், விரிவு, உள்நோக்கம்

:::key முதன்மைச் சாவி
**சாவி** என்பது அதன் பெறுமதிகளால் **உறுப்புச் சோடியைத் தனித்துவமாக அடையாளப்படுத்தும்** பண்புக்கூறு அல்லது பண்புக்கூறுகளின் சேர்க்கை. **முதன்மைச் சாவி**, தேர்ந்தெடுக்கப்பட்ட வேட்பாளர் சாவி; ஆட்களம் (அனுமதிக்கப்பட்ட பெறுமதிகளின் கணம்) தானே சாவி அல்ல.
:::

:::key கூட்டுச் சாவி
ஒவ்வொரு உறுப்புச் சோடியையும் ஒன்றாகச் சேர்ந்து தனித்துவமாக அடையாளப்படுத்தும் பெறுமதிகளுள்ள **பண்புக்கூறுகளின் சேர்க்கை**. வேட்பாளர் சாவிக்கு சேர்க்கை குறைந்தபட்சமானது; தேவையற்ற புலங்களைச் சேர்ப்பது குறைந்தபட்சமல்லாத மேற்சாவியை வழங்குகிறது.
:::

:::example எடுத்துக்காட்டுகள் 10.2.1, 10.2.2 (உறுப்புச் சோடிகள் சேர்க்கப்படவில்லை என அனுமானித்து)
| புலம் | முதன்மைச் சாவியா? | ஏன் |
|---|---|---|
| மாணவர்_பெயர் | ✓ (இந்த விரிவில்) | அனைத்துப் பெயர்களும் வேறுபட்டவை |
| மாணவர்_சுட்டெண் | ✓ | அனைத்தும் தனித்துவமானவை |
| சிறப்புத்துறை | ✗ | கணினி அறிவியலும் கணிதமும் மீண்டும் வருகின்றன |
| GPA | ✗ | 3.45 மீண்டும் வருகிறது |
| **துறை × GPA** | ✓ **கூட்டுச் சாவி** | துறை **மற்றும்** GPA இரண்டையும் எந்த இரு நிரைகளும் பகிர்வதில்லை |
:::

| சொல் | பொருள் |
|---|---|
| **விரிவு** | **தற்போதைய உறுப்புச் சோடிகளின் தொகுப்பு**; பதிவுகள் சேர்க்கப்படும்போது அல்லது நீக்கப்படும்போது மாறுகிறது |
| **உள்நோக்கம்** | **நிலையான பகுதி**: தரவுத்தளத்தின் **பெயரும் பண்புக்கூறுகளும்** |

:::warn மாற்றத்திலும் சாவிகள் செயல்பட வேண்டும்
மாதிரியில் காணப்படும் தனித்துவம், திட்டவடிவச் சாவியை நிறுவப் போதாது. புதிய பதிவுகள் மோசமான தேர்வை வெளிப்படுத்தலாம்; அறிவிக்கப்பட்ட சாவி அனுமதிக்கப்பட்ட அனைத்துத் தரவு நிலைகளிலும் தனித்துவமாக இருக்க வேண்டும். எனவே **உள்நோக்கத்தைப்** பார்த்து **சாத்தியமான அனைத்து விரிவுகளுக்கும்** செயல்படும் சாவிகளைத் தேர்ந்தெடுக்கவும்.

- **சுட்டெண்** நல்ல சாவி (எந்த இரு மாணவர்களும் ஒருபோதும் பகிர்வதில்லை).
- **பெயர்** மோசமான சாவி (இரு மாணவர்களுக்கு ஒரே பெயர் இருக்கலாம்).
:::

## செயல்பாடுகள்: தேர்வு, வீழ்த்தல், இணைப்பு

### தேர்வு Sᴄ (வரையறை 2)
**தேர்வுச் செயற்குறி Sᴄ**, R தொடர்பை **C நிபந்தனையை நிறைவேற்றும் R-இன் அனைத்து உறுப்புச் சோடிகளின்** தொடர்பாக மாற்றுகிறது. **நிரைகளைத் தேர்ந்தெடுக்கிறது**.

:::example எடுத்துக்காட்டு 10.3.1
- C₁: துறை = "கணினி அறிவியல்" → (Ackermann, 231455, கணினி அறிவியல், 3.88), (Chou, 102147, கணினி அறிவியல், 3.49)
- C₂: GPA > 3.5 → Ackermann, Rao
- C₃: துறை = "கணினி அறிவியல்" **∧** GPA > 3.5 → **(Ackermann, 231455, கணினி அறிவியல், 3.88)** மட்டும்
:::

### வீழ்த்தல் P<sub>i₁, i₂, …, iₘ</sub> (வரையறை 3)
**வீழ்த்தல் P<sub>i₁,…,iₘ</sub>** (i₁ < i₂ < … < iₘ உடன்), (a₁, …, aₙ)-ஐ **(a<sub>i₁</sub>, …, a<sub>iₘ</sub>)-க்குப்** பொருத்துகிறது. **நிரல்களைப் பேணி**, **அவற்றில் n − m-ஐ நீக்குகிறது**.

:::example எடுத்துக்காட்டுகள் 10.3.2, 10.3.3
- (2, 3, 0, 4)-இல் P₁,₃, **(2, 0)** வழங்குகிறது.
- (Jane Doe, 234111001, புவியியல், 3.14)-இல் P₁,₃, **(Jane Doe, புவியியல்)** வழங்குகிறது.
- அட்டவணை 10.2.1-இல் P₁,₄, மாணவர்_பெயர், GPA-ஐப் பேணுகிறது (அட்டவணை 10.3.1).
:::

:::warn வீழ்த்தல் குறைந்த நிரைகளை உருவாக்கலாம் (எடுத்துக்காட்டு 10.3.4)
உறுப்புச் சோடிகள் **நீக்கப்பட்ட நிரல்களில் மட்டும் வேறுபட்டால்**, வீழ்த்தியபின் **ஒரே மாதிரியாகி**, ஒன்றாக இணைகின்றன. அட்டவணை 10.3.2-இல் 8 நிரைகள் உள்ளன (Glauser ×3, Marcus ×3, Miller ×2; பாடத்துக்கு ஒன்று). P₁,₂ (மாணவர், துறை), **3 நிரைகளை மட்டுமே** வழங்குகிறது: Glauser–உயிரியல், Marcus–கணிதம், Miller–கணினி அறிவியல்.
:::

### இணைப்பு
**இணைப்பு**, **ஒரே புலங்களின்** அடிப்படையில் இரு அட்டவணைகளை ஓர் அட்டவணையாக இணைக்கிறது.

*எடுத்துக்காட்டு 10.3.5:* பொதுப் புலங்கள் **துறை, பாடக்குறியீடு** ஆகியவற்றில் **கற்பித்தல்_ஒதுக்கீடுகளை** (விரிவுரையாளர், துறை, பாடக்குறியீடு), **வகுப்பு_அட்டவணையுடன்** (துறை, பாடக்குறியீடு, இடம், நேரம்) இணைக்கவும். முடிவு அட்டவணை 10.3.6 (விரிவுரையாளர், துறை, பாடக்குறியீடு, இடம், நேரம்).

{{tool:ra2}}

:::exam
எதிர்பார்க்க வேண்டியவை:

- n-உறுப்புத் தொடர்பில் உறுப்புச் சோடிகளைப் பட்டியலிடுதல் (எ.கா. 0 < a < b < c < 5)
- **படியையும் ஆட்களங்களையும்** குறிப்பிடுதல்
- அட்டவணையில் **முதன்மை மற்றும் கூட்டுச் சாவிகளைக் கண்டறிந்து**, சாத்தியமான சாவிகளை மதிப்பிடுதல் (மாணவர் ID: ஆம்; பெயர், தொலைபேசி: இல்லை; நூல்களுக்கு ISBN)
- **தேர்வு, வீழ்த்தல்** (இணையும் நிரைகளைக் கவனிக்கவும்), **இணைப்பு** செய்தல்
:::

**Q1.** A 3-ary relation on sets A, B, C is a subset of:

(a) A ∩ B ∩ C (b) A × B × C (c) A × C (d) A ∪ B ∪ C

**✅ Answer: (b) A × B × C**

An **n-ary relation** is a set of **n-tuples**. With 3 sets, each tuple is (a, b, c) → a subset of A × B × C. (Binary = 2-tuples = subset of A × B.)


**Q2.** Which is an n-ary relation?

(a) employee name, number, salary, contact number (c) school name, address, number of teachers, number of students (d) five integers in an arithmetic progression with difference 5 (b) all of the above

**✅ Answer: all of the above**

Each one links **several values together in one tuple** (4 values, 4 values, 5 values) → each is an n-ary relation. A row in a database table is exactly this.


**Q3.** R = {(a, b, c, d) | a, b, c, d positive integers with abcd = 6}. The domains are all ____ and the degree is ____.

(a) positive integers, 4 (b) the letters {a, b, c, d}, 4 (c) none (d) the integers, 4

**✅ Answer: (a) the set of positive integers, 4**

- **Domain** = the set each position's values come from → positive integers (as the question says).
- **Degree** = how many items in each tuple → (a, b, c, d) has **4**. Example tuple: (1, 2, 3, 1).


**Q4.** Which is **incorrect**?

(a) A relational database consists of records which are n-tuples made of fields. (b) A database of records is a **binary** relation in the relational model. (c) Fields are the entries of the n-tuples. (d) The relational model is based on relations.

**✅ Answer: (b)**

Records usually have **many** fields (name, ID, major, GPA …), so a database is an **n-ary** relation, not binary (2 fields only).


**Q5.** True or false: relations used to represent databases are also called **tables**.

**✅ Answer: True**

**Vocabulary match:** relation = **table**, n-tuple = **record / row**, field = **column**.


**Q6.** A domain whose value uniquely determines the n-tuple is called:

(a) a primary key (b) an extension (c) an intension (d) a composite key

**✅ Answer: (a) a primary key**

- **Primary key:** one field that identifies each record uniquely (e.g. Student ID).
- **Composite key:** **several** fields together identify the record.


**Q7.** The **extension** of a relational database is:

(a) another word for primary key (b) none (c) the current collection of n-tuples in a relation (d) the more permanent part of a database

**✅ Answer: (c) the current collection of n-tuples**

- **Extension** = the actual rows **right now** (it changes as data is added or deleted).
- **Intension** = the permanent part: the table's **name and its fields** (the structure). Option (d) describes intension.


**Q8.** Which is **not** an operation on n-ary relations?

(a) projection (b) join (c) selection (d) multiplication

**✅ Answer: (d) the multiplication operator**

The operations are:

- **Selection** σ: keep the **rows** that meet a condition.
- **Projection** P: keep only some **columns** (and drop repeated rows).
- **Join** J: combine two tables on matching fields.
There is no “multiplication operator”.
