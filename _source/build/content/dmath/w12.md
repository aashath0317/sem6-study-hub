## Trees

:::key Definition 1
- A **circuit** is a **path that begins and ends at the same vertex**.
- A **tree** is a **connected graph that contains no simple circuits**.
:::

**History and uses:**

- **Arthur Cayley (1857)** used trees to **count chemical compounds**.
- **Computer science:** efficient algorithms for **locating items in a list**.
- **Games** such as checkers and chess: finding **winning strategies**.
- Modelling **sequences of decisions**, e.g. the complexity of sorting algorithms.
- **Family trees** (genealogical charts): vertices are people, edges are parent–child links.

:::key Trees are simple graphs
A tree **can't contain a simple circuit**, so it **can't have multiple edges or loops**. **Every tree is a simple graph.**
:::

:::example Example 12.1.1 — which are trees?
| Graph | Tree? | Reason |
|---|---|---|
| G₁ | ✓ | Connected, no simple circuits |
| G₂ | ✓ | Connected, no simple circuits |
| G₃ | ✗ | e, b, a, d, e is a **simple circuit** |
| G₄ | ✗ | **Not connected** |
:::

### Forests
A graph with **no simple circuits** that is **not necessarily connected** is a **forest**. **Each connected component is a tree.** (Figure 3: one graph, three components, three trees.)

:::key Theorem 1
An undirected graph is a tree **if and only if there is a unique simple path between any two of its vertices**.
:::

:::tip Quick tree tests
A graph with n vertices is a tree if any **two** of these hold:

1. It is **connected**.
2. It has **no simple circuits**.
3. It has exactly **n − 1 edges**.
:::

## Rooted trees & terminology

:::key Definition 2
A **rooted tree** is a tree in which **one vertex is designated as the root** and **every edge is directed away from the root**.
:::

- **Any** vertex can be chosen as the root, and **different roots give different rooted trees** (Figure 4: the same tree T rooted at a and at c).
- We draw the **root at the top** and **omit the arrows**: the choice of root determines their directions.

| Term | Definition |
|---|---|
| **Parent** of v | The unique vertex u with a directed edge **u → v** |
| **Child** of u | v is a child of u if u is v's parent |
| **Siblings** | Vertices with the **same parent** |
| **Ancestors** of v | Vertices on the path **from the root to v**, **excluding v**, **including the root** |
| **Descendants** of v | Vertices that have **v as an ancestor** |
| **Leaf** | A vertex with **no children** |
| **Internal vertex** | A vertex **with children**. The root is internal unless it is the only vertex (then it's a leaf) |
| **Subtree** rooted at a | a, all its descendants, and the edges **between those vertices**; exclude the edge from a to its parent |

## Ordered rooted trees & binary trees

| Concept | Definition |
|---|---|
| **Ordered rooted tree** | A rooted tree where the **children of each internal vertex are ordered**, drawn **left to right** |
| **Binary tree** (ordered binary tree) | Each vertex has **at most two children**, designated left and right. If there are two, the first is the left child and the second is the right child |
| **Left / right subtree** | The tree rooted at the **left / right child** of a vertex |

In some applications every non-root vertex is labelled left or right **even if it is an only child**.

:::example Example 12.1.3 — Figure 7(a)
- The **left child of d is f** and the **right child is g**.
- The **left subtree of c** is rooted at h (h → j).
- The **right subtree of c** is rooted at i (i → k, l; l → m).
:::

## Binary search trees (BST)

**Goal:** search a list efficiently when the items are **totally ordered**.

:::key Binary search tree
A **binary tree** where:

- each child is designated **left or right**
- **no vertex has more than one left or one right child**
- each vertex is labelled with a **key** (one of the items)

**The key of each vertex is larger than every key in its left subtree and smaller than every key in its right subtree.**
:::

### Building one (insertion)
1. The **first item** becomes the **root**.
2. For each new item, start at the root:
    - **Smaller → go left**; **larger → go right**.
    - Repeat until the needed child **doesn't exist**.
3. **Insert the item there** as a new left or right child.

:::example Example 12.2.1 — mathematics, physics, geography, zoology, meteorology, geology, psychology, chemistry
1. **mathematics** → root
2. **physics** > mathematics → right child of mathematics
3. **geography** < mathematics → left child of mathematics
4. **zoology** > mathematics, > physics → right child of physics
5. **meteorology** > mathematics, < physics → left child of physics
6. **geology** < mathematics, > geography → right child of geography
7. **psychology** > mathematics, > physics, < zoology → left child of zoology
8. **chemistry** < mathematics, < geography → left child of geography

```
                 mathematics
               /             \
        geography            physics
        /       \           /       \
  chemistry   geology  meteorology  zoology
                                    /
                              psychology
```
:::

### Algorithm 1 — locating and adding an item

```
procedure insertion(T: binary search tree, x: item)
v := root of T              {a vertex not present in T has the value null}
while v ≠ null and label(v) ≠ x
begin
    if x < label(v) then
        if left child of v ≠ null then v := left child of v
        else add new vertex as a left child of v and set v := null
    else
        if right child of v ≠ null then v := right child of v
        else add new vertex as a right child of v and set v := null
end
if root of T = null then add a vertex v to the tree and label it with x
else if v is null or label(v) ≠ x then label new vertex with x and let v be this new vertex
{v = location of x}
```

:::example Example 12.2.2 — insert "oceanography"
- At **mathematics**: oceanography > mathematics → go **right** to physics.
- At **physics**: oceanography < physics → go **left** to meteorology.
- At **meteorology**: oceanography > meteorology. There's **no right child**, so add a **new right child** of meteorology. Set v := null and exit the loop.
- Label the new vertex **oceanography**.
:::

**Q1.** In a binary tree, how many children can a node have?

(a) 0 or 1 (b) 0, 1 or 2 (c) 2 (d) any number

**✅ Answer: (b) 0, 1 or 2**

**Binary = at most 2** children (a left child and a right child). A leaf has 0.


**Q2.** The tree with root 10, left child 16 and right child 12 is an example of a:

(a) binary tree (b) binary search tree (c) Fibonacci tree (d) AVL tree

**✅ Answer: (a) binary tree**

Each node has at most 2 children → binary tree. It is **not** a binary search tree: in a BST the left child must be **smaller** than the parent, but 16 > 10.


**Q3.** Number of external nodes (leaves) in a full binary tree with n internal nodes?

(a) 2n + 1 (b) 2n (c) n + 1 (d) n

**✅ Answer: (c) n + 1**

**Full binary tree** = every internal node has exactly 2 children. Then **leaves = internal nodes + 1**.
Check: a root with 2 children → 1 internal, 2 leaves ✓. (Total nodes = 2n + 1, which is the trap in (a).)


**Q4.** Which is **false** about a binary search tree?

(a) left and right subtrees are also BSTs (b) the right child is always greater than its parent (c) the left child is always smaller than its parent (d) none of the above

**✅ Answer: (d) none of the above — (a), (b) and (c) are all true**

**BST rule:** everything in the **left** subtree < the node < everything in the **right** subtree, and this holds at every node.


**Q5.** Conditions for an **optimal binary search tree**, and its advantage?

**✅ Answer: the tree is not modified, and you know how often each key is accessed — it improves (lowers) the lookup cost**

An optimal BST puts the **most frequently searched keys near the root**, so the average search is shortest. That only works if the keys and their access frequencies are known and the tree stays fixed.


**Q6.** What is a **complete** binary tree?

**✅ Answer: every level is full except possibly the bottom level, which is filled from left to right**

- **Complete:** all levels full, last level filled **left to right** with no gaps.
- **Full:** every node has **0 or 2** children (option (d) describes a full tree, not a complete one).


**Q7.** Which is **not** an advantage/use of trees?

(a) undo/redo in a notepad (b) hierarchical structure (c) faster search (d) router algorithms

**✅ Answer: (a) undo/redo operations**

Undo/redo is done with a **stack** (last in, first out), not a tree. Trees are good for hierarchies (folders, organisation charts), fast searching (BSTs) and routing.
