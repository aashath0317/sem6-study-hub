1From pairs to n-tuples

n-tuple என்றால் என்ன?

(பெயர், வயது, பாடம்) போல ஒழுங்குடன் உள்ள n மதிப்புகளின் பதிவு n-tuple. Degree என்பது இடங்களின் எண்ணிக்கை; records எண்ணிக்கை அல்ல. வரிசை மாறினால் tuple-இன் பொருள் மாறலாம்.

Relationships often involve more than two things:

  • a patient's name, height and weight
  • a product's name, item number, manufacture date, expiry date and price
  • three integers in increasing order

These are especially common in database management systems.

The "sum to" relation 01:09

"Less than" is a set of pairs like (0, 1). But a relation can involve triples. The sum to relation S holds for (a, b, c) when a + b = c:

  • (2, 2, 4) ∈ S
  • (0, 1, 1) ∈ S
  • (5, −2.1, 2.9) ∈ S

S ⊆ ℝ × ℝ × ℝ. Within one relation, every tuple has the same length 02:27.

Definition 1

Let A₁, A₂, …, Aₙ be sets. An n-ary relation on these sets is a subset of A₁ × A₂ × ⋯ × Aₙ.

  • The sets A₁, …, Aₙ are the domains of the relation.
  • n is its degree.
  • The elements are ordered n-tuples (tuples).

The domains don't have to be the same set. A phone contact list relates names to phone numbers, a subset of Names × Numbers 03:00.

ஒரு record-ஐத் தனியாக அடையாளம் காணும் attribute Primary key. பல fields சேர்ந்தால் Composite key. Intension table அமைப்பு; Extension அப்போது இருக்கும் records. இரண்டையும் மாற்றிப் பொருள் கொள்ளாதீர்கள்.

Primary key

A key is an attribute or combination of attributes whose values uniquely identify a tuple. A primary key is a chosen candidate key; a domain (set of allowed values) is not itself the key.

Composite key

A combination of attributes whose values together identify each tuple uniquely. For a candidate key the combination is minimal; adding unnecessary fields gives a non-minimal superkey.

Term Meaning
Extension The current collection of tuples, which changes as records are added or deleted
Intension The permanent part: the database's name and attributes
Keys must survive change

Observed uniqueness in a sample is not enough to establish a schema key. New records may expose a bad choice; a declared key must remain unique across all permitted data states. So choose keys that work for all possible extensions, by looking at the intension.

  • The index number is a good key (no two students ever share one).
  • The name is a bad key (two students can share a name).

மாதிரியில் காணப்படும் தனித்துவம், திட்டவடிவச் சாவியை நிறுவப் போதாது. புதிய பதிவுகள் மோசமான தேர்வை வெளிப்படுத்தலாம்; அறிவிக்கப்பட்ட சாவி அனுமதிக்கப்பட்ட அனைத்துத் தரவு நிலைகளிலும் தனித்துவமாக இருக்க வேண்டும். எனவே உள்நோக்கத்தைப் பார்த்து சாத்தியமான அனைத்து விரிவுகளுக்கும் செயல்படும் சாவிகளைத் தேர்ந்தெடுக்கவும்.

  • சுட்டெண் நல்ல சாவி (எந்த இரு மாணவர்களும் ஒருபோதும் பகிர்வதில்லை).
  • பெயர் மோசமான சாவி (இரு மாணவர்களுக்கு ஒரே பெயர் இருக்கலாம்).

4Operations: selection, projection, join

வரிசை தேர்வு, நிரல் தேர்வு, இணைப்பு

Selection condition பொருந்தும் rows; Projection வேண்டிய columns; Join தொடர்புடைய tables இணைப்பு. மாணவர் table-ஐ marks table-உடன் Student ID மூலம் சேர்ப்பது Join.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Selection rows குறைக்கும்; degree வழக்கமாக மாறாது. Projection columns தேர்வு செய்யும்; duplicates set semantics-இல் நீங்கலாம். Join common fields பொருந்தும் tuples-ஐ இணைக்கும். Projection-இல் column order கேட்டபடி வைத்திருங்கள். Join key repeated என்றால் பல matching pairs உருவாகலாம்; ஒரு row மட்டும் கிடைக்கும் என்று ஊகிக்காதீர்கள்.

Lecturer/course schedulejoin common Department+Coursecode-இல் match செய்யவேண்டும்;ஒரு field மட்டும் match செய்தால் spurious combinations. SQL projection-இல் distinct behaviour வேறுபடலாம்.

Selection Sᴄ (Definition 2)

The selection operator Sᴄ maps a relation R to the relation of all tuples in R that satisfy condition C. It picks rows.

Example 10.3.1
  • C₁: Area = "Computer Science" → (Ackermann, 231455, Computer Science, 3.88) and (Chou, 102147, Computer Science, 3.49)
  • C₂: GPA > 3.5 → Ackermann and Rao
  • C₃: Area = "Computer Science" ∧ GPA > 3.5 → (Ackermann, 231455, Computer Science, 3.88) only

Projection Pi₁, i₂, …, iₘ (Definition 3)

The projection Pi₁,…,iₘ (with i₁ < i₂ < … < iₘ) maps (a₁, …, aₙ) to (ai₁, …, aiₘ). It keeps columns and deletes n − m of them.

Examples 10.3.2 and 10.3.3
  • P₁,₃ on (2, 3, 0, 4) gives (2, 0).
  • P₁,₃ on (Jane Doe, 234111001, Geography, 3.14) gives (Jane Doe, Geography).
  • P₁,₄ on Table 10.2.1 keeps Student_name and GPA (Table 10.3.1).
Projection can produce fewer rows (Example 10.3.4)

If tuples differ only in the deleted columns, they become identical after projection and merge into one. Table 10.3.2 has 8 rows (Glauser ×3, Marcus ×3, Miller ×2, one per course). P₁,₂ (Student, Area) gives only 3 rows: Glauser–Biology, Marcus–Mathematics, Miller–Computer Science.

Join

The join combines two tables on identical fields into one table.

Example 10.3.5: join Teaching_assignments (Lecturer, Department, Course_code) with Class_schedule (Department, Course_code, Venue, Time) on the common fields Department and Course_code. The result is Table 10.3.6 (Lecturer, Department, Course_code, Venue, Time).

வீழ்த்தல் Pi₁,…,iₘ (i₁ < i₂ < … < iₘ உடன்), (a₁, …, aₙ)-ஐ (ai₁, …, aiₘ)-க்குப் பொருத்துகிறது. நிரல்களைப் பேணி, அவற்றில் n − m-ஐ நீக்குகிறது.

Q1. A 3-ary relation on sets A, B, C is a subset of:

(a) A ∩ B ∩ C (b) A × B × C (c) A × C (d) A ∪ B ∪ C

✅ Answer: (b) A × B × C

An n-ary relation is a set of n-tuples. With 3 sets, each tuple is (a, b, c) → a subset of A × B × C. (Binary = 2-tuples = subset of A × B.)

Q2. Which is an n-ary relation?

(a) employee name, number, salary, contact number (c) school name, address, number of teachers, number of students (d) five integers in an arithmetic progression with difference 5 (b) all of the above

✅ Answer: all of the above

Each one links several values together in one tuple (4 values, 4 values, 5 values) → each is an n-ary relation. A row in a database table is exactly this.

Q3. R = {(a, b, c, d) | a, b, c, d positive integers with abcd = 6}. The domains are all _ and the degree is _.

(a) positive integers, 4 (b) the letters {a, b, c, d}, 4 (c) none (d) the integers, 4

✅ Answer: (a) the set of positive integers, 4

  • Domain = the set each position's values come from → positive integers (as the question says).
  • Degree = how many items in each tuple → (a, b, c, d) has 4. Example tuple: (1, 2, 3, 1).

Q4. Which is incorrect?

(a) A relational database consists of records which are n-tuples made of fields. (b) A database of records is a binary relation in the relational model. (c) Fields are the entries of the n-tuples. (d) The relational model is based on relations.

✅ Answer: (b)

Records usually have many fields (name, ID, major, GPA …), so a database is an n-ary relation, not binary (2 fields only).

Q5. True or false: relations used to represent databases are also called tables.

✅ Answer: True

Vocabulary match: relation = table, n-tuple = record / row, field = column.

Q6. A domain whose value uniquely determines the n-tuple is called:

(a) a primary key (b) an extension (c) an intension (d) a composite key

✅ Answer: (a) a primary key

  • Primary key: one field that identifies each record uniquely (e.g. Student ID).
  • Composite key: several fields together identify the record.

Q7. The extension of a relational database is:

(a) another word for primary key (b) none (c) the current collection of n-tuples in a relation (d) the more permanent part of a database

✅ Answer: (c) the current collection of n-tuples

  • Extension = the actual rows right now (it changes as data is added or deleted).
  • Intension = the permanent part: the table's name and its fields (the structure). Option (d) describes intension.

Q8. Which is not an operation on n-ary relations?

(a) projection (b) join (c) selection (d) multiplication

✅ Answer: (d) the multiplication operator

The operations are:

  • Selection σ: keep the rows that meet a condition.
  • Projection P: keep only some columns (and drop repeated rows).
  • Join J: combine two tables on matching fields. There is no “multiplication operator”.
