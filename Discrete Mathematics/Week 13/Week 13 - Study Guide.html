What is a decision tree?

A decision tree is a map of the possible outcomes of a series of related choices. It lets a person or organisation weigh possible actions against one another based on their costs, probabilities and benefits.

  • It uses a tree-like model of decisions: it starts at a single node that branches into possible outcomes, and each outcome leads to further nodes.
  • It can drive informal discussion or map out an algorithm that predicts the best choice mathematically.
  • A rooted tree is a tree in which one special node, the root, is singled out.
Should I buy a car? 01:44
  • Should I buy a car? → Do I have good public transport?
  • Yes → don't buy
  • No → buy
  • If I decide not to buy → Do I often travel outside my city?
  • Yes → consider buying
  • No → don't buy

The tree starts at one node (the question), branches into outcomes (yes / no), and each outcome leads to further nodes.

Definition 1

A rooted tree in which each internal vertex corresponds to a decision, with a subtree at these vertices for each possible outcome of the decision, is called a decision tree.

Drawing your own decision tree

Symbol Means
Square ■ A decision to be made
Circle ● An uncertain outcome (chance)
Nothing / triangle ▲ A final result
  1. Draw the decision as a small square on the left
  1. Draw one line per option to the right and label it
  1. At each line's end: another decision → square; uncertain → circle; result → nothing
  1. From squares draw the choices; from circles draw the possible outcomes
  1. Keep going until every path ends in a result

Evaluating a decision tree

  1. Estimate the value of each final outcome.
  2. At each circle, assign a probability to each outcome. They must add up to 100% (or 1).
  3. Calculate: multiply each end value by its probability and add them up at each circle. Subtract any costs along the way to get the net value.
  4. Choose the option with the highest value.

Advantages and disadvantages

Advantages Disadvantages
Classify without much computation Error-prone with many classes and few training examples
Handle both continuous and categorical variables Computationally expensive to train (growing the tree is costly)
Clearly show which fields matter most for prediction

The lecture adds more 05:23:

More advantages

  1. Easy to understand, even for people from non-analytical backgrounds
  2. Useful in data exploration: one of the fastest ways to find the most significant variables and relations between them
  3. Less effort needed from users for data preparation
  4. May need less scaling, but still requires data-quality checks and suitable handling of missing or inconsistent values
  5. Numeric and categorical features can be modelled, but implementation-specific encoding and input restrictions still matter
  6. Non-parametric: no assumptions about the space distribution or classifier structure
  7. Can model non-linear relationships, but performance still depends on the data, tree size, representation and training procedure

More disadvantages 06:38

  1. Overfitting: over-complex trees that don't generalise well
  2. Unstable: small variations in the data can produce a completely different tree
  3. Calculations get complex with many class labels

When to use a decision tree 07:14:

  1. The decision maker has an objective (e.g. maximise profit, optimise cost)
  2. There are several courses of action
  3. There's a calculable measure of benefit for the alternatives
  4. There are events beyond the decision maker's control (e.g. environmental factors)
  5. There's uncertainty about which outcome will actually happen

Application areas: medicine, planning, pharmacology, molecular biology, astronomy, biomedical engineering, production and manufacturing.

Example 13.1: play badminton?

To decide whether to play on Saturday, you record temperature, wind, humidity and outlook (sunny, cloudy, rainy) for the last ten days in a lookup table.

  • Problem: Saturday's weather might not match any row of the table.
  • A decision tree solves this. It considers every path to the final decision.
  • Each node is an attribute, each branch is an outcome of that attribute, and each leaf is the final decision (play / don't play).
The badminton tree 08:49
  • Outlook = sunny → depends on humidity: high → don't play; normal → play
  • Outlook = cloudy → play (no other variable matters)
  • Outlook = rainy → depends on wind: strong → don't play; weak → play

Temperature never matters in this tree.

Tree traversal is a form of graph traversal: visiting each node of a tree exactly once 03:43. Ordered rooted trees store information and can represent expressions (numbers, variables, operations). To use the data, we need procedures that visit every vertex: traversal algorithms. Both are defined recursively.

Preorder: root first

Visit the root r, then traverse T₁ in preorder, then T₂, … then Tₙ (subtrees left to right).

Postorder: root last

Traverse T₁ in postorder, then T₂, … then Tₙ, and finally visit the root r.

Definition 2 (postorder)

Let T be an ordered rooted tree with root r. If T is only r, then r is the postorder traversal. Otherwise, with subtrees T₁, …, Tₙ from left to right, the postorder traversal traverses T₁ … Tₙ in postorder and ends by visiting r.

Definition

Let G be a simple graph. A spanning tree of G is a subgraph of G that is a tree containing every vertex of G.

Finding one: remove edges from circuits

Example 13.3.1

G is connected but not a tree, because it has simple circuits.

  1. Remove {a, e}: one circuit is gone, and G stays connected with every vertex.
  2. Remove {e, f}: a second circuit is gone.
  3. Remove {c, g}: no simple circuits are left.

The result is a spanning tree of G.

Theorem 1

A simple graph is connected if and only if it has a spanning tree.

A tree with n vertices has n − 1 edges, so from a connected graph with n vertices and m edges you must remove m − (n − 1) = m − n + 1 edges to get a spanning tree.

Application: IP multicasting (Example 13.3.2)

Unicasting

Send a separate copy to each receiving computer. Inefficient: many copies of the same data cross the network.

IP multicasting

Use a loop-free delivery tree to the participating receivers, branching copies where needed. This need not span every device in the whole physical network.

  • Data must never loop: once it reaches a router it should never return there. Loops are circuits, so the routers build a spanning tree.
  • Vertices: the multicast source, the routers, and the subnetworks with receiving computers.
  • Edges: the links between computers and/or routers.
  • Root: the multicast source.
  • Leaves: the subnetworks containing receiving computers.
Exam focus
  • Decision tree: draw it with squares and circles, show probability × value at each chance node, subtract costs, and give a clear recommendation.
  • Traversal: write the full vertex list, and check that every vertex appears exactly once.
  • Spanning tree: remove one edge from each circuit; a tree with n vertices has n − 1 edges.
