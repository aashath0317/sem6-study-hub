1Why not just use Apriori?

Apriori-இன் செலவு

பல candidates உருவாகி database-ஐ மீண்டும் மீண்டும் scan செய்ய வேண்டியிருக்கும். பெரிய data-வில் இது மெதுவாகலாம். Candidate generation-ஐத் தவிர்க்கும் FP-growth ஒரு மாற்று.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

10,000 frequent items→candidate pairs 10000×9999/2=49,995,000; repeated DB scans மற்ற செலவு. FP-growth first scan supports, second tree build; recursion conditional structures-இல் நடக்கும். “இரண்டு scans” என்பதால் total computation இரண்டு operations மட்டுமே என்று பொருள் அல்ல; output மிகப் பெரியதாக இருந்தால் எந்த algorithm-க்கும் செலவு அதிகம்.

Apriori's candidate generate-and-test shrinks the candidate sets a lot, but it still has two non-trivial costs:

1. Huge candidate sets

With 10⁴ frequent 1-itemsets, Apriori must generate more than 10⁷ candidate 2-itemsets. That's 10⁴ × (10⁴ − 1)/2 ≈ 5 × 10⁷.

2. Repeated database scans

It scans the database again at every level and checks many candidates by pattern matching. Going over every transaction to count support is costly.

FP-growth's answer

No candidate generation, and only two database scans 00:02. The video stresses that this is why computation time drops.

2FP-growth: the idea

FP-growth மையக் கருத்து

Frequent items-ஐ ஒரே வரிசையில் அமைத்து common transaction prefixes-ஐ FP-tree-இல் பகிர்வோம். சுருக்கமான tree-இல் conditional patterns தேடுவதால் candidates அனைத்தையும் முன்பே உருவாக்க வேண்டியதில்லை.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

FP-tree build: முதலில் count செய்து infrequent items நீக்கு; frequent items descending support order அமை; ஒவ்வொரு transaction-ஐ அதே order-இல் insert செய்து shared-prefix counts உயர்த்து. Header links ஒரே item-இன் nodes-ஐ இணைக்கும். Branch count அந்த prefix-க்கு உரியது; ஒரே item பல branches-இல் வந்தால் அதன் total count-ஐ header links வழியாகச் சேர்த்து பார்க்க வேண்டும்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Frequent items மட்டும் வைத்து global descending-support order; ties-க்கு consistent rule. Root null; common prefix counts increment; வேறு suffix new branch. Header table node-links ஒரே item occurrences-ஐ இணைக்கும். Tree node count அந்த path-இல் அந்த node-ஐக் கடக்கும் transactions; ஒரு item-இன் total support அதன் nodes counts கூட்டுத்தொகை.

Frequent-pattern growth (FP-growth) uses a divide-and-conquer strategy:

  1. Compress the database of frequent items into a frequent-pattern tree (FP-tree). The tree keeps the itemset association information.
  2. Divide the compressed database into conditional databases (a kind of projected database), each linked to one frequent item or "pattern fragment".
  3. Mine each conditional database separately.

The three steps of building the tree 00:37

Scan 1: count supports → frequent 1-itemsetsDrop infrequent items & sort each transaction by descending supportScan 2: insert each transaction as a path from the root

How a transaction is inserted:

  • Create a root labelled null.
  • Process the items of each transaction in L order (descending support).
  • If the transaction shares a prefix with an existing path, increment the count of each node along the shared prefix by 1.
  • Create new nodes only for the items after the shared prefix.
  • Keep an item header table: each item points to its occurrences in the tree through a chain of node-links.

The problem of mining the database becomes the problem of mining the FP-tree.

3Worked example (min_sup = 3)

FP-tree எடுத்துக்காட்டு

முதலில் counts, பின்னர் frequent items மட்டும் வைத்த ordered transactions உருவாக்குங்கள். பொதுவான பாதையைப் பகிர்ந்து count உயர்த்துங்கள். Tree-இன் ஒரு node count அந்த prefix வழியாக வந்த transactions எண்ணிக்கை.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

4Mining the FP-tree

FP-tree-ஐ Mine செய்வது

ஒரு item-க்கு முன் உள்ள prefix paths அதன் Conditional pattern base. அதிலிருந்து சிறிய conditional tree செய்து தேடலைத் தொடர்வோம். Path count-ஐ ஒருமுறை மட்டும் கணக்கிடுவது முக்கியம்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

ஒரு suffix item-ஐத் தேர்வு செய்து அதன் எல்லா prefix paths-ஐ suffix node count-உடன் எடுங்கள். இதுவே Conditional pattern base. Weighted counts மூலம் conditional FP-tree உருவாக்கி recursion தொடரும். Path-இல் suffix-ஐ மீண்டும் சேர்த்து இருமுறை எண்ணாதீர்கள். ஒரு single path மட்டுமே இருந்தால் அதிலிருந்து combinations எளிதாக உருவாகலாம்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Suffix p: prefixes f,c,a,m:2 மற்றும் c,b:1. Totals c3, f/a/m2,b1→conditional tree c3→pattern{c,p}:3. Suffix m: f,c,a:2 மற்றும் f,c,a,b:1→f/c/a3,b1; f,c,a subsets-உடன் m சேர்த்து frequent patterns. Prefix counts weighted; path-ஐ ஒருமுறை எண்ணுவது மட்டும் போதாது. Recursively suffix சேர்த்துச் செல்லுங்கள்.

For each frequent item, starting from the least frequent (bottom of L) as the suffix:

  1. Build its conditional pattern base: the set of prefix paths in the tree that end just before the suffix, each with the suffix's count.
  2. Build the conditional FP-tree from that base, keeping only items whose total count ≥ min_sup.
  3. Mine it recursively. Patterns grow by concatenating the suffix with the patterns found in the conditional tree.
Item Conditional pattern base Conditional FP-tree Frequent patterns generated
p {f,c,a,m : 2}, ⟨c:3⟩ {c,p : 3}
m {f,c,a : 2}, ⟨f:3, c:3, a:3⟩ {f,m}, {c,m}, {a,m}, {f,c,m}, {f,a,m}, {c,a,m}, {f,c,a,m} : 3
b {f,c,a : 1}, {f : 1}, {c : 1} ∅ (no item reaches 3) —
a {f,c : 3} ⟨f:3, c:3⟩ {f,a}, {c,a}, {f,c,a} : 3
c {f : 3} ⟨f:3⟩ {f,c} : 3
f ∅ — —
Reading the p row

p sits at the end of two paths: f-c-a-m-p (count 2) and c-b-p (count 1). The prefixes are {f,c,a,m}:2 and {c,b}:1. Totals: c = 2 + 1 = 3 ✓, while f, a, m = 2 and b = 1 ✗. So the conditional tree is just ⟨c:3⟩ and the pattern is {c, p}: 3.

🧪 Try it — FP-tree builder & miner
Why it's faster
  • FP-growth turns finding long patterns into recursively finding short ones and concatenating the suffix.
  • Using the least frequent items as suffixes gives good selectivity.
  • It's efficient and scalable for both long and short patterns, and can outperform Apriori on suitable data; there is no fixed speedup guarantee across datasets and implementations.
  • If the tree doesn't fit in memory, partition the DB into projected databases and build an FP-tree for each, recursively if needed.
Exam focus

FP-tree questions ask you to:

  1. Find the supports and drop infrequent items.
  2. Re-order each transaction.
  3. Draw the tree with counts.
  4. Make the conditional pattern base / conditional FP-tree / frequent patterns table.

Practise with the builder above. Change min_sup or paste the lecture's fruit/vegetable dataset.

5Multilevel association rules

பல நிலை விதிகள்

பால் → பாண் என்ற பொதுவிதியும் skimmed milk → brown bread என்ற நுணுக்க விதியும் வெவ்வேறு levels. Multilevel mining concept hierarchy-ஐப் பயன்படுத்தும். நுணுக்க நிலைகளுக்கு support குறையலாம்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Uniform support: எல்லா abstraction levels-க்கும் ஒரே threshold. Reduced support: கீழ்நிலை specific items-க்கு குறைந்த threshold. “Milk” பல brands சேர்வதால் support உயரலாம்; குறிப்பிட்ட milk brand-க்கு அதே threshold அதிகமாக இருக்கலாம். Hierarchy-யில் parent-child தொடர்பைத் தெளிவாக வைத்துக் கொண்டு எந்த level-இன் rule என்று குறிப்பிடுங்கள்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Concept hierarchy computer→laptop/desktop. Uniform min5%: computer10,laptop6 pass,desktop4 fail. Reduced lower-level min3% என்றால் desktop-உம் pass. High level common-sense patterns; low level sparse patterns. Lowered threshold காரணமாக parent fail என்ற alone அடிப்படையில் எல்லா deeper cases-ஐ prune செய்யலாமா என்பதை threshold scheme-உடன் பார்க்கவேண்டும்.

  • At low (primitive) levels, data is sparse, so strong associations are hard to find.
  • Strong associations at high levels may just be common sense, but what is common sense to one user may be novel to another.
  • So the system should mine at multiple levels of abstraction using concept hierarchies:
                       all
        ┌───────┬──────┼───────┬─────────────┐
    computer  software printer  computer accessory
     ┌──┴──┐     …       …            …
  laptop desktop
  • Rules mined at multiple levels are multilevel association rules.
  • They're mined under a support-confidence framework with a top-down strategy: count frequent itemsets at level 1, then go down level by level until no more frequent itemsets are found. Any algorithm (e.g. Apriori) works at each level.
Approach Thresholds Example (computer 10%, laptop 6%, desktop 4%)
Uniform support Same min_sup at every level min_sup 5%: computer ✓, laptop ✓, desktop ✗
Reduced support Smaller min_sup at deeper levels Level 1 = 5%, level 2 = 3%: computer ✓, laptop ✓, desktop ✓
Trade-off

Uniform support is simple, but if it's too high you miss meaningful low-level associations, and if it's too low you get too many uninteresting high-level ones. Reduced support fixes this by being more lenient at the specific levels.

6Multidimensional association rules

பல Dimension விதிகள்

Age, income, buys போன்ற பல attributes ஒன்றாக ஒரு விதியில் வந்தால் Multidimensional association. Basket items மட்டும் தேடுவதிலிருந்து இது விரிவானது. ஒவ்வொரு attribute value-யும் தெளிவாக வரையறுக்கப்பட வேண்டும்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Single-dimensional: buys(A)→buys(B), ஒரே predicate. Interdimensional: age(20–29) ∧ income(high) → buys(laptop), predicate மீண்டும் வராது. Hybrid-dimensional: மற்ற attributes-உடன் buys போன்ற predicate மீண்டும் வரலாம். Numeric attributes-ஐ intervals-ஆக discretise செய்தால் boundaries rule-இன் பொருளை மாற்றும்; அவற்றைச் சொல்ல வேண்டும்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Predicate பெயர் எண்ணுங்கள்: buys(camera)⇒buys(printer) ஒரே buys repeated→single-dimensional. age∧occupation⇒buys:பல predicates, repeats இல்லை→interdimensional. age∧buys(laptop)⇒buys(printer):பல predicates, buys repeat→hybrid. Multilevel என்பது concept hierarchy depth; multidimensional என்பது predicates/dimensions; இரண்டும் ஒரே வேறுபாடு அல்ல.

Each distinct predicate in a rule is a dimension.

Type Predicates Example
Single-dimensional (intradimensional) One predicate, repeated buys(X, "digital camera") ⇒ buys(X, "HP printer")
Interdimensional Two or more, no repeats age(X, "20…29") ∧ occupation(X, "student") ⇒ buys(X, "laptop")
Hybrid-dimensional Two or more, with a repeated predicate age(X, "20…29") ∧ buys(X, "laptop") ⇒ buys(X, "HP printer")
Quick test

Count the distinct predicate names. One → single-dimensional. More than one with no repeats → interdimensional. More than one with a repeat → hybrid.

7Constraint-based association mining

Constraints கொண்டு தேடுதல்

பயனர் விரும்பும் விலை வரம்பு, item வகை போன்ற கட்டுப்பாடுகள் தேடலைக் குறைக்கும். முதலில் constraints-ஐப் பயன்படுத்தினால் பயனற்ற patterns-ஐ உருவாக்கும் செலவு குறையலாம்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

ஐந்து constraints: knowledge type(association/correlation); data(Colombo2025); dimension/level(brand+age); interestingness(support/confidence); rule form(metarule/RHS/predicate count). Search-இலேயே constraints பயன்படுத்தினால் தேவையற்ற output குறையலாம். Template மட்டுமே useful/correct என்று நிரூபிக்காது; support/confidence மற்றும் task relevance சோதிக்கவும்.

  • Mining can produce thousands of rules, most uninteresting.
  • Users often know the "direction" and "form" of what they want, so they specify constraints to confine the search space. This is constraint-based mining.
Constraint Specifies Example
Knowledge type Type of knowledge Association or correlation
Data Task-relevant data Sales in Colombo, 2025
Dimension/level Which dimensions or hierarchy levels Use item at "brand" level, plus age
Interestingness Thresholds on statistical measures support ≥ 5%, confidence ≥ 70%, correlation
Rule Form of rules: metarules (templates), max/min predicates on each side, relationships among attributes or aggregates P(X, Y) ∧ Q(X, W) ⇒ buys(X, "laptop")

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Frequent items மட்டும் வைத்து global descending-support order; ties-க்கு consistent rule. Root null; common prefix counts increment; வேறு suffix new branch. Header table node-links ஒரே item occurrences-ஐ இணைக்கும். Tree node count அந்த path-இல் அந்த node-ஐக் கடக்கும் transactions; ஒரு item-இன் total support அதன் nodes counts கூட்டுத்தொகை.

FP-tree எடுத்துக்காட்டு

முதலில் counts, பின்னர் frequent items மட்டும் வைத்த ordered transactions உருவாக்குங்கள். பொதுவான பாதையைப் பகிர்ந்து count உயர்த்துங்கள். Tree-இன் ஒரு node count அந்த prefix வழியாக வந்த transactions எண்ணிக்கை.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Five-transaction example min3: f4,c4,a3,b3,m3,p3; order f,c,a,b,m,p. T100 f-c-a-m-p;T200 f-c-a-b-m;T300 f-b;T400 c-b-p;T500 f-c-a-m-p. Final shared f-c-a path count3; அதன் m branch2,p2; b branch1,m1. Root f4 மற்றும் c1. Fruit/vegetable video example வேறு dataset; அதன் supports-ஐ இதில் கலக்காதீர்கள்.

FP-tree-ஐ Mine செய்வது

ஒரு item-க்கு முன் உள்ள prefix paths அதன் Conditional pattern base. அதிலிருந்து சிறிய conditional tree செய்து தேடலைத் தொடர்வோம். Path count-ஐ ஒருமுறை மட்டும் கணக்கிடுவது முக்கியம்.

ஒரு suffix item-ஐத் தேர்வு செய்து அதன் எல்லா prefix paths-ஐ suffix node count-உடன் எடுங்கள். இதுவே Conditional pattern base. Weighted counts மூலம் conditional FP-tree உருவாக்கி recursion தொடரும். Path-இல் suffix-ஐ மீண்டும் சேர்த்து இருமுறை எண்ணாதீர்கள். ஒரு single path மட்டுமே இருந்தால் அதிலிருந்து combinations எளிதாக உருவாகலாம்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Suffix p: prefixes f,c,a,m:2 மற்றும் c,b:1. Totals c3, f/a/m2,b1→conditional tree c3→pattern{c,p}:3. Suffix m: f,c,a:2 மற்றும் f,c,a,b:1→f/c/a3,b1; f,c,a subsets-உடன் m சேர்த்து frequent patterns. Prefix counts weighted; path-ஐ ஒருமுறை எண்ணுவது மட்டும் போதாது. Recursively suffix சேர்த்துச் செல்லுங்கள்.

பல நிலை விதிகள்

பால் → பாண் என்ற பொதுவிதியும் skimmed milk → brown bread என்ற நுணுக்க விதியும் வெவ்வேறு levels. Multilevel mining concept hierarchy-ஐப் பயன்படுத்தும். நுணுக்க நிலைகளுக்கு support குறையலாம்.

Uniform support: எல்லா abstraction levels-க்கும் ஒரே threshold. Reduced support: கீழ்நிலை specific items-க்கு குறைந்த threshold. “Milk” பல brands சேர்வதால் support உயரலாம்; குறிப்பிட்ட milk brand-க்கு அதே threshold அதிகமாக இருக்கலாம். Hierarchy-யில் parent-child தொடர்பைத் தெளிவாக வைத்துக் கொண்டு எந்த level-இன் rule என்று குறிப்பிடுங்கள்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Concept hierarchy computer→laptop/desktop. Uniform min5%: computer10,laptop6 pass,desktop4 fail. Reduced lower-level min3% என்றால் desktop-உம் pass. High level common-sense patterns; low level sparse patterns. Lowered threshold காரணமாக parent fail என்ற alone அடிப்படையில் எல்லா deeper cases-ஐ prune செய்யலாமா என்பதை threshold scheme-உடன் பார்க்கவேண்டும்.

பல Dimension விதிகள்

Age, income, buys போன்ற பல attributes ஒன்றாக ஒரு விதியில் வந்தால் Multidimensional association. Basket items மட்டும் தேடுவதிலிருந்து இது விரிவானது. ஒவ்வொரு attribute value-யும் தெளிவாக வரையறுக்கப்பட வேண்டும்.

Single-dimensional: buys(A)→buys(B), ஒரே predicate. Interdimensional: age(20–29) ∧ income(high) → buys(laptop), predicate மீண்டும் வராது. Hybrid-dimensional: மற்ற attributes-உடன் buys போன்ற predicate மீண்டும் வரலாம். Numeric attributes-ஐ intervals-ஆக discretise செய்தால் boundaries rule-இன் பொருளை மாற்றும்; அவற்றைச் சொல்ல வேண்டும்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Predicate பெயர் எண்ணுங்கள்: buys(camera)⇒buys(printer) ஒரே buys repeated→single-dimensional. age∧occupation⇒buys:பல predicates, repeats இல்லை→interdimensional. age∧buys(laptop)⇒buys(printer):பல predicates, buys repeat→hybrid. Multilevel என்பது concept hierarchy depth; multidimensional என்பது predicates/dimensions; இரண்டும் ஒரே வேறுபாடு அல்ல.

Constraints கொண்டு தேடுதல்

பயனர் விரும்பும் விலை வரம்பு, item வகை போன்ற கட்டுப்பாடுகள் தேடலைக் குறைக்கும். முதலில் constraints-ஐப் பயன்படுத்தினால் பயனற்ற patterns-ஐ உருவாக்கும் செலவு குறையலாம்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

ஐந்து constraints: knowledge type(association/correlation); data(Colombo2025); dimension/level(brand+age); interestingness(support/confidence); rule form(metarule/RHS/predicate count). Search-இலேயே constraints பயன்படுத்தினால் தேவையற்ற output குறையலாம். Template மட்டுமே useful/correct என்று நிரூபிக்காது; support/confidence மற்றும் task relevance சோதிக்கவும்.
