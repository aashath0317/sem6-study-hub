## கிடங்குகளுக்கு ஏன் வேறு திட்டவடிவம்?

- **தொடர்புநிலைத் தரவுத்தளங்கள்** (OLTP), **உருப்பொருள்-உறவு (ER) மாதிரியால்** வடிவமைக்கப்படுகின்றன: உருப்பொருட்களின் தொகுப்பும் அவற்றுக்கிடையிலான உறவுகளும்.
- **தரவுக் கிடங்குக்கு**, **நிகழ்நிலைத் தரவுப் பகுப்பாய்வை** ஆதரிக்கும் **சுருக்கமான, பொருள் நோக்கிய திட்டவடிவம்** தேவை.
- கிடங்குக்கு மிகவும் பிரபலமானது **பல்பரிமாண மாதிரி**. அது மூன்று வடிவங்களில் வருகிறது:

:::flow
நட்சத்திரத் திட்டவடிவம்
பனித்துகள் திட்டவடிவம்
உண்மை விண்மீன்கூட்டம்
:::

மூன்றிலும் **உண்மை அட்டவணையும்** (அளவைகளையும் பரிமாணங்களுக்கான சாவிகளையும் கொண்டது) **பரிமாண அட்டவணைகளும்** (ஒவ்வொரு பரிமாணத்தையும் விவரிப்பவை) உள்ளன.

## நட்சத்திரத் திட்டவடிவம்

**ஒவ்வொரு பரிமாணத்துக்கும் ஓர் அட்டவணையுடன் இணைக்கப்பட்ட மைய உண்மை அட்டவணை.** இதுவே **மிக எளிய** திட்டவடிவம்.

- **எடுத்துக்காட்டு (படம் 6-1):** **sales** உண்மை அட்டவணையில் **time, item, branch, location** ஆகியவற்றுக்கான சாவிகளும் **dollars_sold**, **units_sold** என்ற இரு அளவைகளும் உள்ளன.
- **ஒவ்வொரு பரிமாணமும் துல்லியமாக ஓர் அட்டவணை.**

:::warn குறைபாடு: மிகைமை
location அட்டவணையில் (location_key, street, city, province_or_state, country) உள்ளன. Vancouver, Victoria இரண்டும் கனடாவின் British Columbia-வில் உள்ளதால், "British Columbia, Canada" பல வரிசைகளில் **மீண்டும் வருகிறது**:

(…, Vancouver, British Columbia, Canada)
(…, Victoria, British Columbia, Canada)
:::

## பனித்துகள் திட்டவடிவம்

**பரிமாண அட்டவணைகள் இயல்பாக்கப்பட்ட நட்சத்திரத் திட்டவடிவம்** (கூடுதல் அட்டவணைகளாகப் பிரிக்கப்பட்டவை). வரைபடம் **பனித்துகள்** போன்று கிளைக்கிறது.

- **எடுத்துக்காட்டு (படம் 6-2):**
  - **item** → item(item_key, item_name, brand, type, **supplier_key**) + **supplier**(supplier_key, supplier_type)
  - **location** → location(location_key, street, **city_key**) + **city**(city_key, city, province_or_state, country)

:::grid
**நன்மைகள்**

- **மிகைமையைக் குறைக்கிறது** (இயல்பாக்கப்பட்டது)
- **பராமரிக்க எளிது**
- **சேமிப்பிடத்தைச் சேமிக்கிறது**
+++
**தீமைகள்**

- உண்மை அட்டவணையின் அளவுடன் ஒப்பிடும்போது சேமிக்கப்படும் இடம் **மிகச்சிறியது**
- ஒவ்வொரு வினவலுக்கும் **அதிக இணைப்புகள்** தேவை; எனவே **உலாவல் குறைந்த திறனுடையது** (மெதுவானது)
:::

:::tip எது அதிகம் பிரபலமானது?
சிறிய சேமிப்பு மிச்சத்தைவிட வினவல் வேகம் முக்கியமானதால், பனித்துகளைக் காட்டிலும் **நட்சத்திரத் திட்டவடிவம்** அதிகம் பிரபலமானது.
:::

## உண்மை விண்மீன்கூட்டம் (விண்மீன்பேரடைத் திட்டவடிவம்)

**பரிமாண அட்டவணைகளைப் பகிரும் பல உண்மை அட்டவணைகள்.** இது நட்சத்திரங்களின் தொகுப்பாக இருப்பதால் **விண்மீன்பேரடைத் திட்டவடிவம்** என்றும் அழைக்கப்படுகிறது.

**எடுத்துக்காட்டு (படம் 6-3):** இரு உண்மை அட்டவணைகள்.

| உண்மை அட்டவணை | சாவிகள் (பரிமாணங்கள்) | அளவைகள் |
|---|---|---|
| **sales** | time, item, branch, location | dollars_sold, units_sold |
| **shipping** | item, time, **shipper**, **from_location**, **to_location** | dollars_cost, units_shipped |

இரு உண்மை அட்டவணைகளும் **time, item, location** ஆகியவற்றைப் **பகிர்கின்றன**.

{{tool:sch}}

:::exam
வரைபடங்களுடன் "நட்சத்திரம், பனித்துகள், உண்மை விண்மீன்கூட்டத் திட்டவடிவங்களை ஒப்பிடுக" என்பது விருப்பமான கேள்வி. ஒவ்வொன்றுக்கும் **sales** எடுத்துக்காட்டை வரையவும். பனித்துகளில் **item → supplier**, **location → city** ஆகியவற்றைக் காட்டவும். விண்மீன்கூட்டத்தில் **sales + shipping, time/item/location-ஐப் பகிர்வதைக்** காட்டவும்.
:::

## தரவுக் கிடங்கும் தரவுச் சந்தையும்

| | **தரவுக் கிடங்கு** | **தரவுச் சந்தை** |
|---|---|---|
| **நோக்கெல்லை** | **நிறுவனம் முழுவதும்**: முழு நிறுவனத்திலும் உள்ள பொருள்கள் (வாடிக்கையாளர்கள், பொருட்கள், விற்பனை, சொத்துகள், பணியாளர்கள்) | **துறை/செயல்முறையை மையமாகக் கொண்டது**: கிடங்கைச் சார்ந்த உட்கணமாகவோ சுயாதீனச் சந்தையாகவோ இருக்கலாம் |
| **பொருள்கள்** | பல, ஒன்றோடொன்று தொடர்புடையவை | **தேர்ந்தெடுக்கப்பட்ட / ஒற்றைப்** பொருள்கள் |
| **பொதுவாகப் பயன்படும் திட்டவடிவம்** | **உண்மை விண்மீன்கூட்டம்** (பல தொடர்புடைய பொருள்களை மாதிரியாக்குகிறது) | **நட்சத்திரம்** அல்லது **பனித்துகள்** (ஒரு பொருள்); **நட்சத்திரம் அதிகம் பிரபலமானதும் திறனுடையதும்** |
| **தரவு மூலங்கள்** | பல | சில |
| **அளவு** | பெரியது (100 GB – TB+) | சிறியது |
| **உருவாக்க நேரம்** | மாதங்கள் முதல் ஆண்டுகள் வரை | வாரங்கள் முதல் மாதங்கள் வரை |

:::tip கற்பனை செய்து பாருங்கள்
கிடங்கு என்பது பேரங்காடிச் சங்கிலியின் **மையச் சேமிப்பகம்**. தரவுச் சந்தை என்பது தேவையான பொருள்களை மட்டும் கொண்ட **சந்தைப்படுத்தல் துறையின் அலமாரி**.
:::

## DMQL-ஆல் கனசதுரங்களை வரையறுத்தல்

SQL தொடர்புநிலை வினவல்களைக் குறிப்பிடுவதுபோல, **தரவுச் சுரங்க வினவல் மொழி (DMQL)** சுரங்கப் பணிகளைக் குறிப்பிடுகிறது. கிடங்குகளும் சந்தைகளும் **இரு அடிப்படைக் கூறுகளால்** வரையறுக்கப்படுகின்றன:

```
define cube <cube_name> [<dimension_list>]: <measure_list>
define dimension <dimension_name> as (<attribute_or_subdimension_list>)
```

### DMQL-இல் நட்சத்திரத் திட்டவடிவம்
```
define cube sales_star [time, item, branch, location]:
    dollars_sold = sum(sales_in_dollars), avg_sales = avg(sales_in_dollars),
    units_sold = count(*)
define dimension time     as (time_key, day, day_of_week, month, quarter, year)
define dimension item     as (item_key, item_name, brand, type, supplier_type)
define dimension branch   as (branch_key, branch_name, branch_type)
define dimension location as (location_key, street, city, province_or_state, country)
```
இந்தப் பாடத்தின் DMQL குறியீட்டில் **define cube**, மையக் கனசதுர/உண்மை மாதிரியைக் குறிப்பிடுகிறது (4 பரிமாணங்களும் அளவைகளும்). இது பிற முறைமைகளில் அப்படியே பயன்படும் SQL தொடரமைப்பு அல்ல. **count(*) வரிசைகளை எண்ணுகிறது**; ஒரு வரிசைக்கு ஓர் அலகு என்ற நுணுக்கநிலை இருந்தாலன்றி பொருள் அளவுகளை அல்ல. ஒவ்வொரு **define dimension**-உம் ஒரு பரிமாண அட்டவணையை உருவாக்குகிறது.

### DMQL-இல் பனித்துகள் திட்டவடிவம்
மாற்றம் ஒன்றே: பெற்றோர் பரிமாணத்துக்குள் **துணைப் பரிமாணங்கள் உள்ளடக்கப்படுகின்றன**:
```
define dimension item as (item_key, item_name, brand, type,
                          supplier(supplier_key, supplier_type))
define dimension location as (location_key, street,
                          city(city_key, province_or_state, country))
```
**item-க்குள் supplier-ஐ** வரையறுப்பது item அட்டவணையில் **supplier_key-ஐ மறைமுகமாக உருவாக்குகிறது**. **location-க்குள் city** என்பது **city_key-ஐ** மறைமுகமாக உருவாக்குகிறது.

### DMQL-இல் உண்மை விண்மீன்கூட்டம்
நட்சத்திரத் திட்டவடிவத்தைப் போல **sales** கனசதுரத்தை வரையறுத்து, பின்னர் **shipping**-ஐ வரையறுத்துப் பகிரப்பட்ட பரிமாணங்களை **மீண்டும் பயன்படுத்தவும்**:
```
define cube shipping [time, item, shipper, from_location, to_location]:
    dollar_cost = sum(cost_in_dollars), unit_shipped = count(*)
define dimension time  as time in cube sales
define dimension item  as item in cube sales
define dimension shipper as (shipper_key, shipper_name,
                             location as location in cube sales, shipper_type)
define dimension from_location as location in cube sales
define dimension to_location   as location in cube sales
```
**"as … in cube sales"** மூலமே உண்மை அட்டவணைகளுக்கிடையே பரிமாணம் **பகிரப்படுகிறது**.

:::key வேறுபாட்டை விரைவாகக் கண்டறியவும்
- **நட்சத்திரம்:** தட்டையான பண்புக்கூறுப் பட்டியல்கள்
- **பனித்துகள்:** உள்ளடக்கப்பட்ட அடைப்புக்குறிகள், `supplier(…)`, `city(…)`
- **விண்மீன்கூட்டம்:** இரு `define cube` கூற்றுகளும் `… in cube sales` என்பதும்
:::

## கருத்துப் படிநிலைகள்

**கருத்துப் படிநிலை** என்பது **கீழ்நிலைக் கருத்துகளிலிருந்து உயர்நிலையான, மேலும் பொதுவான கருத்துகளுக்கான பொருத்துதல்களின் தொடர்**.

:::example இடப் படிநிலை (படம் 6-4)
```
                        all
              ┌──────────┴──────────┐
           Canada                  USA
       ┌──────┴──────┐        ┌─────┴──────┐
 British Columbia  Ontario  New York    Illinois
       │              │        │            │
   Vancouver      Toronto   New York     Chicago
```
நகரம் → மாகாணம்_அல்லது_மாநிலம் → நாடு → அனைத்தும்
:::

- **பல படிநிலைகள் திட்டவடிவத்தில் மறைமுகமாக உள்ளன.** location-க்கு number, street, city, province_or_state, zip_code, country ஆகிய பண்புக்கூறுகள் இருந்தால், **முழுமையான வரிசை** தருவது: **street < city < province_or_state < country** (படம் 6-5).
- **மேல்சுருக்கம்** படிநிலையில் ஏறுகிறது (நகரம் → நாடு). **கீழ்விரிப்பு** மீண்டும் கீழே செல்கிறது.

## Weka 1.2 — Explorer-ஐ ஆராய்தல்

நீங்கள் பயன்படுத்தும் முக்கிய இடைமுகமான **Explorer**-ஐ Weka காணொளி சுற்றிக்காட்டுகிறது:

- **Preprocess** தாவல்: **தரவுத்தொகுப்பைத் திறக்கவும்** (ARFF கோப்பு); **பண்புக்கூறுகளின்** பட்டியல், **நிகழ்வுகளின் எண்ணிக்கை**, ஒவ்வொரு பண்புக்கூறின் புள்ளிவிவரங்கள், அலைவெண் செவ்வகம் ஆகியவற்றைப் பார்க்கவும். வடிகட்டிகளும் இங்கே பயன்படுத்தப்படுகின்றன.
- மற்ற தாவல்கள்: **Classify, Cluster, Associate, Select attributes, Visualize**.
- தரவுத்தொகுப்புகளில் **நிகழ்வுகளும்** (வரிசைகள்) **பண்புக்கூறுகளும்** (நிரல்கள்) உள்ளன. ஒரு பண்புக்கூறு பொதுவாக **வகுப்பாக** இருக்கும்.
