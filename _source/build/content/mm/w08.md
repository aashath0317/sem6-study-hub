## What interactive multimedia adds

:::key Definition
Interactive multimedia changes its behaviour in response to user input. The user actively controls, combines or manipulates text, graphics, animation, sound or video instead of only watching a fixed presentation.
:::

An ordinary animation follows its timeline. An interactive animation may wait for a click, move to a chosen location, repeat a section or branch to another scene. Both the user and system have an active role: the user acts, the system interprets the action, and the visible or audible response informs the user what happened.

A learning title can let a student choose a topic, pause a demonstration, change a parameter and try again. A Sri Lankan railway kiosk can let the traveller select language and destination before showing the relevant information. A game can move a character in response to keyboard or pointer input. In each case, describe the input, the rule and the resulting output. Merely placing a decorative button on the stage does not implement an interaction.

Plan the interaction modes before writing scripts. Ask what the learner needs to control, which control makes that action obvious, how the system reports success or failure, and how the learner can recover from an unwanted choice. Keep related controls close together and group them by purpose. The PDF compares this to physical control systems such as steering and aircraft controls: the arrangement should support the task.

## Flow control, frame control and time control

| Control | Decision being made | Example |
|---|---|---|
| Flow control | What sequence or branch comes next? | A correct answer opens the next scene |
| Frame control | Which frame should be displayed or played from? | Jump to a labelled demonstration frame |
| Time control | When should something happen or how long should it remain? | Wait for a timer, hold until input, repeat after a delay |

The PDF's flow-control definition uses events to determine the next sequence of frames. Its time-control explanation includes repeating, holding and pre-assigned triggers. These controls can work together. A timer may fire an event; the handler may then choose the next frame. Do not confuse a frame number with elapsed seconds. A frame's time depends on the movie's frame rate.

For an interactive lesson, stop at a decision screen, wait for input and branch only after the selection is valid. For a demonstration, let the learner replay a sequence without duplicating its assets. Name important destinations with frame labels where the package permits; a meaningful label is easier to maintain than a mysterious number. Avoid a timeline script that repeatedly registers the same listener each time the playhead re-enters a frame.

:::example A clear control plan
A bus-safety lesson begins at an introduction. The learner presses Start, watches an ordered crossing demonstration and reaches a question. The movie holds. A correct response goes forward; an incorrect response displays feedback and enables Replay. The user controls the branch, while the demonstration itself keeps its sequence.
:::

## Actions, events, listeners, trigger functions and handlers

A **user action** is a physical or intentional act such as clicking, moving a pointer, touching or pressing a key. An **event** is the program's representation of an occurrence. An **event listener** registers interest in a particular event on a particular object. A **callback or event handler** is the function executed when the relevant event occurs.

The PDF calls the mechanism that selects the appropriate code a **trigger function**. Terminology differs between environments, but preserve the causal chain: action → event → listener/dispatch → handler → state change → output. A handler can also be triggered by a timer or another program event; events are not limited to physical mouse actions. A main event loop or the runtime coordinates dispatch so the program can react without continuously asking the user to make a choice in a blocking loop.

:::flow Event-driven sequence
The user activates a button
A click event is generated
The registered listener recognises the event
The handler checks the current state
The handler updates the movie or data
The interface displays feedback
:::

The lesson mentions ActionScript 3 in Flash/Animate tutorials. The exact API depends on the document type and scripting environment. The same event-driven idea also applies to browser JavaScript. State your environment when giving code; ActionScript and JavaScript snippets cannot simply be pasted into each other's projects.

```javascript
startButton.addEventListener('click', startLesson);
function startLesson(event) {
  currentScene = 'demonstration';
  showScene(currentScene);
}
```

This short browser-style example registers a function; it does not call it immediately. The handler runs after the event. A common mistake is passing the result of a function call instead of the function itself. Another is changing the display but forgetting to update the state that later decisions use. Test an interaction more than once, including after replay or reset.

## Reusable components, libraries and widgets

A **component** is a reusable element such as a button, graphic, movie clip or animation. A **library** stores definitions for reuse. An **instance** is a placed use of a definition. The PDF emphasises that editing the shared library definition can update its instances. Instance-specific values such as position or state can still differ; do not assume every placed instance must always look and behave identically.

A button placed on the stage can expose events such as click, mouse-up or keyboard activation. A script attached through the supported environment links the event to behaviour. A reusable butterfly symbol can have its own wing animation while its instance changes position on the main stage. Component-based development reduces repeated drawing and lets the programmer work with meaningful visual objects.

Choose widgets for their purpose: a button initiates an action; a slider changes a range value; a checkbox switches an independent option; a list selects among alternatives. Give each a visible label and a clear state. Ensure focus can reach it and keyboard users can activate it. Show feedback close to the control that caused it. A disabled or unavailable action should be understandable, rather than silently doing nothing.

Keep library names and instance names distinct. The library defines a symbol; code usually needs the particular placed instance. If a script cannot find its target, check the instance name, timeline scope, frame existence and whether the object was created before the script ran. Reusing a visual symbol does not remove the need to plan its event behaviour.

## Activity 8.1(i): butterfly moves to the clicked location

**Question:** create an animation of a butterfly whose location changes when the user clicks the stage, moving to the clicked position.

**Full model answer:** create a butterfly symbol and place one named instance on a background layer. Give the butterfly a suitable registration point near its centre. Register a click listener on the stage. Read the click coordinates in the stage's local coordinate system, then set a target position for the butterfly. Move immediately for a simple response, or interpolate from its current position for a visible flight. Keep wing-flapping as a separate internal animation so travelling and flapping can be controlled independently. Clamp the target if the whole butterfly must remain visible at the stage edge.

```text
on stageClick(event):
    target = convertPointerToStage(event)
    target = keepInsideStage(target, butterflyBounds)
    moveButterflyFromCurrentPositionTo(target)
```

Test clicks near each corner, repeated clicks during travel and clicks on the butterfly itself. Decide whether a new click replaces the current destination. Avoid starting unlimited concurrent movement loops. On a web page, scale pointer coordinates from the displayed stage rectangle to its internal drawing coordinates; otherwise the destination is wrong after responsive resizing. Provide a keyboard way to move the object or choose a destination. The model below uses a pointer and arrow-key control and keeps the object within its stage.

## Activity 8.1(ii): random paths in sequence

**Question:** animate a ball across the stage along different paths, one after another, selecting its path randomly for each movement.

**Full model answer:** prepare several valid routes as point lists or labelled timeline segments. Give every route a start state, an end state and a duration. Store the ball's current route, progress and playing/paused state. When a movement completes, choose a route index randomly, initialise that route and continue. Use one update mechanism. If the requirement means every consecutive route must differ, reject the previous index when choosing the next one. Random selection alone can repeat a path; state this distinction instead of promising no repeats.

```text
on movementComplete:
    next = chooseRandomRouteExcluding(previousRoute)
    initialise(next)
    play(next)
on pause:
    preserve current route and progress
on resume:
    continue from preserved progress
```

For a route with a different starting point, decide whether the ball returns visibly or whether routes share endpoints. A sudden unexplained teleport is usually a design defect. Add Start, Pause, Resume and Reset controls with understandable states. Reset should restore the original ball and route state. Test every route individually before testing random selection; randomness can otherwise hide an untested branch. A sequence is still event-driven because completion triggers the next choice, even when no new mouse click is needed.

### Model quality checklist

Check logical control grouping, correct event target, one listener per intended action, a visible response, valid coordinate conversion, safe stage boundaries and repeatable reset. Verify keyboard operation and the intended mobile interaction.
