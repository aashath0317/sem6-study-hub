1Direct manipulation

பொருளையே நேரடியாகக் கையாளுதல்

திரையில் உள்ள பொருளையே நேரடியாக நகர்த்துவது அல்லது மாற்றுவது போலப் பயனருக்குத் தோன்றும் தொடர்புமுறை Direct manipulation.

படத்தைப் பெரிதாக்கும் இரண்டு வழிகள்
வழிபயனர் என்ன செய்கிறார்?கவனம் எங்கே செல்கிறது?
வழிMenu-and-percentage — மெனு வழிபயனர் என்ன செய்கிறார்?மெனுவைத் திறந்து பெரிதாக்கும் கட்டுப்பாட்டைத் தேடி, 150% போன்ற எண்ணை உள்ளிடுகிறார்.கவனம் எங்கே செல்கிறது?படத்தைப் பார்ப்பதிலிருந்து கட்டுப்பாடுகளை அமைப்பதற்குக் கவனம் மாறுகிறது.
வழிPinch-on-object — பொருளின் மேல் செயல்பயனர் என்ன செய்கிறார்?படத்தின் மேல் இரண்டு விரல்களை வைத்து விரிக்கிறார்; படம் பெரிதாகிறது.கவனம் எங்கே செல்கிறது?படத்தை விரிப்பது போன்ற பழக்கமான செயலும் தெரியும் விளைவும் இணைகின்றன.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

இதை “தொட்டுத் திரை நல்லது; மவுஸ் நல்லதல்ல” என்று புரிந்துகொள்ள வேண்டாம். மவுஸால் ஒரு கோப்பை இழுத்து அடைவுக்குள் விடுவதும் நேரடி மாற்றம் போல அமையலாம்.

செயலின் விளைவு உடனே தெரிய வேண்டும்; தவறான மாற்றத்தைத் திரும்பப் பெறும் வசதியும் உதவும். மென்பொருளின் கட்டுப்பாடுகளைப் பற்றிய கவலை குறைந்து, பயனர் தனது வேலையில் கவனம் செலுத்துவது நோக்கம்.

In direct manipulation the user feels immediate, tactile control of the task object itself. The software layer fades from conscious awareness, which narrows both the gulf of execution and the gulf of evaluation.

2The desktop metaphor vs the command line

Desktop மற்றும் Command line

கோப்பை நகர்த்தும் ஒரே வேலையைச் சின்னங்களைப் பயன்படுத்தியும் எழுத்துக் கட்டளை மூலமும் செய்யலாம். இரண்டு வழிகளும் பயனரிடம் எதிர்பார்க்கும் அறிவு வேறுபடும்.

GUI மற்றும் CLI: வேலை ஒன்றே, செய்யும் முறை வேறு
வழிகோப்பை நகர்த்துவது எப்படி?நினைவில் வைத்திருக்க வேண்டியதுசாத்தியமான சிக்கல்
வழிDesktop GUI — காட்சி வழிகோப்பை நகர்த்துவது எப்படி?கோப்பின் சின்னத்தை இழுத்து வேண்டிய அடைவில் விடுகிறார்.நினைவில் வைத்திருக்க வேண்டியதுகோப்பு எங்கே இருக்கிறது, எந்த அடைவுக்கு நகர்த்த வேண்டும் என்பதைத் திரையில் அறிகிறார்.சாத்தியமான சிக்கல்தவறான கோப்பை அல்லது அடைவைத் தேர்வு செய்யலாம்; காட்சி வழியிலும் பிழை ஏற்படலாம்.
வழிCommand line / CLI — கட்டளை வழிகோப்பை நகர்த்துவது எப்படி?கோப்புப் பாதையையும் செல்ல வேண்டிய பாதையையும் எழுத்துக் கட்டளையில் குறிப்பிடுகிறார்.நினைவில் வைத்திருக்க வேண்டியதுசரியான கட்டளை வடிவம், இடைவெளி, பாதை போன்றவை தெரிந்திருக்க வேண்டும்.சாத்தியமான சிக்கல்எழுத்துப் பிழை அல்லது தவறான பாதையால் கட்டளை தோல்வியடையலாம் அல்லது தவறான விளைவு வரலாம்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

பாடத்தின் கருத்து: கட்டளையின் வடிவத்தை நினைவுகூரும் சுமை, காட்சி வழியில் அடையாளம் காணும் சுமையிலிருந்து வேறுபடுகிறது. ஆனால் CLI எப்போதும் மோசமானது அல்ல; பழகிய பயனருக்கு வேகமாகவும் மீளச் செய்ய ஏற்றதாகவும் இருக்கலாம். பயனர், வேலை, சூழலை வைத்து மதிப்பிடுங்கள்.

The desktop metaphor succeeded because it mimics a physical desk.

3Metaphorical vs literal invisibility — good vs bad design

Invisibility-இன் இரண்டு பொருள்கள்

இங்கு “கண்ணுக்குத் தெரியாத இடைமுகம்” என்பதற்கு இரண்டு பொருள்கள் உள்ளன. இதை உண்மையில் எல்லாப் பொத்தான்களையும் செய்திகளையும் மறைத்துவிடுதல் என்று புரிந்துகொள்ளக்கூடாது.

கவனத்தில் மறைவதும் திரையிலிருந்து மறைவதும் ஒன்றல்ல
கேள்விநல்ல வடிவமைப்புகுழப்பம் தரும் வடிவமைப்பு
கேள்விபயனரின் கவனம் எதில் இருக்கிறது?நல்ல வடிவமைப்புகட்டுப்பாட்டை எப்படிப் பயன்படுத்துவது என்ற கவலை குறைந்து, செய்யும் வேலையில் கவனம் இருக்கிறது. இதுவே metaphorical invisibility.குழப்பம் தரும் வடிவமைப்புஎன்ன செய்யலாம், என்ன நடந்தது என்று தேடுவதிலேயே கவனம் செல்கிறது.
கேள்விதேவையான உதவி தெரிகிறதா?நல்ல வடிவமைப்புதேவையான கட்டுப்பாடுகளும் நிலையைத் தெரிவிக்கும் பதிலும் கிடைக்கின்றன; அவை வேலையைத் தடுக்கவில்லை.குழப்பம் தரும் வடிவமைப்புஉதவியும் feedback-உம் மறைக்கப்பட்டதால் செயல் வெற்றியா தோல்வியா என்று தெரியவில்லை.
கேள்விமுடிவு என்ன?நல்ல வடிவமைப்புபயனர் நம்பிக்கையுடன் வேலையைத் தொடர்கிறார்.குழப்பம் தரும் வடிவமைப்புபதில் கிடைக்காமல் அதே செயலை மீண்டும் செய்யவோ வேலையை நிறுத்தவோ நேரலாம்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

“இடைமுகம் கவனத்தில் படாத அளவுக்குச் சுலபமாக இருக்கட்டும்” என்பதே நல்ல நோக்கம். “தேவையான தகவலும் இருக்கக்கூடாது” என்பது அதன் பொருள் அல்ல. சேமித்தபின் “Saved” என்று காட்டுவது வேலையில் நம்பிக்கை தரும் உதவி.

The key distinction 00:30
  • Metaphorically invisible: the user's train of thought is never interrupted by confusing software mechanics. There's no noticeable "figurative" involvement of the interface.
  • Literally visible: the interface is still there doing its job, giving clear visual status, confirmation highlights and feedback.
✅ Good design ❌ Bad design
Metaphorically Invisible: you think about the task (may also feel invisible)
Literally Present: gives feedback and support Invisible even literally: what the interface is for is forgotten, so there's no feedback 01:40
Result The sense of interaction is there, but the interface isn't prominent Violates the feedback cycle, so the user gets no support
One-line version 02:46

Good design = metaphorically invisible, literally present. Bad design = invisible even literally, so the user gets no feedback.

6Five tips for invisible interfaces

Invisible interface உருவாக்குதல்

பயனர் கட்டுப்பாடுகளுடன் போராடாமல் தனது வேலையைச் செய்ய உதவும் ஐந்து நடைமுறை வழிகள் இவை.

ஐந்து ஆலோசனைகள்: பெயருடன் அதன் செயல் பயனையும் நினைவில் கொள்ளுங்கள்
ஆலோசனைஎளிய பொருள்உதாரணம்
ஆலோசனை1. Natural affordancesஎளிய பொருள்என்ன செயல் செய்யலாம் என்பதற்கேற்ற கட்டுப்பாடும் தெளிவான குறியும் கொடுங்கள்.உதாரணம்அழுத்தக்கூடியது என்பதைப் புரியவைக்கும் பொத்தான்.
ஆலோசனை2. Know your userஎளிய பொருள்புதியவருக்கும் அனுபவமுள்ளவருக்கும் தேவையான உதவி ஒரே அளவில் இருக்காது.உதாரணம்புதியவருக்கு படிப்படியான வழிகாட்டல்; பழகியவருக்கு குறுக்குவழி.
ஆலோசனை3. Differentiate usersஎளிய பொருள்ஒரே வேலையைச் செய்ய ஏற்ற பல வழிகளை வழங்கலாம்.உதாரணம்Save மெனு, பொத்தான், Ctrl+S ஆகிய மாற்று வழிகள்.
ஆலோசனை4. Let the interface teachஎளிய பொருள்செய்யும்போதே புரியும்படி பதில், உதவிக்குறிப்பு, பாதுகாப்பான திருத்தம் கொடுங்கள்.உதாரணம்செல்லாத உள்ளீட்டிற்கு காரணத்தையும் சரிசெய்யும் வழியையும் காட்டுதல்.
ஆலோசனை5. Talk to usersஎளிய பொருள்உண்மையான பயன்பாட்டைக் கவனித்து விருப்பங்களையும் சிரமங்களையும் கேளுங்கள்.உதாரணம்பயனர் எந்தப் பொத்தானைத் தேடி நிற்கிறார் என்பதைப் பார்த்து பெயரை மேம்படுத்துதல்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Affordance என்பது செய்ய இயலும் செயல்; அதைப் புரியவைக்கும் குறி signifier. உதாரணமாகப் பொத்தானின் தோற்றமும் பெயரும் செயலைச் சுட்டிக்காட்டுகின்றன. எல்லா labels-ஐயும் மறைத்துவிடுவது எளிமை அல்ல.

வழக்கமான கேள்விகள்:

  • “நேரடிக் கையாளுதல் என்றால் என்ன? எடுத்துக்காட்டுகள் தருக” (விரல்களை விரித்துப் பெரிதாக்குதல், இழுத்துவிடுதல்)
  • “கற்றலால் மற்றும் வடிவமைப்பால் ஏற்படும் புலப்படாமையை வேறுபடுத்துக”
  • “உருவகமாகவும் நேரடியாகவும் புலப்படாமையை விளக்குக”
  • “புலப்படாத இடைமுகங்களை வடிவமைக்க ஐந்து குறிப்புகளைப் பட்டியலிடுக”

விரைவாக நினைவுபடுத்திக்கொள்ள

பொருளையே நேரடியாகக் கையாளுதல்

திரையில் உள்ள பொருளையே நேரடியாக நகர்த்துவது அல்லது மாற்றுவது போலப் பயனருக்குத் தோன்றும் தொடர்புமுறை Direct manipulation.

Desktop மற்றும் Command line

கோப்பை நகர்த்தும் ஒரே வேலையைச் சின்னங்களைப் பயன்படுத்தியும் எழுத்துக் கட்டளை மூலமும் செய்யலாம். இரண்டு வழிகளும் பயனரிடம் எதிர்பார்க்கும் அறிவு வேறுபடும்.

Invisibility-இன் இரண்டு பொருள்கள்

இங்கு “கண்ணுக்குத் தெரியாத இடைமுகம்” என்பதற்கு இரண்டு பொருள்கள் உள்ளன. இதை உண்மையில் எல்லாப் பொத்தான்களையும் செய்திகளையும் மறைத்துவிடுதல் என்று புரிந்துகொள்ளக்கூடாது.

Direct manipulation-இன் எல்லை

கீழே உள்ளவை பாடம் விவாதிக்கும் மேம்பாட்டு எண்ணங்கள். இவை எல்லா சாதனங்களிலும் இன்று உள்ள வசதிகள் என்று எடுத்துக்கொள்ள வேண்டாம்.

கற்றதால் எளிதா, Design-ஆல் எளிதா?

ஒரு இடைமுகம் பழகிய பிறகு எளிதாகத் தோன்றலாம். மற்றொன்று புதியவருக்கும் ஆரம்பத்திலேயே புரியும்படி வடிவமைக்கப்பட்டிருக்கலாம்.

Invisible interface உருவாக்குதல்

பயனர் கட்டுப்பாடுகளுடன் போராடாமல் தனது வேலையைச் செய்ய உதவும் ஐந்து நடைமுறை வழிகள் இவை.
