## Apriori-ஐ மட்டும் ஏன் பயன்படுத்தக்கூடாது?

Apriori-இன் வேட்பாளர் உருவாக்கிச் சோதித்தல், வேட்பாளர் தொகுப்புகளைப் பெரிதும் **சுருக்கினாலும்**, **அற்பமல்லாத இரு செலவுகள்** இன்னும் உள்ளன:

:::grid
**1. மிகப்பெரிய வேட்பாளர் தொகுப்புகள்**

**10⁴ அடிக்கடி நிகழும் 1-பொருட்கணங்கள்** இருந்தால், Apriori **10⁷-க்கும் மேற்பட்ட 2-பொருட்கண வேட்பாளர்களை** உருவாக்க வேண்டும். அது 10⁴ × (10⁴ − 1)/2 ≈ 5 × 10⁷.
+++
**2. மீண்டும் மீண்டும் தரவுத்தள ஸ்கேன்கள்**

**ஒவ்வொரு நிலையிலும் தரவுத்தளத்தை மீண்டும் ஸ்கேன் செய்து**, வடிவப் பொருத்தத்தால் பல வேட்பாளர்களைச் சரிபார்க்கிறது. ஆதரவை எண்ண ஒவ்வொரு பரிவர்த்தனையையும் ஆராய்வது **செலவுடையது**.
:::

:::key FP-growth-இன் விடை
**வேட்பாளர் உருவாக்கம் இல்லை; இரண்டு தரவுத்தள ஸ்கேன்கள் மட்டுமே** [[00:02]]. இதனால்தான் கணக்கீட்டு நேரம் குறைகிறது எனக் காணொளி வலியுறுத்துகிறது.
:::

## FP-growth: கருத்து

**அடிக்கடி நிகழும் வடிவ வளர்ச்சி (FP-growth)**, **பிரித்தாளும்** உத்தியைப் பயன்படுத்துகிறது:

1. அடிக்கடி நிகழும் பொருட்களின் தரவுத்தளத்தை **அடிக்கடி நிகழும் வடிவ மரமாக (FP-tree) சுருக்கவும்**. மரம் **பொருட்கணத் தொடர்புத் தகவலைப்** பேணுகிறது.
2. சுருக்கப்பட்ட தரவுத்தளத்தை **நிபந்தனைத் தரவுத்தளங்களாகப் பிரிக்கவும்** (*வீழ்த்தப்பட்ட தரவுத்தளத்தின்* ஒரு வகை); ஒவ்வொன்றும் ஓர் அடிக்கடி நிகழும் பொருள் அல்லது "வடிவத் துண்டுடன்" இணைந்திருக்கும்.
3. **ஒவ்வொரு நிபந்தனைத் தரவுத்தளத்தையும் தனியாகச் சுரங்கம் செய்யவும்.**

### மரத்தை உருவாக்கும் மூன்று படிகள் [[00:37]]

:::flow
ஸ்கேன் 1: ஆதரவுகளை எண்ணு → அடிக்கடி நிகழும் 1-பொருட்கணங்கள்
அடிக்கடி நிகழாத பொருட்களை நீக்கி ஒவ்வொரு பரிவர்த்தனையையும் இறங்குவரிசை ஆதரவுப்படி வரிசைப்படுத்து
ஸ்கேன் 2: ஒவ்வொரு பரிவர்த்தனையையும் வேரிலிருந்து ஒரு பாதையாகச் சேர்க்கவும்
:::

**ஒரு பரிவர்த்தனை சேர்க்கப்படுவது எவ்வாறு:**

- **null** அடையாளத்துடன் வேரை உருவாக்கவும்.
- ஒவ்வொரு பரிவர்த்தனையின் பொருட்களையும் **L வரிசையில்** (இறங்குவரிசை ஆதரவு) செயலாக்கவும்.
- ஏற்கெனவேயுள்ள பாதையுடன் பரிவர்த்தனை **முன்னொட்டைப் பகிர்ந்தால்**, பகிரப்பட்ட முன்னொட்டின் ஒவ்வொரு கணுவின் **எண்ணிக்கையையும்** 1 **அதிகரிக்கவும்**.
- பகிரப்பட்ட முன்னொட்டுக்குப் பின்னருள்ள பொருட்களுக்கு மட்டும் **புதிய கணுக்களை** உருவாக்கவும்.
- **பொருள் தலைப்பு அட்டவணையைப்** பேணவும்: ஒவ்வொரு பொருளும் மரத்தில் தோன்றும் இடங்களை **கணு-இணைப்புச்** சங்கிலி மூலம் சுட்டுகிறது.

தரவுத்தளத்தைச் சுரங்கம் செய்யும் பிரச்சினை, **FP-tree-ஐச் சுரங்கம் செய்யும்** பிரச்சினையாகிறது.

**மரத்தை உருவாக்குதல்:**

- **T200**, f-c-a முன்னொட்டைப் பகிர்வதால் அவை f:2, c:2, a:2 ஆகின்றன; a-க்குக் கீழ் புதிய **b:1 → m:1** கிளை சேர்க்கப்படுகிறது.

```
                 null
               /      \
            f:4        c:1
           /   \         \
        c:3    b:1       b:1
         |                 \
        a:3                p:1
       /    \
     m:2    b:1
      |       \
     p:2      m:1
```

## FP-tree-ஐச் சுரங்கம் செய்தல்

அடிக்கடி நிகழும் ஒவ்வொரு பொருளுக்கும், **மிகக்குறைவாக நிகழ்வதிலிருந்து தொடங்கி** (L-இன் கீழிருந்து), அதை **பின்னொட்டாக** எடுத்துக்கொள்ளவும்:

1. அதன் **நிபந்தனை வடிவத் தளத்தை** உருவாக்கவும்: பின்னொட்டுக்கு சற்று முன் முடியும் மரத்தின் **முன்னொட்டுப் பாதைகளின்** தொகுப்பு; ஒவ்வொன்றுக்கும் பின்னொட்டின் எண்ணிக்கை.
2. மொத்த எண்ணிக்கை ≥ min_sup உள்ள பொருட்களை மட்டும் பேணி, அந்தத் தளத்திலிருந்து **நிபந்தனை FP-tree** உருவாக்கவும்.
3. **அதை மறுசுழற்சியாகச் சுரங்கம் செய்யவும்.** நிபந்தனை மரத்தில் கண்டறிந்த வடிவங்களுடன் **பின்னொட்டை இணைப்பதால்** வடிவங்கள் வளர்கின்றன.

| பொருள் | நிபந்தனை வடிவத் தளம் | நிபந்தனை FP-tree | உருவான அடிக்கடி நிகழும் வடிவங்கள் |
|---|---|---|---|
| **p** | {f,c,a,m : 2}, {c,b : 1} | ⟨c:3⟩ | {c,p : 3} |
| **m** | {f,c,a : 2}, {f,c,a,b : 1} | ⟨f:3, c:3, a:3⟩ | {f,m}, {c,m}, {a,m}, {f,c,m}, {f,a,m}, {c,a,m}, **{f,c,a,m} : 3** |
| **b** | {f,c,a : 1}, {f : 1}, {c : 1} | ∅ (எந்தப் பொருளும் 3-ஐ அடையவில்லை) | — |
| **a** | {f,c : 3} | ⟨f:3, c:3⟩ | {f,a}, {c,a}, **{f,c,a} : 3** |
| **c** | {f : 3} | ⟨f:3⟩ | **{f,c} : 3** |
| **f** | ∅ | — | — |

p இரு பாதைகளின் இறுதியில் உள்ளது: f-c-a-m-**p** (எண்ணிக்கை 2), c-b-**p** (எண்ணிக்கை 1). முன்னொட்டுகள் {f,c,a,m}:2, {c,b}:1. மொத்தங்கள்: c = 2 + 1 = 3 ✓; ஆனால் f, a, m = 2 மற்றும் b = 1 ✗. எனவே நிபந்தனை மரம் ⟨c:3⟩ மட்டுமே; வடிவம் **{c, p}: 3**.
:::

{{tool:fp}}

:::tip இது ஏன் வேகமானது
- FP-growth, **நீண்ட வடிவங்களைக் கண்டறிவதை**, **மறுசுழற்சியாகச் சிறிய வடிவங்களைக் கண்டறிந்து பின்னொட்டை இணைப்பதாக** மாற்றுகிறது.
- **மிகக்குறைவாக நிகழும் பொருட்களைப் பின்னொட்டுகளாகப்** பயன்படுத்துவது சிறந்த **தேர்வுத்தன்மையை** வழங்குகிறது.
- நீண்ட, குறுகிய வடிவங்கள் இரண்டுக்கும் இது **திறமையானதும் விரிவாக்கமடையக்கூடியதும்**; பொருத்தமான தரவில் Apriori-ஐவிடச் சிறப்பாகச் செயல்படலாம்; தரவுத்தொகுப்புகள் மற்றும் செயலாக்கங்கள் அனைத்திலும் **நிலையான வேக உயர்வு உறுதியில்லை**.
- மரம் நினைவகத்தில் பொருந்தாவிட்டால், **தரவுத்தளத்தை வீழ்த்தப்பட்ட தரவுத்தளங்களாகப் பிரித்து**, ஒவ்வொன்றுக்கும் FP-tree உருவாக்கவும்; தேவைப்பட்டால் மறுசுழற்சியாகச் செய்யவும்.
:::

:::exam
FP-tree கேள்விகள் கேட்பவை:

1. ஆதரவுகளைக் கண்டறிந்து அடிக்கடி நிகழாத பொருட்களை நீக்கவும்.
2. ஒவ்வொரு பரிவர்த்தனையையும் மறுவரிசைப்படுத்தவும்.
3. எண்ணிக்கைகளுடன் **மரத்தை வரையவும்**.
4. **நிபந்தனை வடிவத் தளம் / நிபந்தனை FP-tree / அடிக்கடி நிகழும் வடிவங்கள்** அட்டவணையை உருவாக்கவும்.

மேலுள்ள உருவாக்கியுடன் பயிற்சி செய்யவும். min_sup-ஐ மாற்றவும் அல்லது விரிவுரையின் பழம்/காய்கறித் தரவுத்தொகுப்பை ஒட்டவும்.
:::

## பல்நிலைத் தொடர்பு விதிகள்

- **கீழ் (அடிப்படை) நிலைகளில்** தரவு **அரிதாக** இருப்பதால் வலுவான தொடர்புகளைக் கண்டறிவது கடினம்.
- **உயர் நிலைகளிலுள்ள** வலுவான தொடர்புகள் **பொது அறிவாக** இருக்கலாம்; ஆனால் ஒருவருக்குப் பொது அறிவானது மற்றொருவருக்கு **புதிதாக** இருக்கலாம்.
- எனவே **கருத்துப் படிநிலைகளைப்** பயன்படுத்தி முறைமை **பல அருவாக்க நிலைகளில்** சுரங்கம் செய்ய வேண்டும்:

```
                       அனைத்தும்
        ┌───────┬──────┼───────┬─────────────┐
      கணினி  மென்பொருள் அச்சுப்பொறி  கணினித் துணைப்பொருள்
     ┌──┴──┐     …       …            …
 மடிக்கணினி மேசைக்கணினி
```

- பல நிலைகளில் சுரங்கப்படும் விதிகள் **பல்நிலைத் தொடர்பு விதிகள்**.
- **ஆதரவு-நம்பிக்கைக் கட்டமைப்பின்கீழ்**, **மேலிருந்து கீழ்** உத்தியுடன் சுரங்கப்படுகின்றன: **நிலை 1**-இல் அடிக்கடி நிகழும் பொருட்கணங்களை எண்ணி, மேலும் கிடைக்காதவரை நிலைவாரியாக **கீழே** செல்லவும். ஒவ்வொரு நிலையிலும் எந்தப் படிமுறையும் (எ.கா. Apriori) இயங்கும்.

| அணுகுமுறை | வரம்புகள் | எடுத்துக்காட்டு (கணினி 10%, மடிக்கணினி 6%, மேசைக்கணினி 4%) |
|---|---|---|

| **குறைக்கப்பட்ட ஆதரவு** | **ஆழமான** நிலைகளில் **சிறிய** min_sup | நிலை 1 = 5%, நிலை 2 = 3%: **கணினி ✓, மடிக்கணினி ✓, மேசைக்கணினி ✓** |

:::warn சமரசம்
**சீரான ஆதரவு** எளிதானது; ஆனால் அதிகமாக இருந்தால் பொருளுள்ள கீழ்நிலைத் தொடர்புகளை **இழக்கிறீர்கள்**; குறைவாக இருந்தால் சுவாரசியமற்ற உயர்நிலைத் தொடர்புகள் **அளவுக்கதிகமாக** வருகின்றன. குறிப்பான நிலைகளில் தளர்வாக இருப்பதன் மூலம் **குறைக்கப்பட்ட ஆதரவு** இதைச் சரிசெய்கிறது.
:::

## பல்பரிமாணத் தொடர்பு விதிகள்

விதியிலுள்ள ஒவ்வொரு **வேறுபட்ட பயனிலையும்** ஒரு **பரிமாணம்**.

| வகை | பயனிலைகள் | எடுத்துக்காட்டு |
|---|---|---|
| **ஒற்றைப் பரிமாணம்** (உட்பரிமாணம்) | **ஒரு** பயனிலை, மீண்டும் வருகிறது | buys(X, "digital camera") ⇒ buys(X, "HP printer") |
| **பரிமாணங்களுக்கிடையிலானது** | **இரண்டு அல்லது அதிகம்**, **மீளுருவில்லை** | age(X, "20…29") ∧ occupation(X, "student") ⇒ buys(X, "laptop") |
| **கலப்புப் பரிமாணம்** | இரண்டு அல்லது அதிகம், **மீண்டும் வரும் பயனிலையுடன்** | age(X, "20…29") ∧ buys(X, "laptop") ⇒ buys(X, "HP printer") |

:::tip விரைவுச் சோதனை
**வேறுபட்ட** பயனிலைப் பெயர்களை எண்ணவும். ஒன்று → ஒற்றைப் பரிமாணம். ஒன்றுக்கு மேல், மீளுருவில்லை → பரிமாணங்களுக்கிடையிலானது. ஒன்றுக்கு மேல், மீளுருவுள்ளது → கலப்பு.
:::

## கட்டுப்பாடு சார்ந்த தொடர்புச் சுரங்கம்

- சுரங்கம் **ஆயிரக்கணக்கான விதிகளை** உருவாக்கலாம்; பெரும்பாலானவை **சுவாரசியமற்றவை**.
- தேவையானவற்றின் **"திசையும்"** **"வடிவமும்"** பயனர்களுக்குப் பெரும்பாலும் தெரியும்; எனவே **தேடல் வெளியை மட்டுப்படுத்தக் கட்டுப்பாடுகளைக்** குறிப்பிடுகின்றனர். இதுவே **கட்டுப்பாடு சார்ந்த சுரங்கம்**.

| கட்டுப்பாடு | குறிப்பிடுவது | எடுத்துக்காட்டு |
|---|---|---|
| **அறிவு வகை** | அறிவின் வகை | தொடர்பு விதி அல்லது ஒட்டுறவு |
| **தரவு** | பணிக்குப் பொருத்தமான தரவு | கொழும்பு விற்பனை, 2025 |
| **பரிமாணம்/நிலை** | எந்தப் பரிமாணங்கள் அல்லது படிநிலை நிலைகள் | பொருளை "வணிகப்பெயர்" நிலையில், வயதுடன் பயன்படுத்துதல் |
| **சுவாரசியத்தன்மை** | புள்ளிவிவர அளவைகளின் வரம்புகள் | ஆதரவு ≥ 5%, நம்பிக்கை ≥ 70%, ஒட்டுறவு |
| **விதி** | விதிகளின் **வடிவம்**: **மேல்விதிகள் (வார்ப்புருக்கள்)**, ஒவ்வொரு பக்கத்திலும் அதிகபட்ச/குறைந்தபட்சப் பயனிலைகள், பண்புக்கூறுகள் அல்லது திரட்டல்களுக்கிடையிலான உறவுகள் | P(X, Y) ∧ Q(X, W) ⇒ buys(X, "laptop") |
