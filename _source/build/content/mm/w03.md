## The role and building blocks of text

Text communicates names, instructions, facts and abstract ideas. In multimedia it appears in page titles, picture labels, button menus, navigation and the main content. A photograph can show a bus, but text can explain its destination, fare conditions or a concept that has no obvious visual form.

Developers consider text from two viewpoints. **Presentation** is how the words look: typeface, size, colour and arrangement. **Content and behaviour** are what the words mean and what happens when a person interacts with them. A hyperlink can look attractive yet still be confusing if its label does not describe its destination.

The PDF groups basic characters into alphabetic characters, numbers and special characters. Alphabetic examples include uppercase and lowercase letters. Numerical examples are the digits. Special characters include punctuation, mathematical symbols and signs. Icons, drawing symbols and Greek letters can also belong to a character repertoire. Characters combine into words, sentences, paragraphs and longer works.

**Linear text organisation** follows a sequence. **Nonlinear organisation** uses links to jump to a chosen item. A **glyph** is the visible shape used to represent a character. Character meaning and glyph appearance are separate: the same letter can have different shapes in different typefaces.

:::example A railway information screen
The title identifies the service. A short instruction explains how to choose a destination. Labels name the controls. A link labelled “Fare conditions” leads to further information. Meaning, appearance and interaction all help the traveller complete the task.
:::

## Typeface, font and appearance effects

:::key Two terms to distinguish
A **typeface** is the visual design of a family of letters, numbers and symbols. A **font**, in the lesson's traditional definition, is a collection of characters of one size and style from that family. In digital use “font” also names the software resource that supplies character shapes and rendering information.
:::

For example, a typeface family can have regular, bold and italic styles. Choosing a family establishes the visual design; choosing a style and size establishes its particular use in a heading or paragraph. The words are often used interchangeably in everyday conversation, but explain the distinction in an exam.

Type size is measured in **points**. **One point is 1/72 inch**. The PDF describes point size using capital tops and descenders. More precisely, point size is the font's design/em size; the visible letter height varies by typeface. Therefore two fonts set at the same point size can look different in height.

| Effect in the lesson | Purpose and caution |
|---|---|
| UPPERCASE and lowercase | Establish tone and hierarchy; long uppercase passages can be tiring |
| Bold | Emphasise an important word or heading |
| Italic | Show a distinction or emphasis without changing family |
| Underline | Emphasise text; on a website it often suggests a link |
| Superscript and subscript | Position characters above or below the normal line, as in powers or chemical notation |
| Emboss or shadow | Add a dimensional or decorative effect; preserve readability |
| Colour | Draw attention and organise meaning; test against the background |
| Strikethrough | Show that text has been removed or superseded |

An effect is useful when it carries a clear message. Applying all effects to one phrase destroys hierarchy and may reduce readability. Use the same effect consistently for the same purpose.

## Serif, sans serif and spacing anatomy

**Serif** typefaces have finishing strokes or small tips at the ends of main strokes. Times New Roman is a familiar example. **Sans serif** typefaces omit these features. Arial is a familiar example. Figures 3.1 and 3.2 compare the same words in the two categories.

The PDF recommends serif faces for long documents and sans serif faces for displays. Treat that as design guidance, not an absolute rule. Size, spacing, contrast, rendering and the reader's needs also affect readability. Test the actual screen or printed output.

| Term | What to identify |
|---|---|
| Baseline | The reference line on which most letters sit |
| Cap height | Height of capital letters above the baseline |
| x-height | Height of the main body of a lowercase letter such as x |
| Ascender | An upward stroke above the main lowercase body, as in h, b or d |
| Descender | A stroke below the baseline, as in p, q or y |
| Leading | Space between lines of text |
| Tracking | Overall spacing across a run of characters |
| Kerning | Adjustment of spacing between a particular pair of characters |

## Bitmap fonts, vector fonts and rasterization

A **bitmap font** stores character appearances as pixel patterns. It is closely tied to a particular pixel size. Enlarging it magnifies its stored pixels, and storing more characters or size variants needs additional data.

A **vector or outline font** stores mathematical descriptions of the glyph outlines. The rendering system scales those outlines to the desired size before drawing them. TrueType and PostScript outline fonts are the lesson's examples. Reusing outlines across sizes is efficient, although the PDF's claim that every vector-font file is much smaller is not a universal size guarantee.

| Bitmap font | Vector/outline font |
|---|---|
| Stores pixel patterns | Stores mathematical outlines |
| Designed for particular pixel dimensions | Can be scaled to different sizes |
| Enlargement exposes pixels | Renderer generates pixels for the chosen size |
| Several stored sizes may require more data | One outline design can serve many sizes |

**Rasterization** converts a glyph outline into screen pixels. Because a screen has a discrete grid, the edge of a diagonal stroke may look like steps. This is **aliasing**. **Anti-aliasing** uses intermediate edge intensities to blend the glyph with its background and make the perceived edge smoother. It improves appearance; it does not add unlimited physical resolution.

:::flow Outline to visible text
Character code selects a glyph
Font supplies the glyph outline
Renderer scales and positions it
Rasterization selects pixel coverage
Anti-aliasing adjusts edge intensities
Screen displays the result
:::

Figure 3.4 compares a diagonal stroke, circle and stepped raster edge with smoother versions. The important relationship is outline → pixel grid → possible jagged edge → intensity blending.

## Plain text, rich text and hypertext

**Plain text** stores characters without embedded presentation formatting such as bold or centred paragraphs. **Rich text** adds formatting instructions or control structures. **Hypertext** includes links that let the reader navigate to related sections, documents or media. These describe text organisation and presentation, while encoding describes how characters become data.

The PDF uses ASCII as its plain-text example. Plain text is not restricted to ASCII: a UTF-8 Tamil text file is also plain text. A document can also combine rich formatting with hyperlinks.

To use text efficiently, be concise without hiding essential information behind repeated clicks. Avoid decorative faces at small sizes. Use a small, consistent set of typefaces and vary bold or italic for appropriate distinctions. Set readable leading, give more important content a stronger size or weight, and adjust headline spacing carefully. Test text/background colour combinations. Similar content should retain the same style. Keyboard access, controls, user choices and clear interaction labels are part of text design too.

:::example Improve an instruction
“Click here” gives no destination. “Open the route map” explains the action and result. Put the instruction beside the relevant control. A clear sentence usually helps more than an ornate font or animated heading.
:::

## Character encoding and font mapping

A **character set** defines a repertoire of characters. A **code point** identifies a character numerically. A **character encoding** maps those values to stored or transmitted code units and bytes. The PDF's examples are ASCII, “EBCD” and Unicode; “EBCD” appears to refer to **EBCDIC**.

**ASCII** uses a small repertoire suited to basic English letters, digits, punctuation and control codes. It cannot represent the Tamil and Sinhala scripts. **Unicode** provides a shared repertoire covering many writing systems. UTF encodings represent Unicode data in bytes; Unicode and a particular UTF are not interchangeable terms.

The supplied [character-encoding article](https://medium.com/jspoint/introduction-to-character-encoding-3b9735f265a6) explains binary/hexadecimal notation, code points and byte encodings. Its useful distinction is that a character's identity differs from the bytes storing it. Endianness describes the order of bytes in a multi-byte value; a byte-order mark can signal an encoding convention. Reading data with the wrong encoding can produce garbled text.

:::warn Source correction: variable-length encodings
The PDF says every symbol has a fixed number of bits. This is too broad. UTF-8 uses **1–4 bytes** for a Unicode scalar value; UTF-16 uses **1 or 2 code units**; UTF-32 uses one code unit. See the [Unicode FAQ](https://www.unicode.org/faq/utf_bom.html). A displayed character can also consist of several code points.
:::

**Font mapping** specifies a substitute when the intended font is unavailable. Prefer available system fonts or package properly licensed resources for the target platform. A substitute may alter layout or lack required glyphs. The PDF suggests converting special text to an image; that preserves appearance but loses ordinary editability and selectable text, and may lose sharpness when enlarged. Test the result on the audience's device.

**PostScript** is a page-description language associated with mathematical outline-font technology and high-quality printing. The lesson contrasts its historical display-support requirements with **TrueType**, the outline-font technology associated with Apple and Microsoft and supported by operating-system renderers. The PDF's “no licensing needed” claim for TrueType is unsafe: the font's licence still controls use and distribution. A font format alone does not grant permission.

## All five PDF review questions

**1. What is meant by typeface?** It is the designed appearance of letters, numbers and symbols in a family. Font refers to a specific style/size in traditional usage or the digital resource supplying those shapes.

**2. Describe two main types of fonts with examples.** Serif typefaces have small finishing strokes, as in Times New Roman. Sans serif typefaces omit them, as in Arial. Select using context, size, spacing and readability, then test the actual output.

**3. Distinguish bitmap and vector fonts.** Bitmap fonts store pixel patterns and are tied to designed pixel sizes. Vector fonts store scalable mathematical outlines, which must be rasterized for a pixel screen. Outline reuse supports many sizes without storing a separate bitmap for each one.

**4. What is anti-aliasing?** It smooths the perceived jagged boundary of rasterized text or graphics by adjusting edge pixel intensities to blend foreground and background.

**5. Compare ASCII and Unicode.** Both support numerical representation of text. ASCII provides a limited basic repertoire and cannot encode Tamil or Sinhala. Unicode covers many scripts and separates character identity from encoding forms such as UTF-8. A correct font is still needed to draw the encoded text; choosing Unicode alone does not select its visual design.

:::exam English answer frame
“Readable multimedia text needs a suitable typeface, size, contrast and spacing. Serif and sans serif describe stroke design; bitmap and vector describe representation. Outline fonts are rasterized for the display, and anti-aliasing smooths perceived pixel edges. Use a suitable character encoding and test font availability or mapping on the target device.”
:::
