## Video organisation மற்றும் digitization

:::key Digital video
Video என்பது கால வரிசையில் வரும் **frames** என்ற images-இன் தொகுப்பு. Picture இரு dimensions கொண்டது; time மற்றொரு dimension. Digital video continuous voltage/magnetic pattern-க்கு பதிலாக numerical samples சேமிக்கிறது.
:::

Camera உலகக் காட்சியை image sequence-ஆக மாற்றுகிறது. **Sampling** time-ஐ frames-ஆகவும் ஒவ்வொரு frame-ஐ pixels என்ற spatial samples-ஆகவும் பிரிக்கிறது. **Quantization** sampled amplitude/colour component-க்கு discrete value தருகிறது. Temporal sampling frame rate-ஐயும் spatial sampling resolution-ஐயும் quantization possible colour values-ஐயும் நிர்ணயிக்கின்றன.

பாடம் frame rate, frame resolution, colour depth ஆகியவற்றை video-வின் மூன்று resolutions என்கிறது. இவை quality மற்றும் raw capacity-ஐ மாற்றும். குறைத்தால் size குறையலாம்; motion detail, spatial detail, colour precision-உம் இழக்கலாம். Application மற்றும் audience தேவைக்கேற்ப தேருங்கள்.

:::flow Figure 11.4-இன் மறுவரைவு
Scene → camera signal
Time sampling → successive frames
Space sampling → frame-இன் pixels
Quantization → numerical colour values
Encoding/storage → playable digital stream
:::

Analogue recording continuous-ஆக மாறும்; ஆனால் medium noise/imperfections சேர்க்கலாம். Transmission/decoding சரியானால் digital copying numerical data பாதுகாக்கும். “Digital எப்போதும் அதிக தகவல்” அல்லது “analogue எப்போதும் நல்லது” என்பது பொதுவிதி அல்ல. Capture, sampling, processing, delivery quality-ஐ நிர்ணயிக்கும்.

## Component, separated மற்றும் composite signals

| Signal | Organisation | முக்கிய பலன் | செலவு அல்லது limitation |
|---|---|---|---|
| Component | மூன்று தனி component paths; RGB, YUV அல்லது YIQ | Separate components கலப்பதைத் தவிர்க்கும் | அதிக connections/bandwidth மற்றும் sync |
| S-Video | Luminance, chrominance தனித்த paths | Brightness/colour crosstalk தவிர்க்கும் | Colour components ஒன்றாகவே உள்ளன |
| Composite | Luminance/chrominance ஒரே signal-இல் கலக்கும் | எளிய single video connection | Receiver பிரிக்க வேண்டும்; interference இருக்கலாம் |

**Luminance** brightness தகவல். **Chrominance** colour தகவல். PDF connector pictures component-க்கு மூன்று plugs, S-Video-க்கு multi-pin connector, composite-க்கு ஒரு plug காட்டுகின்றன. Signal paths எண்ணிக்கை அதே எண்ணிக்கையிலான முழு pictures என்று பொருளல்ல.

Component paths சரியாக sync ஆகவேண்டும். Visual detail brightness-ஐ மிகவும் சார்வதால் S-Video அதைத் தனியாக வைக்கிறது. Composite shared channel-இன் higher-frequency பகுதியில் chrominance வைக்கிறது; சரியாகப் பிரிக்காவிட்டால் artifacts தோன்றலாம். இவை signal arrangements; file extensions அல்ல.

## Progressive மற்றும் interlaced scanning

**Progressive scanning** frame-இன் எல்லா lines-ஐயும் வரிசையில் வரையும். **Interlaced scanning** alternate line sets-ஐ தனித்த fields-ஆக வரையும்: ஒன்று odd lines, அடுத்தது even lines. Interlaced frame-க்கு இரண்டு fields. Transmission constraints இருந்தபோது flicker குறைக்க interlacing பயன்பட்டது. வேறு நேரங்களில் எடுத்த fields-ஐ சரியான processing இல்லாமல் இணைத்தால் motion edges comb போலத் தோன்றலாம்.

| பாடத்தின் notation | பொருள் மற்றும் context |
|---|---|
| 525/59.94/2:1 | Total lines, field rate, interlaced; பழைய North American/Japanese family |
| 625/50/2:1 | Total lines, field rate, interlaced; பழைய European/Asian family |
| 1125/60/2:1 | பழைய high-definition interlaced family |
| 1920×1080, 1080i | Full-HD spatial dimensions, interlaced presentation |
| 1280×720, 720p | HD spatial dimensions, progressive presentation |

Fields/second மற்றும் frames/second ஒன்றல்ல. Total lines-இல் blanking/sync overhead உள்ளது; active picture lines குறைவு. PDF பழைய conventional picture-ஐ 644×483 என்றும் பழைய HDTV-ஐ 1920×1035 non-square pixels என்றும் விவரிக்கிறது. இவை குறிப்பிட்ட historical descriptions; எல்லா SD/HD files-க்கும் universal dimensions அல்ல.

Standard-definition families-க்கு basic component sampling rate **13.5 MHz**, பழைய high-definition family-க்கு **74.25 MHz** என source தருகிறது. Analogue studio bandwidth examples முறையே **5.5 MHz**, **6.5 MHz**, **30 MHz**. Sampling frequency மற்றும் analogue channel bandwidth வெவ்வேறு அளவுகள்.

## Raw video data size: முழு working

:::formula
Video bytes = width × height × frames/second × (bits/pixel ÷ 8) × seconds
Audio bytes = channels × samples/second × (bits/sample ÷ 8) × seconds
Total bytes = video bytes + audio bytes
Decimal MB = bytes ÷ 1,000,000
:::

இந்த estimates headers, metadata, compression, transmission overhead சேர்க்கவில்லை. Minutes-ஐ seconds-ஆகவும் bits-ஐ bytes-ஆகவும் மாற்றிவிட்டு multiply செய்யுங்கள். Source example போல இங்கு decimal MB பயன்படுத்தப்படுகிறது.

:::example Solved size example A: திருத்திய PDF example
கொடுத்தது **320×240**, **30 fps**, **8-bit** colour, **60 s**; audio **44,100 Hz**, **8-bit**, mono.

Video formula → **320 × 240 × 30 × (8/8) × 60**.
Working → **76,800 × 30 × 1 × 60 = 138,240,000 bytes = 138.24 MB**.
Audio formula → **1 × 44,100 × (8/8) × 60 = 2,646,000 bytes = 2.646 MB**.
Answer → **140,886,000 bytes = 140.886 MB**, சுமார் **140.89 MB**.

PDF substitution-இல் “44100 kHz” என்கிறது; அது **44,100 Hz** ஆகவேண்டும். Audio-ஐ முதலில் **2.6 MB** என round செய்து total **140.84 MB** பெறுகிறது. கடைசி answer வரை முழு precision வைத்திருங்கள்.
:::

:::example Solved size example B: video மட்டும்
கொடுத்தது **640×480**, **25 fps**, **24 bits/pixel**, **10 s**.
Formula → W × H × r × (b/8) × t.
Substitution → **640 × 480 × 25 × (24/8) × 10**.
Working → **307,200 × 25 × 3 × 10 = 230,400,000**.
Answer → **230,400,000 bytes = 230.4 MB**, video மட்டும்.
:::

:::example Solved size example C: video மற்றும் stereo sound
கொடுத்தது **1280×720**, **25 fps**, **24 bits/pixel**, **4 s**; **48,000 Hz**, **16-bit**, stereo.
Video → **1280 × 720 × 25 × 3 × 4 = 276,480,000 bytes**.
Audio → **2 × 48,000 × 2 × 4 = 768,000 bytes**.
Total → **276,480,000 + 768,000 = 277,248,000 bytes = 277.248 MB**.
:::

## Bit rate மற்றும் compression ratio

:::formula
Raw video bit rate = width × height × fps × bits/pixel
Average bit rate = file bytes × 8 ÷ duration in seconds
Compression ratio = uncompressed size ÷ compressed size
Compressed size = uncompressed size ÷ compression ratio
:::

**R:1** என்றால் uncompressed quantity compressed quantity-இன் **R** மடங்கு. ஒரே units ஒப்பிடுங்கள். **Mb/s** megabits/second; **MB/s** megabytes/second. உண்மையான network-க்கு overhead மற்றும் variable-rate peaks-க்கான capacity-உம் தேவை.

:::example மூன்று solved bit-rate examples
**Activity 11.1(a):** **320×240**, **12 fps**, **8 bits/pixel**. Formula → W × H × r × b. Substitution → **320 × 240 × 12 × 8**. Working → **76,800 × 96 = 7,372,800**. Answer → minimum raw video payload **7,372,800 bit/s = 7.3728 Mb/s**, audio/overhead தவிர.

**Example B:** **640×480**, **25 fps**, **24 bits/pixel**. Formula → W × H × r × b. Working → **640 × 480 × 25 × 24 = 184,320,000 bit/s = 184.32 Mb/s**.

**Example C:** **15,000,000-byte** delivery file, **30 s**. Formula → bytes × 8 ÷ seconds. Working → **15,000,000 × 8 ÷ 30 = 4,000,000 bit/s = 4 Mb/s**, average total file rate.
:::

:::example மூன்று solved compression examples
**Example A:** raw **120 MB**, encoded **12 MB**. Ratio → **120 ÷ 12 = 10**, ஆகவே **10:1**. Space saved → **120 − 12 = 108 MB**, அல்லது **90%**.

**Example B:** raw **300 MB**, ratio **25:1**. Compressed size → **300 ÷ 25 = 12 MB**.

**Example C:** encoded **8 MB**, ratio **15:1**. Raw size → **8 × 15 = 120 MB**. Check → **120 ÷ 8 = 15:1**.
:::

## Codecs, containers மற்றும் distribution

**Codec** media-ஐ encode/decode செய்கிறது. **Container** streams/metadata வைத்திருக்கும். **Player** container-ஐப் புரிந்துகொண்டு codecs support செய்ய வேண்டும். Extension மட்டும் எல்லா device-இலும் decode ஆகும் உறுதி தராது. PDF examples **FLV, MP4, MOV, WMV, WebM, RealMedia, AVI**, **MPG**. AVI/MOV பல codecs வைத்திருக்கலாம்; ஒவ்வொன்றும் ஒரு fixed compression algorithm அல்ல.

**Lossless compression** decode செய்தபின் original numerical data அப்படியே தரும். **Lossy compression** capacity/rate குறைக்க சில information-ஐ இழக்கும்; distortion ஏற்கப்படுகிறது. Pictures-க்குள்ளும் அருகிலுள்ள frames-க்கிடையிலும் உள்ள similarity-ஐ video compression பயன்படுத்துகிறது. அதிக compression artifacts மற்றும் decoding வேலை தரலாம். நல்ல-quality master வைத்து target-க்கு delivery copies செய்யுங்கள்.

**Activity 11.1(b), model answer:** MPEG-1 VCD-era lower-resolution delivery தொடர்புடையது; பழைய support பரவலாக இருந்தாலும் efficiency குறைவு. MPEG-2 DVD/broadcast workflows தொடர்புடையது; established ஆனாலும் பிற efficient codecs-ஐவிட ஒத்த quality-க்கு அதிக data தேவைப்படலாம். MPEG-4 ஒரு standards family; ஒரு extension/algorithm அல்ல. MPEG-4 AVC/H.264 போன்ற specific codecs efficient delivery தரும்; encoding/decoding effort மற்றும் compatibility பார்க்க வேண்டும். RLE lossless, repeated runs-க்கு உதவும்; noisy complex footage-க்கு சிறப்பல்ல. Cinepak, Indeo, Microsoft original Video பழைய AVI examples. Quality, bandwidth, devices, editing தேவைக்கேற்ப தேருங்கள். Source “current popular” wording மற்றும் MOV-க்கு எப்போதும் QuickTime install வேண்டும் என்ற கூற்று historical; தற்போதைய universal rule அல்ல.
