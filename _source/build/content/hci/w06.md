## Direct manipulation

In **direct manipulation** the user feels **immediate, tactile control of the task object itself**. The software layer **fades from conscious awareness**, which narrows **both the gulf of execution and the gulf of evaluation**.

| | **💻 Laptop without touch (indirect)** | **📱 Tablet / phone (direct manipulation)** |
|---|---|---|
| **Zoom an image** | Move cursor → open menu → click the zoom widget → **type a percentage** | **Put two fingers on the image and pinch outward** |
| **Effect** | **High friction**: attention shifts from the image to configuring controls | **Invisible interface**: the gesture maps **1-to-1** onto the mental model of stretching a photo |

## The desktop metaphor vs the command line

The **desktop metaphor** succeeded because it **mimics a physical desk**.

| | **📁 Desktop GUI** | **⌨️ Command line (CLI)** |
|---|---|---|
| **Move a document** | **Drag the icon into a folder**, like moving a paper folder on a desk | Recall exact syntax: `mv /usr/var/doc.txt /home/docs/` |
| **Risk** | Low: you see the result | **One missing space or typo = failure** |
| **Attention** | On the **task** | On the **syntax** |

## Metaphorical vs literal invisibility — good vs bad design

:::key The key distinction [[v2 00:30]]
- **Metaphorically invisible:** the user's train of thought is **never interrupted** by confusing software mechanics. There's no noticeable "figurative" involvement of the interface.
- **Literally visible:** the interface is **still there** doing its job, giving **clear visual status, confirmation highlights and feedback**.
:::

| | **✅ Good design** | **❌ Bad design** |
|---|---|---|
| **Metaphorically** | Invisible: you think about the task | (may also feel invisible) |
| **Literally** | **Present**: gives feedback and support | **Invisible even literally**: what the interface is for is forgotten, so there's **no feedback** [[v2 01:40]] |
| **Result** | The sense of interaction is there, but the interface isn't prominent | **Violates the feedback cycle**, so the user gets no support |

:::tip One-line version [[v2 02:46]]
Good design = **metaphorically invisible, literally present**. Bad design = **invisible even literally**, so the user gets no feedback.
:::

## Where direct manipulation is still lacking

| Scenario | Today (indirect, high friction) | Direct vision |
|---|---|---|
| **Typo correction** | Moving a tiny cursor with a finger and holding backspace | **Scribble out or swipe** the unwanted text, like on a whiteboard |
| **Emoji selection** | Pausing the conversation to browse hundreds of emoji grids | **Facial expression tracking** adds a smile or wink automatically |
| **Car climate control** | Digging through dashboard menus at 80 km/h | **Biometric sensors** detect shivering or heat and adjust the cabin automatically |

## Invisibility by learning vs by design

| | **📚 By learning** (a design crutch) | **✨ By design** (the gold standard) |
|---|---|---|
| **How** | The interface **fades with practice**. At first you notice it, then familiarity makes it go unnoticed [[v3 00:58]] | **Disappears from the very first moment** of use: no manual, no training [[v3 02:26]] |
| **Example** | **50-button TV remote**: an adult uses it blind, but a **2-year-old can't** (arbitrary mapping). **Video game** controls become automatic after practice | **YouTube on an iPad**: a **2-year-old** taps the big thumbnail and it plays, with zero instruction |
| **Who does the thinking** | The **user** (learning effort) | The **designer** [[v3 04:03]] |

:::warn Why invisibility by design is hard [[v3 03:19]]
- It's **very challenging** and **hard to achieve 100%**.
- "Most of the thinking has to be done by the **designer**, not by the user." The user's mental challenge is minimised, but the **designer's is immense**.
- Designers' effort is **commonly underestimated**, even by computing experts [[v3 04:47]].
:::

| # | Tip | Core idea |
|---|---|---|
| 1 | **Use natural affordances** | Controls show how they're used; placement has reasons [[v4 00:00]] |
| 2 | **Know your user** | Novice → ease of use; expert → efficiency [[v4 01:59]] |
| 3 | **Differentiate your users** | Several paths to the same task (menu, toolbar, right-click, shortcut) [[v4 03:45]] |
| 4 | **Let the interface teach** | Learn by doing: feedback, options, error tolerance, inline hints [[v4 04:44]] |
| 5 | **Talk to your users** | People have emotions and preferences; observe real use [[v4 05:33]] |
