1Task analysis & cognitive modelling

வேலையைச் சிறு செயல்களாக ஆராய்தல்

பெரிய வேலையைச் சிறு செயல்களாகப் பிரிப்பது Task analysis. அந்தச் செயல்களில் மனிதர் எப்படி செயல்படுவார் அல்லது எவ்வளவு நேரம் எடுப்பார் என்று மாதிரி மூலம் கணிப்பது Cognitive modelling.

நான்கு மாதிரிகள் எதற்குப் பயன்படுகின்றன?
மாதிரிஎதைக் கவனிக்கிறது?நினைவில் வைக்கும் கேள்வி
மாதிரிGOMSஎதைக் கவனிக்கிறது?இலக்கு, அடிப்படைச் செயல்கள், செயல் வழிகள், வழியைத் தேர்வு செய்யும் விதிகள் ஆகியவற்றை அமைக்கிறது.நினைவில் வைக்கும் கேள்வி“இந்த வேலையை எந்த வழியில் முடிப்பார்?”
மாதிரிKLMஎதைக் கவனிக்கிறது?அறிந்த வேலையின் குறிப்பிட்ட சிறு செயல்களுக்கு நேர மதிப்புகளைச் சேர்த்துக் கணிக்கிறது.நினைவில் வைக்கும் கேள்வி“இந்தச் செயல் வரிசைக்கு சுமார் எவ்வளவு நேரம்?”
மாதிரிFitts’s lawஎதைக் கவனிக்கிறது?குறிப்பிட்ட இலக்கை நோக்கி விரைவாகச் சுட்டியை நகர்த்தும் நேரத்தைக் கணிக்க உதவும்.நினைவில் வைக்கும் கேள்வி“பொத்தான் தொலைவிலும் சிறியதாகவும் இருந்தால் என்ன மாறும்?”
மாதிரிMHP — Model Human Processorஎதைக் கவனிக்கிறது?மனிதரின் உணர்வு, சிந்தனை, இயக்கச் செயலாக்கத்தை விளக்கும் அடிப்படை மாதிரி.நினைவில் வைக்கும் கேள்வி“தகவலை உணர்ந்து பதிலளிக்கும் மனிதச் செயல்முறை என்ன?”

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

GOMS ஒப்பீட்டளவில் மேல்நிலை அமைப்பைப் பார்க்கிறது; KLM குறிப்பிட்ட செயல் வரிசையைச் சிறு அளவில் பார்க்கிறது. Fitts இயக்கத்தின் ஒரு பகுதியைக் கவனிக்கிறது. நான்கையும் ஒரே formula என்று கருத வேண்டாம்.

இடைமுகத்தின் செயல் விவரம் தெரிந்தால் முழுப் பொருளைக் கட்டுவதற்கு முன்பும் சில ஒப்பீடுகளைச் செய்யலாம். ஆனால் விவரமில்லாத எந்த வடிவமைப்புக்கும் தானாகத் துல்லியமான நேரம் கிடைக்காது.

  • Task analysis is the formal breakdown of what a user must do (physical actions and cognitive processing) to reach a desired system state.
  • Cognitive modelling predicts how a person's mind works while using a particular UI: how they'd complete a task with that specific interface 01:01.
Why model instead of test? 02:46
  • Models don't need to be implemented or prototyped. You predict and assess mentally, without real users.
  • They have explanatory power (theory explains behaviour) and give a foundation for design, as in other engineering fields.
  • You can calculate performance times and compare workflows before writing code.

🖥 Information processor model

Human = input–output unit (the Model Human Processor, MHP). Focuses on keystrokes, pointing and perceptual cycles: GOMS, KLM.

🧠 Cognitive / predictor model

Focuses on mental simulations, hypotheses, problem-solving strategies and forming intentions.

சோதிப்பதற்குப் பதிலாக ஏன் மாதிரியாக்க வேண்டும்? 02:46
  • மாதிரிகளை செயல்படுத்தவோ முன்மாதிரியாக உருவாக்கவோ தேவையில்லை. உண்மையான பயனர்கள் இல்லாமல், மனதளவில் முன்கணித்து மதிப்பிடலாம்.
  • அவற்றுக்கு விளக்கத் திறன் உள்ளது (கோட்பாடு நடத்தையை விளக்குகிறது); மற்ற பொறியியல் துறைகளைப் போல வடிவமைப்புக்கு அடித்தளம் தருகின்றன.

2The GOMS framework

இலக்கு, செயல்கள், முறைகள், தேர்வு விதிகள்

G, O, M, S என்ற எழுத்துகள் நான்கு வேறு கூறுகளைக் குறிக்கின்றன. ஒரே “அறிக்கை அனுப்புதல்” உதாரணத்தில் அவற்றை இணைத்துப் பாருங்கள்.

GOMS: இலக்கிலிருந்து வழித் தேர்வு வரை
எழுத்து / சொல்எளிய விளக்கம்அறிக்கையை அனுப்பும் உதாரணம்
எழுத்து / சொல்G · Goalsஎளிய விளக்கம்முடிக்க விரும்பும் இலக்கு.அறிக்கையை அனுப்பும் உதாரணம்மேலாளருக்கு அதிகாரபூர்வ அறிக்கையைச் சேர்க்க வேண்டும்.
எழுத்து / சொல்O · Operatorsஎளிய விளக்கம்வேலையில் பயன்படும் அடிப்படை உணர்வு, சிந்தனை அல்லது இயக்கச் செயல்கள்.அறிக்கையை அனுப்பும் உதாரணம்ஒரு பொத்தானை அழுத்துதல், தட்டச்சு செய்தல், பட்டியலைப் பார்த்தறிதல்.
எழுத்து / சொல்M · Methodsஎளிய விளக்கம்இலக்கை முடிக்கும் வரிசைப்படுத்தப்பட்ட செயல்தொடர்.அறிக்கையை அனுப்பும் உதாரணம்மின்னஞ்சல் திறத்தல் → பெறுநரைச் சேர்த்தல் → கோப்பை இணைத்தல் → அனுப்புதல். அனுமதிக்கப்பட்ட அரட்டைச் செயலி மற்றொரு வழியாக இருக்கலாம்.
எழுத்து / சொல்S · Selection rulesஎளிய விளக்கம்எந்தச் சூழலில் எந்த வழியைத் தேர்வு செய்வது என்ற நிபந்தனை.அறிக்கையை அனுப்பும் உதாரணம்இந்த உதாரணத்தில் அதிகாரபூர்வ அறிக்கைக்கு மின்னஞ்சல்; வேறு அனுமதிக்கப்பட்ட சூழலில் அரட்டை வழி.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

Operator ஒரு சிறு செயல்; Method பல செயல்களின் வரிசை; Selection rule எந்த வரிசையைத் தேர்வு செய்வது என்ற விதி. இம்மூன்றையும் “செய்முறை” என்ற ஒரே சொல்லால் மட்டும் குறித்தால் குழப்பம் வரும்.

கோப்பைச் சேமித்தல் என்ற இலக்கிற்கு மெனு வழியும் Ctrl+S வழியும் இருக்கலாம். கை விசைப்பலகையில் இருந்தால் குறுக்குவழியைத் தேர்வு செய்வது ஒரு தேர்வு விதிக்கான உதாரணம். வழக்கமான, பழகிய, பிழையில்லாத செயல்திறன் என்பது அடிப்படை மாதிரியின் முக்கியக் கருதுகோள்.

GOMS (Card, Moran & Newell) models an expert doing goal-oriented, error-free tasks:

Letter Component Meaning Example: send a report to your manager
G Goals The high-level objective "Send an official report to the manager"
O Operators Elementary perceptual, motor or cognitive actions Click a button, type a key, scan a list
M Methods Ordered sequences of operators that achieve a (sub)goal Method A: email · Method B: chat app
S Selection rules If-then logic choosing which method to use IF formal or urgent THEN email ELSE chat 
GOAL: Send report to manager
 ├─ [Selection rule] IF formal THEN use METHOD-A ELSE METHOD-B
 ├─ METHOD-A (Email):  open mail → click Compose → type address → attach file → click Send
 └─ METHOD-B (Chat):   open chat → find manager → drag file in → press Enter

GOMS (கார்ட், மோரன், நியூவெல்), இலக்கு நோக்கிய, பிழையற்ற பணிகளைச் செய்யும் வல்லுநரை மாதிரியாக்குகிறது:

எழுத்து கூறு பொருள் எடுத்துக்காட்டு: மேலாளருக்கு அறிக்கை அனுப்புதல்
G இலக்குகள் (Goals) உயர்நிலை நோக்கம் “மேலாளருக்கு அதிகாரபூர்வ அறிக்கையை அனுப்புதல்”
O அடிப்படைச் செயல்கள் (Operators) அடிப்படையான புலனுணர்வு, இயக்க அல்லது அறிவாற்றல் செயல்கள் பொத்தானைச் சொடுக்குதல், விசையைத் தட்டுதல், பட்டியலைப் பார்வையிடுதல்
M முறைகள் (Methods) ஒரு (துணை) இலக்கை அடைய அடிப்படைச் செயல்களின் வரிசைப்படுத்தப்பட்ட தொடர்கள் முறை A: மின்னஞ்சல் · முறை B: உரையாடல் செயலி
S தெரிவு விதிகள் (Selection rules) பயன்படுத்த வேண்டிய முறையைத் தேர்ந்தெடுக்கும் எனில்–அப்போது தர்க்கம் அதிகாரபூர்வமானது அல்லது அவசரமானது எனில் மின்னஞ்சல்; இல்லையெனில் உரையாடல் 
இலக்கு: மேலாளருக்கு அறிக்கை அனுப்புதல்
 ├─ [தெரிவு விதி] அதிகாரபூர்வமானது எனில் முறை-A; இல்லையெனில் முறை-B
 ├─ முறை-A (மின்னஞ்சல்): அஞ்சலைத் திற → புதிய அஞ்சலைச் சொடுக்கு → முகவரியைத் தட்டச்சு செய் → கோப்பை இணை → அனுப்பு என்பதைச் சொடுக்கு
 └─ முறை-B (உரையாடல்): உரையாடலைத் திற → மேலாளரைக் கண்டுபிடி → கோப்பை இழுத்துச் சேர் → Enter அழுத்து

3Keystroke-Level Model (KLM)

அடிப்படைச் செயல்களால் நேரம் கணித்தல்

வேலையைச் சிறு செயல்களாக எழுதி, ஒவ்வொரு செயலுக்கான நேரத்தைச் சேர்க்கும் முறை இது. ஒரு எழுத்து அல்லது குறி பலமுறை வந்தால் அவ்வளவு முறைக்கான நேரத்தையும் சேர்க்க வேண்டும்.

KLM குறிகள்: எதை எண்ண வேண்டும்?
குறிசெயல் என்ன?பாடத்தில் பயன்படுத்தும் நேரம்
குறிK · Keystrokeசெயல் என்ன?விசையை அழுத்துதல் அல்லது குறிப்பிடப்பட்ட பொத்தான் செயல்.பாடத்தில் பயன்படுத்தும் நேரம்சாதாரண பாட மதிப்பு 0.20 வினாடி. தட்டச்சுத் திறனுக்கு ஏற்ப மாறலாம்; பாடத்தில் 0.12 மற்றும் 0.40 வினாடி மதிப்புகளும் வருகின்றன.
குறிP · Pointingசெயல் என்ன?மவுஸ் சுட்டியை இலக்குக்குக் கொண்டு செல்லுதல்.பாடத்தில் பயன்படுத்தும் நேரம்சுமார் 1.10 வினாடி.
குறிH · Homingசெயல் என்ன?விசைப்பலகையிலிருந்து மவுஸிற்கு அல்லது மறுதிசையில் கையை மாற்றுதல்.பாடத்தில் பயன்படுத்தும் நேரம்சுமார் 0.40 வினாடி.
குறிM · Mental preparationசெயல் என்ன?அடுத்த செயல் தொகுதிக்குத் தேவையான மனத் தயாரிப்பு.பாடத்தில் பயன்படுத்தும் நேரம்சுமார் 1.35 வினாடி.
குறிD · Drawingசெயல் என்ன?பேனா அல்லது மவுஸால் வரைதல்.பாடத்தில் பயன்படுத்தும் நேரம்வேலையைப் பொறுத்து மாறும்.
குறிR · Response timeசெயல் என்ன?அமைப்பின் பதிலுக்குக் காத்திருத்தல்.பாடத்தில் பயன்படுத்தும் நேரம்அமைப்பின் பதில் நேரத்தைப் பொறுத்து மாறும்.
ஒரே சேமிப்பு வேலை: பாடத்தின் இரண்டு கணக்குகள்
வழிநேரத்தைச் சேர்ப்பதுமொத்தம்
வழிமவுஸ் மெனு வழிநேரத்தைச் சேர்ப்பதுH + M + P + BB + M + P + BB = 0.40 + 1.35 + 1.10 + 0.20 + 1.35 + 1.10 + 0.20மொத்தம்5.70 வினாடி.
வழிCtrl+S வழிநேரத்தைச் சேர்ப்பதுM + K + K = 1.35 + 0.20 + 0.20மொத்தம்1.75 வினாடி.
வழிஇந்தக் கருதுகோள்களில் உள்ள வேறுபாடுநேரத்தைச் சேர்ப்பது5.70 − 1.75மொத்தம்3.95 வினாடி.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

இந்த உதாரணத்தில் B என்பது மவுஸ் பொத்தானை அழுத்துதல் அல்லது விடுதல்; தலா 0.10 வினாடி. எனவே BB = 0.20 வினாடி. அதை K-க்கான மதிப்புடன் குழப்ப வேண்டாம்.

மொத்த நேரம் = பயன்படுத்திய எல்லாச் செயல்களுக்கான நேரங்களின் கூட்டுத்தொகை. மனத் தயாரிப்பு M-ஐ ஒவ்வொரு நகர்வுக்கும் காரணமின்றிச் சேர்க்க வேண்டாம்; செயல்தொகுதி மற்றும் சூழலைக் கவனிக்க வேண்டும். இவை பாடத்தின் மதிப்பீடுகள்; எல்லா நபருக்கும் உறுதியான நேரங்கள் அல்ல.

KLM is a simplified, quantitative version of GOMS. It calculates the execution time for an expert doing a routine task with no errors:

Texecute = TK + TP + TH + TD + TM + TR
Operator Meaning Typical time
K Keystroke / button press ~0.20 s (skilled typist 0.12 s, novice 0.40 s)
P Pointing the mouse at a target ~1.10 s
H Homing: moving the hand between keyboard and mouse ~0.40 s
M Mental preparation before the next chunk ~1.35 s (the largest)
D Drawing with pen or mouse Depends on the domain
R System response time (waiting) Depends on the system
Where to put M operators 00:00

The lecture starts with an M before a P that selects a command. Mental preparation placement also depends on task chunking and context; do not add an M mechanically before every movement. M is the biggest operator, so too many commands to choose from means too many M's, which makes the task slow 01:04. Each operator time is an estimate; add them up for the total task time.

KLM என்பது GOMS-இன் எளிமைப்படுத்தப்பட்ட அளவுசார் வடிவம். ஒரு வல்லுநர் வழக்கமான பணியைப் பிழையின்றிச் செய்வதற்கான செயலாக்க நேரத்தைக் கணக்கிடுகிறது:

Texecute = TK + TP + TH + TD + TM + TR
அடிப்படைச் செயல் பொருள் வழக்கமான நேரம்
K விசை அழுத்தம் / பொத்தான் அழுத்தம் சுமார் 0.20 நொடி (திறமையான தட்டச்சாளர் 0.12 நொடி; புதியவர் 0.40 நொடி)
P சுட்டியை இலக்கை நோக்கிச் சுட்டுதல் சுமார் 1.10 நொடி
H கைமாற்றம்: விசைப்பலகைக்கும் சுட்டிக்கும் இடையே கையை நகர்த்துதல் சுமார் 0.40 நொடி
M அடுத்த தகவல் தொகுதிக்கு முன் மனத் தயாரிப்பு சுமார் 1.35 நொடி (மிகப் பெரியது)
D பேனா அல்லது சுட்டியால் வரைதல் பயன்பாட்டுத் துறையைச் சார்ந்தது
R முறைமை பதிலளிக்கும் நேரம் (காத்திருத்தல்) முறைமையைச் சார்ந்தது
M செயல்களை எங்கு வைப்பது? 00:00

கட்டளையைத் தேர்ந்தெடுக்கும் P-க்கு முன் M வைப்பதிலிருந்து விரிவுரை தொடங்குகிறது. மனத் தயாரிப்பை வைப்பது பணித் தொகுதியாக்கலையும் சூழலையும் சார்ந்தது; ஒவ்வொரு நகர்வுக்கும் முன் இயந்திரத்தனமாக M சேர்க்க வேண்டாம். M மிகப் பெரிய அடிப்படைச் செயல்; எனவே தேர்ந்தெடுக்க அதிகக் கட்டளைகள் இருந்தால் அதிக M-கள் தேவைப்படும்; பணி மெதுவாகும் 01:04. ஒவ்வொரு செயல் நேரமும் ஒரு மதிப்பீடு; மொத்தப் பணி நேரத்துக்கு அவற்றைக் கூட்டவும்.

சுட்டி மூலம் சேமித்தலும் விசைப்பலகை மூலம் சேமித்தலும்
  • பட்டி மூலம் சேமித்தல்: H + M + P + B B + M + P + B B = 0.4 + 1.35 + 1.1 + 0.2 + 1.35 + 1.1 + 0.2 = 5.70 நொடி
  • Ctrl+S: M + K + K = 1.35 + 0.2 + 0.2 = 1.75 நொடி

இதனால்தான் வல்லுநர்கள் குறுக்குவழிகளை விரும்புகிறார்கள். (B = சுட்டிப் பொத்தானை அழுத்துதல் அல்லது விடுதல்; ஒவ்வொன்றும் சுமார் 0.1 நொடி.)

4Fitts's law

Fitts விதி

ஒரு பொத்தானை நோக்கி விரைவாகச் சுட்டியை நகர்த்தும் நேரத்தில் தூரமும் பொத்தானின் அகலமும் தாக்கம் தருகின்றன. பொதுவாகத் தொலைவில் இருக்கும் சிறிய இலக்கை அடைவது கடினம்.

Formula-வில் வரும் குறிகள்
குறிஎளிய பொருள்
குறிMTஎளிய பொருள்இலக்கை நோக்கிச் செல்லும் இயக்க நேரம்.
குறிDஎளிய பொருள்தொடக்க இடத்திலிருந்து இலக்குவரை உள்ள தூரம்.
குறிWஎளிய பொருள்இயக்கத் திசையில் அளக்கும் இலக்கின் அகலம். D மற்றும் W ஒரே அளவலகில் இருக்க வேண்டும்.
குறிaஎளிய பொருள்அளவீடுகளிலிருந்து பொருத்தப்படும் நிலையான தொடக்கக் கூறு.
குறிbஎளிய பொருள்சிரம அளவு மாறும்போது நேரம் எவ்வளவு மாறுகிறது என்பதைக் காட்டும் பொருத்தப்பட்ட கூறு.
குறிIDஎளிய பொருள்இலக்கை அடைவதற்கான சிரமக் குறியீடு; எந்த formula பயன்படுத்துகிறோம் என்பதற்கேற்ப கணக்கிடப்படுகிறது.
இரண்டு formula வடிவங்களை ஒன்றாகக் கலக்காதீர்கள்
பாடத்தில் வரும் வடிவம்D=400, W=40, a=0.1, b=0.15 என்ற உதாரணம்கிடைக்கும் நேரம்
பாடத்தில் வரும் வடிவம்PDF / கீழுள்ள ஆய்வுக்கருவி: MT = a + b log₂(2D/W)D=400, W=40, a=0.1, b=0.15 என்ற உதாரணம்ID = log₂(20) ≈ 4.322; MT = 0.1 + 0.15 × 4.322கிடைக்கும் நேரம்சுமார் 0.7486 வினாடி; இரண்டு தசமத்திற்கு 0.75 வினாடி.
பாடத்தில் வரும் வடிவம்Shannon வடிவம்: MT = a + b log₂(1 + D/W)D=400, W=40, a=0.1, b=0.15 என்ற உதாரணம்ID = log₂(11) ≈ 3.459; MT = 0.1 + 0.15 × 3.459கிடைக்கும் நேரம்சுமார் 0.619 வினாடி.
பாடத்தில் வரும் வடிவம்Shannon வடிவத்தில் அகலத்தை W=80 ஆக்கினால்D=400, W=40, a=0.1, b=0.15 என்ற உதாரணம்ID = log₂(6) ≈ 2.585; MT = 0.1 + 0.15 × 2.585கிடைக்கும் நேரம்சுமார் 0.488 வினாடி.
வடிவமைப்புக்கு என்ன பொருள்?
செய்யக்கூடிய மாற்றம்அது உதவும் காரணம்
செய்யக்கூடிய மாற்றம்முக்கிய பொத்தானை ஏற்ற அளவில் பெரிதாக்குதல்அது உதவும் காரணம்இலக்கை அடைவது எளிதாகலாம்; மிகத் துல்லியமாகச் சுட்ட வேண்டிய தேவை குறையும்.
செய்யக்கூடிய மாற்றம்சிறிய இலக்கை அருகில் வைத்தல்அது உதவும் காரணம்நகர்த்த வேண்டிய தூரம் குறைகிறது.
செய்யக்கூடிய மாற்றம்திரை ஓரம் / மூலை பயன்படுத்துதல்அது உதவும் காரணம்மவுஸ் சுட்டி ஓரத்தைத் தாண்டாமல் நிற்பது சில திசைகளில் உதவும். எல்லா சாதனத்திலும் எல்லாத் திசையிலும் அகலம் முடிவிலி அல்ல.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

கேள்வி கொடுக்கும் formula மற்றும் அதற்குரிய a, b மதிப்புகளையே பயன்படுத்துங்கள். ஒரு வடிவத்திற்குப் பொருத்திய மாறிலிகளை மற்ற வடிவத்தில் காரணமின்றிப் பயன்படுத்தக்கூடாது.

மேலுள்ள 0.75 மற்றும் 0.619 விடைகள் வேறுபடுவது formula வேறுபாட்டால். “இரண்டும் ஒன்றே; ஏதாவது விடை எழுதலாம்” என்பது தவறு.

Fitts's law comes from product ergonomics and is easily adapted to UIs. It predicts the time to move a pointer (or finger) to a target 03:38.

MT = a + b · log₂(2D / W) (PDF form)
MT = a + b · log₂(D / W + 1) (Shannon form, used in the lecture video 05:47)
Symbol Meaning
MT Movement time
D Distance (amplitude) to the target
W Width of the target along the direction of movement
a, b Constants from linear regression: a = intercept, b = slope
log₂(2D/W) Index of Difficulty (ID) in bits
In plain words 06:44

Longer distance + smaller target = more time. The wider the target, the less time it takes; the narrower, the more.

What Fitts's law means for design

Implication Explanation
🎯 Make important targets big Larger W means a faster click. Primary call-to-action buttons need generous hit areas. On phones, the answer and end-call buttons are large 07:51
📏 Keep small targets close If a target must be narrow, reduce the distance, which also cuts errors
🖥 Use screen edges and corners Pointer clamping at an edge reduces overshoot in that direction; the effective-width analogy is not a literal infinite W in every direction or on every device: Windows Start menu, Mac Apple menu
⚖️ Speed–accuracy trade-off Fast movement + small targets = higher error rates 06:44
⚡ Scope Applies to rapid pointing movements, not continuous movements 08:58

Operator timings and mental chunking are model assumptions, not guarantees for each person. See MIT's KLM teaching notes.

5Strengths and limits of predictive models

Predictive model-இன் வரம்பு

Prototype முழுவதும் செய்யாமலே design alternatives ஒப்பிட உதவும். ஆனால் உணர்வு, தவறு, கற்றல், சமூகச் சூழல் அனைத்தையும் நேரக் கணிப்பு காட்டாது. Model prediction-ஐ உண்மைப் பயனர் சோதனையுடன் இணைக்க வேண்டும்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

பாடத்தின் மீதிப் புள்ளிகளும் உதாரணமும்

பலன்கள்: prototype கட்டுமுன் alternatives-ஐ எண்ணிக்கையால் ஒப்பிடலாம்; bottleneck operator தெரியும்; task-ஐ மீண்டும் கணிக்கக்கூடிய படிகளாகப் பிரிக்கலாம். வரம்புகள்: novice learning, errors, exploration, fatigue, emotion, interruption ஆகியவை basic expert-time model-இல் இல்லை.

அதனால் “shortcut model-இல் வேகம்” என்பதிலிருந்து “அனைத்து users-க்கும் இதுவே சிறந்த UX” என்று முடிவுசெய்யாதீர்கள். Model ஒரு design ஆதாரம்; representative users-உடன் evaluation அதை நிரப்பவேண்டும்.

✅ Strengths

  • Objective, repeatable numbers to compare prototypes
  • Saves time and money: finds bottlenecks before user testing
  • Breaks complex tasks into measurable micro-steps

⚠️ Limitations

  • Assumes expert, error-free performance. No novice confusion, slips or exploring
  • Ignores fatigue, stress, emotion, delight, creativity
  • Hard to use when goals are unstructured or keep changing
Exam focus

Expect:

  • "Explain GOMS with an example": draw the goal → methods → selection rule
  • KLM time calculation: list the operators and add their times
  • "State Fitts's law and give UI design implications": big targets, edges and corners, keep small targets close
  • "Limitations of GOMS/KLM"

✅ பலங்கள்

  • முன்மாதிரிகளை ஒப்பிட புறநிலையான, மீண்டும் பெறக்கூடிய எண்கள்
  • நேரமும் பணமும் மிச்சம்: பயனர் சோதனைக்கு முன்பே தடைகளைக் கண்டறிகிறது
  • சிக்கலான பணிகளை அளக்கக்கூடிய சிறு படிகளாகப் பிரிக்கிறது

⚠️ வரம்புகள்

  • வல்லுநரின் பிழையற்ற செயல்திறனை அனுமானிக்கிறது. புதியவரின் குழப்பம், செயல் வழுவல்கள், ஆராய்தல் இல்லை
  • சோர்வு, மன அழுத்தம், உணர்ச்சி, மகிழ்ச்சி, படைப்பாற்றலைப் புறக்கணிக்கிறது
  • இலக்குகள் கட்டமைக்கப்படாதபோது அல்லது தொடர்ந்து மாறும்போது பயன்படுத்துவது கடினம்
தேர்வில் கவனம் செலுத்த வேண்டியவை

எதிர்பார்க்கப்படுபவை:

  • “GOMS-ஐ எடுத்துக்காட்டுடன் விளக்குக”: இலக்கு → முறைகள் → தெரிவு விதியை வரைக
  • KLM நேரக் கணக்கீடு: அடிப்படைச் செயல்களைப் பட்டியலிட்டு அவற்றின் நேரங்களைக் கூட்டுக
  • “ஃபிட்ஸின் விதியைக் கூறி UI வடிவமைப்பு விளைவுகளைத் தருக”: பெரிய இலக்குகள், ஓரங்களும் மூலைகளும், சிறிய இலக்குகளை அருகில் வைத்தல்
  • “GOMS/KLM-இன் வரம்புகள்”
