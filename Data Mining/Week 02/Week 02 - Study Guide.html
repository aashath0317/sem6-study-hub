1Data mining = "knowledge mining from data"

தரவிலிருந்து அறிவைப் பெறுதல்

Knowledge mining என்பது பதிவுகளிலிருந்து அர்த்தமுள்ள தொடர்பைப் பெறுவது. பாணும் வெண்ணெயும் சேர்ந்து வாங்கப்படுகின்றன என்ற pattern கடையில் பொருட்களை வைக்க உதவலாம். அது ஒவ்வொரு வாடிக்கையாளருக்கும் பொருந்தும் சட்டம் அல்ல.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

பாறையிலிருந்து தங்கம் எடுப்பது போல data-விலிருந்து knowledge கண்டுபிடிக்கிறோம். KDD முழுப் பயணம்; இந்தப் பாடத்தில் data mining அதற்குள் pattern extraction செய்யும் ஒரு முக்கியப் படி. சிலர் இரண்டையும் loosely ஒரே பொருளில் சொல்வார்கள்; exam-இல் எந்த view என்பதைக் குறிப்பிட்டு ஏழு stages விளக்குங்கள்.

In simple terms, data mining is extracting ("mining") knowledge from large amounts of data.

The gold-mining analogy

Mining gold from rocks is called gold mining, not rock mining. So "data mining" should really be called "knowledge mining from data": the data is the rock and the knowledge is the gold. The name stuck because "knowledge mining from data" is too long, and "knowledge mining" alone loses the idea of large amounts of data.

There are two views of how data mining relates to KDD (Knowledge Discovery from Data):

View 1: synonym

Many people use data mining and KDD to mean the same thing.

View 2: one step

Others see data mining as one essential step inside the larger knowledge discovery process. The notes use this view.

எளிமையாகச் சொன்னால், தரவுச் சுரங்கம் என்பது பெருமளவிலான தரவுகளிலிருந்து அறிவைப் பிரித்தெடுத்தல் ("சுரங்கம் செய்தல்") ஆகும்.

தங்கச் சுரங்க ஒப்புமை

பாறைகளிலிருந்து தங்கத்தை எடுப்பது தங்கச் சுரங்கம் எனப்படுகிறது; பாறைச் சுரங்கம் என்றல்ல. எனவே "தரவுச் சுரங்கம்" உண்மையில் "தரவிலிருந்து அறிவைச் சுரங்கம் செய்தல்" எனப்பட வேண்டும்: தரவு பாறை; அறிவு தங்கம். "தரவிலிருந்து அறிவைச் சுரங்கம் செய்தல்" நீளமான பெயர் என்பதாலும் "அறிவுச் சுரங்கம்" மட்டும் பெருமளவு தரவுகள் என்ற கருத்தை இழக்கச் செய்வதாலும் இந்தப் பெயர் நிலைத்தது.

தரவுச் சுரங்கத்துக்கும் KDD (தரவிலிருந்து அறிவைக் கண்டறிதல்) என்பதற்கும் உள்ள தொடர்பைப் பற்றி இரு பார்வைகள் உள்ளன:

பார்வை 1: ஒரே பொருளுடையவை

பலர் தரவுச் சுரங்கம், KDD ஆகியவற்றை ஒரே பொருளில் பயன்படுத்துகின்றனர்.

பார்வை 2: ஒரு படி

மற்றவர்கள், பெரிய அறிவுக் கண்டறிதல் செயல்முறைக்குள் தரவுச் சுரங்கத்தை ஓர் இன்றியமையாத படியாக கருதுகின்றனர். குறிப்புகள் இந்தப் பார்வையைப் பயன்படுத்துகின்றன.

2The 7 steps of the KDD process

KDD-இன் ஏழு படிகள்

சுத்தப்படுத்துதல், இணைத்தல், தேர்வு, மாற்றம், mining, மதிப்பீடு, விளக்கமாகக் காட்டுதல் ஆகியவை KDD. Data mining அதற்குள் ஒரு படி மட்டுமே. குப்பைத் தரவை நேரடியாக algorithm-க்கு கொடுத்தால் முழு செயலும் பாதிக்கப்படும்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

ஏழு படிகள்: (1) Cleaning — தவறு/noise சரிசெய்; (2) Integration — sources இணை; (3) Selection — தேவையான data எடு; (4) Transformation — ஏற்ற வடிவம் மாற்று; (5) Mining — pattern தேடு; (6) Evaluation — பயன்படும் pattern தேர்வு; (7) Presentation — மனிதர் புரியும் வடிவில் காட்டு. முடிவில் குறை தெரிந்தால் முந்தைய படிகளுக்குத் திரும்பலாம். KDD முழுச் செயல்முறை; mining அதன் ஐந்தாவது படி.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

ஏழு stages: cleaning பிழை/குறை சரிசெய்; integration sources இணை; selection task-relevant data தேர்வு; transformation ஏற்ற வடிவம்; mining pattern கண்டுபிடி; evaluation பயனுள்ளதா சோதி; presentation user-க்கு புரியும் வடிவில் காட்டு. முதல் நான்கு preprocessing. Evaluation-இல் பிரச்சினை தெரிந்தால் முன்படிகளுக்குத் திரும்பலாம்; ஒரே நேர்கோட்டில் ஒருமுறை முடியும் process அல்ல.

Knowledge discovery is an iterative sequence of these steps (Figure 2-1):

# Step What happens
1 Data cleaning Remove noise and inconsistent data
2 Data integration Combine multiple data sources
3 Data selection Retrieve the data relevant to the analysis task from the database
4 Data transformation Transform or consolidate data into forms suitable for mining, e.g. summary or aggregation operations
5 Data mining The essential step: intelligent methods are applied to extract data patterns
6 Pattern evaluation Identify the truly interesting patterns using interestingness measures
7 Knowledge presentation Visualisation and knowledge-representation techniques present the knowledge to the user

Must-know facts
  • Steps 1–4 are all forms of data preprocessing: they prepare the data for mining.
  • The data mining step may interact with the user or a knowledge base.
  • Interesting patterns are presented to the user and may be stored as new knowledge in the knowledge base.
  • In this view data mining is only one step of the whole process, but an essential one because it uncovers the hidden patterns.
Exam focus

"Explain the steps of the KDD process" is a very common question. Write the 7 steps in order with one line each, then add the point that steps 1–4 are preprocessing. A quick memory chain: C-I-S-T-M-E-P ("Can I See The Mined Evidence Please").

அறிவைக் கண்டறிதல், இந்தப் படிகளின் மீண்டும் மீண்டும் நிகழும் தொடராகும் (படம் 2-1):

# படி என்ன நிகழ்கிறது
1 தரவுத் தூய்மைப்படுத்தல் இரைச்சலையும் முரண்பாடான தரவுகளையும் அகற்றுதல்
2 தரவு ஒருங்கிணைப்பு பல தரவு மூலங்களை இணைத்தல்
3 தரவுத் தேர்வு தரவுத்தளத்திலிருந்து பகுப்பாய்வுப் பணிக்குப் பொருத்தமான தரவுகளைப் பெறுதல்
4 தரவு உருமாற்றம் சுரங்கத்துக்கு ஏற்ற வடிவங்களாகத் தரவுகளை மாற்றுதல் அல்லது ஒருங்குதிரட்டுதல்; எ.கா. சுருக்க அல்லது திரட்டல் செயல்பாடுகள்
5 தரவுச் சுரங்கம் இன்றியமையாத படி: தரவு வடிவங்களைப் பிரித்தெடுக்க நுண்ணறிவு முறைகள் பயன்படுத்தப்படுகின்றன
6 வடிவ மதிப்பீடு சுவாரசியத்தன்மை அளவைகளைப் பயன்படுத்தி உண்மையில் சுவாரசியமான வடிவங்களை அடையாளம் காணுதல்
7 அறிவை வழங்குதல் காட்சிப்படுத்தல் மற்றும் அறிவுப் பிரதிநிதித்துவ நுட்பங்கள் அறிவைப் பயனருக்கு வழங்குகின்றன
தூய்மைப்படுத்தல்ஒருங்கிணைப்புதேர்வுஉருமாற்றம்தரவுச் சுரங்கம்வடிவ மதிப்பீடுவழங்குதல்

அறிந்திருக்க வேண்டிய உண்மைகள்
  • 1–4 படிகள் அனைத்தும் தரவு முன்செயலாக்க வடிவங்களாகும்: அவை தரவைச் சுரங்கத்துக்குத் தயார்படுத்துகின்றன.
  • தரவுச் சுரங்கப் படி பயனருடனோ அறிவுத் தளத்துடனோ இடைவினையாற்றலாம்.
  • சுவாரசியமான வடிவங்கள் பயனருக்கு வழங்கப்படுகின்றன; அறிவுத் தளத்தில் புதிய அறிவாகச் சேமிக்கப்படலாம்.
  • இந்தப் பார்வையில், முழுச் செயல்முறையின் ஒரு படி மட்டுமே தரவுச் சுரங்கம்; ஆனால் மறைந்த வடிவங்களை வெளிக்கொணர்வதால் அது இன்றியமையாதது.
Exam focus

"KDD செயல்முறையின் படிகளை விளக்குக" என்பது மிகவும் பொதுவான கேள்வி. 7 படிகளையும் வரிசையாக ஒவ்வொன்றுக்கு ஒரு வரி எழுதவும்; பின்னர் 1–4 படிகள் முன்செயலாக்கம் என்ற கருத்தையும் சேர்க்கவும். விரைவான நினைவுத் தொடர்: C-I-S-T-M-E-P ("Can I See The Mined Evidence Please" — சுரங்கப்பட்ட ஆதாரத்தை நான் பார்க்கலாமா).

3Architecture of a typical data mining system

Data mining அமைப்பின் பகுதிகள்

Database தகவலை வழங்கும்; mining engine patterns தேடும்; evaluation அவற்றின் பயனை மதிப்பிடும்; interface மனிதருக்குக் காட்டும். Knowledge base தேடலுக்கு வழிகாட்டும். ஒவ்வொரு பகுதியின் வேலையைத் தனியாக நினைவில் கொள்ளுங்கள்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

கீழிருந்து மேலே architecture: databases/warehouse/web→clean/integrate/select→DB/DW server→mining engine→pattern evaluation→UI. Knowledge base domain hierarchies, beliefs, metadata, thresholds மூலம் search/evaluation-ஐ வழிநடத்தும். Engine classification, association, clustering, prediction, outliers, evolution போன்ற functions செய்கிறது. UI-இல் task specify, intermediate results explore, patterns visualise செய்யலாம். தேவையற்ற patterns உருவாக்கியபின் மட்டும் reject செய்யாமல் evaluation constraints-ஐ search-இலேயே பயன்படுத்துவது efficiency-க்கு உதவும்.

Component Role
User interface Links the user and the system. The user can specify a data mining query/task, give information to focus the search, do exploratory mining on intermediate results, browse database/warehouse schemas, evaluate patterns and visualise them in different forms.
Pattern evaluation module Uses interestingness measures and works with the mining modules to focus the search toward interesting patterns. Can use interestingness thresholds to filter out patterns. May be integrated with the mining module.
Data mining engine The essential part: a set of functional modules for characterization, association & correlation analysis, classification, prediction, cluster analysis, outlier analysis and evolution analysis.
Knowledge base Domain knowledge that guides the search or evaluates interestingness: concept hierarchies, user beliefs (to judge how unexpected a pattern is), extra interestingness constraints and thresholds, and metadata.
Database / data warehouse server Fetches the relevant data for the user's request.
Efficiency point from the notes

For efficient mining, push the evaluation of pattern interestingness as deep as possible into the mining process. The search is then limited to interesting patterns only, and the system doesn't waste time generating patterns that will be thrown away.

வடிவ மதிப்பீட்டுக் கூறு சுவாரசியத்தன்மை அளவைகளைப் பயன்படுத்திச் சுரங்கக் கூறுகளுடன் இணைந்து சுவாரசியமான வடிவங்களை நோக்கித் தேடலைக் குவிக்கிறது. வடிவங்களை வடிகட்ட சுவாரசியத்தன்மை வரம்புகளைப் பயன்படுத்தலாம். சுரங்கக் கூறுடன் ஒருங்கிணைக்கப்படலாம்.
தரவுச் சுரங்க இயந்திரம் இன்றியமையாத பகுதி: பண்புவிவரித்தல், தொடர்பு விதி மற்றும் ஒட்டுறவுப் பகுப்பாய்வு, வகைப்படுத்தல், முன்னறிவிப்பு, குழுமப் பகுப்பாய்வு, புறநிலைப் பகுப்பாய்வு, பரிணாமப் பகுப்பாய்வு ஆகியவற்றுக்கான செயல்பாட்டுக் கூறுகளின் தொகுப்பு.
அறிவுத் தளம் தேடலை வழிநடத்தும் அல்லது சுவாரசியத்தன்மையை மதிப்பிடும் துறைசார் அறிவு: கருத்துப் படிநிலைகள், பயனர் நம்பிக்கைகள் (ஒரு வடிவம் எவ்வளவு எதிர்பாராதது என்பதை மதிப்பிட), கூடுதல் சுவாரசியத்தன்மைக் கட்டுப்பாடுகள் மற்றும் வரம்புகள், மேல்தரவு.
தரவுத்தள / தரவுக் கிடங்குச் சேவையகம் பயனரின் கோரிக்கைக்குப் பொருத்தமான தரவுகளைப் பெறுகிறது.

In principle data mining applies to any data repository and also to transient data such as data streams.

Relational databases

A DBMS = a collection of interrelated data (the database) plus software to manage and access it. The software handles defining structures, storage, concurrent/shared/distributed access, and consistency and security, even through system crashes or attempts at unauthorised access.

Details worth remembering

  • Spatial data formats
  • Raster: n-dimensional bit/pixel maps (e.g. each pixel of a satellite image = rainfall in that area)
  • Vector: roads, bridges, lakes as unions of points, lines and polygons
  • Text data structure levels
  • Unstructured: some web pages
  • Semi-structured: e-mail, HTML/XML pages
  • Well structured: library catalogues, which can be stored in relational DBs
  • Multimedia needs support for large objects (gigabytes) and special storage and search. Audio and video need real-time retrieval at a steady rate (to avoid gaps and buffer overflows), so they are called continuous-media data. Promising approaches are multimedia data cubes, feature extraction and similarity-based pattern matching.
  • Web usage mining (Weblog mining) means capturing user access patterns on the web. It helps system design (efficient access between related objects) and marketing (place ads on frequently visited pages, better customer classification).

  • நன்கு கட்டமைக்கப்பட்டவை: தொடர்புநிலைத் தரவுத்தளங்களில் சேமிக்கக்கூடிய நூலகப் பட்டியல்கள்
  • பல்லூடகத்துக்கு, பெரிய பொருட்களை (கிகாபைட்டுகள்) ஆதரிக்கும் சிறப்புச் சேமிப்பும் தேடலும் தேவை. ஒலிக்கும் காணொளிக்கும் சீரான வீதத்தில் நிகழ்நேர மீட்பு தேவை (இடைவெளிகளையும் இடையக நிரம்பிவழிதலையும் தவிர்க்க); எனவே அவை தொடர்ச்சியான ஊடகத் தரவுகள் எனப்படுகின்றன. பல்லூடகத் தரவுக் கனசதுரங்கள், அம்சப் பிரித்தெடுப்பு, ஒற்றுமை அடிப்படையிலான வடிவப் பொருத்தம் ஆகியவை நம்பிக்கைக்குரிய அணுகுமுறைகள்.
  • வலைப் பயன்பாட்டுச் சுரங்கம் (வலைப்பதிவுச் சுரங்கம்) என்பது வலையில் பயனர் அணுகல் வடிவங்களைப் பதிவு செய்தல். இது முறைமை வடிவமைப்புக்கும் (தொடர்புடைய பொருட்களுக்கிடையே திறமையான அணுகல்) சந்தைப்படுத்தலுக்கும் (அடிக்கடி பார்வையிடப்படும் பக்கங்களில் விளம்பரங்கள், சிறந்த வாடிக்கையாளர் வகைப்படுத்தல்) உதவுகிறது.

5Data mining task primitives

எதைத் தேட வேண்டும் என்று சொல்வது

Task primitives-இல் எந்தத் தரவு, எந்த அறிவு, எந்த அளவுகோல், எந்த வடிவில் முடிவு வேண்டும் என்பதை வரையறுப்போம். எல்லாப் பதிவுகளிலும் எல்லா patterns-ஐயும் தேடுவது செலவானதும் பயனற்றதுமாகலாம்.

மேலும் புரிந்துகொள்ள · தேர்வுக் குறிப்புகள்

ஐந்து Task primitives: task-relevant data; தேடும் knowledge வகை; பயன்படுத்தும் background knowledge; interestingness measures/thresholds; முடிவின் presentation. உதாரணம்: கடந்த வருட supermarket baskets-இல், பொருள் hierarchy பயன்படுத்தி, support≥10%, confidence≥60% rules தேடி table-ஆகக் காட்டு. “எதை, எப்படித் தேர்வு செய்து, எந்த format-இல்?” என்பதற்குப் பதில் கிடைக்க வேண்டும்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

ஒரு query-க்கு ஐந்து primitives: எந்த data (Sri Lanka customers); எந்த knowledge (association); background (age/item hierarchies); interestingness (support≥5%, confidence≥70%); output (rules/table/chart/tree). “எந்த algorithm?” என்ற பதில் மட்டும் முழு task specification அல்ல. ஒரே data-இல் வேறு goal/threshold/hierarchy வைத்தால் வேறு patterns பயனுள்ளதாகலாம்.

A user specifies a data mining task as a data mining query. The query is defined in terms of task primitives, which let the user interactively communicate with the system to direct the mining and look at results from different angles.

There are five primitives (Figure 2-4):

# Primitive Specifies Example
1 Task-relevant data Which portion of the database: the relevant attributes or dimensions "Customers in Sri Lanka, attributes age, income, items bought"
2 Kind of knowledge to be mined The function: characterization, discrimination, association/correlation, classification, prediction, clustering, outlier analysis, evolution analysis "Find association rules"
3 Background knowledge Domain knowledge that guides discovery and evaluation: concept hierarchies (mine at multiple levels of abstraction), user beliefs Age hierarchy: 20–29 → young → all
4 Interestingness measures and thresholds How to judge patterns, e.g. support and confidence for association rules. Rules below the user-given thresholds are uninteresting min support 5%, min confidence 70%
5 Representation for visualising patterns Output form: rules, tables, charts, graphs, decision trees, cubes "Show as a decision tree"
Memory hook: "D-K-B-I-V"

# அடிப்படைக் கூறு குறிப்பிடுவது எடுத்துக்காட்டு
1 பணிக்குப் பொருத்தமான தரவு தரவுத்தளத்தின் எந்தப் பகுதி: பொருத்தமான பண்புக்கூறுகள் அல்லது பரிமாணங்கள் "இலங்கையிலுள்ள வாடிக்கையாளர்கள்; வயது, வருமானம், வாங்கிய பொருட்கள் ஆகிய பண்புக்கூறுகள்"
2 சுரங்கப்பட வேண்டிய அறிவின் வகை செயல்பாடு: பண்புவிவரித்தல், வேறுபடுத்தல், தொடர்பு விதி/ஒட்டுறவு, வகைப்படுத்தல், முன்னறிவிப்பு, குழுமமாக்கல், புறநிலைப் பகுப்பாய்வு, பரிணாமப் பகுப்பாய்வு "தொடர்பு விதிகளைக் கண்டறி"
3 பின்னணி அறிவு கண்டுபிடிப்பையும் மதிப்பீட்டையும் வழிநடத்தும் துறைசார் அறிவு: கருத்துப் படிநிலைகள் (பல அருவாக்க நிலைகளில் சுரங்கம் செய்தல்), பயனர் நம்பிக்கைகள் வயதுப் படிநிலை: 20–29 → இளையவர் → அனைவரும்
4 சுவாரசியத்தன்மை அளவைகளும் வரம்புகளும் வடிவங்களை எவ்வாறு மதிப்பிடுவது; எ.கா. தொடர்பு விதிகளுக்கான ஆதரவும் நம்பிக்கையும். பயனர் வழங்கிய வரம்புகளுக்குக் கீழுள்ள விதிகள் சுவாரசியமற்றவை குறைந்தபட்ச ஆதரவு 5%, குறைந்தபட்ச நம்பிக்கை 70%

தரவிலிருந்து அறிவைப் பெறுதல்

Knowledge mining என்பது பதிவுகளிலிருந்து அர்த்தமுள்ள தொடர்பைப் பெறுவது. பாணும் வெண்ணெயும் சேர்ந்து வாங்கப்படுகின்றன என்ற pattern கடையில் பொருட்களை வைக்க உதவலாம். அது ஒவ்வொரு வாடிக்கையாளருக்கும் பொருந்தும் சட்டம் அல்ல.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

பாறையிலிருந்து தங்கம் எடுப்பது போல data-விலிருந்து knowledge கண்டுபிடிக்கிறோம். KDD முழுப் பயணம்; இந்தப் பாடத்தில் data mining அதற்குள் pattern extraction செய்யும் ஒரு முக்கியப் படி. சிலர் இரண்டையும் loosely ஒரே பொருளில் சொல்வார்கள்; exam-இல் எந்த view என்பதைக் குறிப்பிட்டு ஏழு stages விளக்குங்கள்.

KDD-இன் ஏழு படிகள்

சுத்தப்படுத்துதல், இணைத்தல், தேர்வு, மாற்றம், mining, மதிப்பீடு, விளக்கமாகக் காட்டுதல் ஆகியவை KDD. Data mining அதற்குள் ஒரு படி மட்டுமே. குப்பைத் தரவை நேரடியாக algorithm-க்கு கொடுத்தால் முழு செயலும் பாதிக்கப்படும்.

ஏழு படிகள்: (1) Cleaning — தவறு/noise சரிசெய்; (2) Integration — sources இணை; (3) Selection — தேவையான data எடு; (4) Transformation — ஏற்ற வடிவம் மாற்று; (5) Mining — pattern தேடு; (6) Evaluation — பயன்படும் pattern தேர்வு; (7) Presentation — மனிதர் புரியும் வடிவில் காட்டு. முடிவில் குறை தெரிந்தால் முந்தைய படிகளுக்குத் திரும்பலாம். KDD முழுச் செயல்முறை; mining அதன் ஐந்தாவது படி.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

ஏழு stages: cleaning பிழை/குறை சரிசெய்; integration sources இணை; selection task-relevant data தேர்வு; transformation ஏற்ற வடிவம்; mining pattern கண்டுபிடி; evaluation பயனுள்ளதா சோதி; presentation user-க்கு புரியும் வடிவில் காட்டு. முதல் நான்கு preprocessing. Evaluation-இல் பிரச்சினை தெரிந்தால் முன்படிகளுக்குத் திரும்பலாம்; ஒரே நேர்கோட்டில் ஒருமுறை முடியும் process அல்ல.

Data mining அமைப்பின் பகுதிகள்

Database தகவலை வழங்கும்; mining engine patterns தேடும்; evaluation அவற்றின் பயனை மதிப்பிடும்; interface மனிதருக்குக் காட்டும். Knowledge base தேடலுக்கு வழிகாட்டும். ஒவ்வொரு பகுதியின் வேலையைத் தனியாக நினைவில் கொள்ளுங்கள்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

கீழிருந்து மேலே architecture: databases/warehouse/web→clean/integrate/select→DB/DW server→mining engine→pattern evaluation→UI. Knowledge base domain hierarchies, beliefs, metadata, thresholds மூலம் search/evaluation-ஐ வழிநடத்தும். Engine classification, association, clustering, prediction, outliers, evolution போன்ற functions செய்கிறது. UI-இல் task specify, intermediate results explore, patterns visualise செய்யலாம். தேவையற்ற patterns உருவாக்கியபின் மட்டும் reject செய்யாமல் evaluation constraints-ஐ search-இலேயே பயன்படுத்துவது efficiency-க்கு உதவும்.

எந்தத் தரவை ஆய்வு செய்யலாம்?

அட்டவணை மட்டும் அல்ல; விற்பனை transactions, text, images, காலவரிசை போன்றவற்றையும் ஆய்வு செய்யலாம். தரவின் வடிவத்தைப் பொறுத்து preprocessing, algorithm மாற வேண்டும்.

Relational data rows/columns; transaction data ஒவ்வொரு basket-இன் items; warehouse ஒருங்கிணைந்த historical data. Advanced types: temporal — time-dependent states; sequence — வரிசை முக்கியம்; time-series — நேர இடைவெளியில் அளவுகள்; spatial — இடம்/வரைபடம்; spatiotemporal — இடமும் நேரமும்; text; multimedia; heterogeneous; legacy; web. “ஒவ்வொரு வெள்ளியும் விற்பனை உயர்கிறது” என்பது time pattern; “A வாங்கியபின் B வாங்குகிறார்கள்” என்பது sequence pattern.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

Data வகைகளை example-உடன் வேறுபடுத்து: relational rows/tables; transaction ID+item list; warehouse integrated historical data; temporal timestamps; sequence event order; time-series repeated numeric readings; spatial location; text; multimedia; heterogeneous/legacy sources; web/streams. Raster=pixels; vector=points/lines/polygons. Email/XML semi-structured ஆகலாம். Audio/video continuous media-க்கு சரியான rate-இல் retrieval முக்கியம். Web usage mining access logs-இன் behaviour; web content mining page content.

எதைத் தேட வேண்டும் என்று சொல்வது

Task primitives-இல் எந்தத் தரவு, எந்த அறிவு, எந்த அளவுகோல், எந்த வடிவில் முடிவு வேண்டும் என்பதை வரையறுப்போம். எல்லாப் பதிவுகளிலும் எல்லா patterns-ஐயும் தேடுவது செலவானதும் பயனற்றதுமாகலாம்.

ஐந்து Task primitives: task-relevant data; தேடும் knowledge வகை; பயன்படுத்தும் background knowledge; interestingness measures/thresholds; முடிவின் presentation. உதாரணம்: கடந்த வருட supermarket baskets-இல், பொருள் hierarchy பயன்படுத்தி, support≥10%, confidence≥60% rules தேடி table-ஆகக் காட்டு. “எதை, எப்படித் தேர்வு செய்து, எந்த format-இல்?” என்பதற்குப் பதில் கிடைக்க வேண்டும்.

விரிவான விளக்கம் · கணக்கும் தேர்வுப் புள்ளிகளும்

ஒரு query-க்கு ஐந்து primitives: எந்த data (Sri Lanka customers); எந்த knowledge (association); background (age/item hierarchies); interestingness (support≥5%, confidence≥70%); output (rules/table/chart/tree). “எந்த algorithm?” என்ற பதில் மட்டும் முழு task specification அல்ல. ஒரே data-இல் வேறு goal/threshold/hierarchy வைத்தால் வேறு patterns பயனுள்ளதாகலாம்.
