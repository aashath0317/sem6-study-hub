## Why graphs?

**Graphs are discrete structures made of vertices and edges that connect them.** They model a huge range of problems:

- **Competition** between species in an ecological niche
- **Who influences whom** in an organisation
- **Round-robin tournament** outcomes
- **Acquaintanceships** between people and **links** between websites
- **Roadmaps** and **assigning jobs** to employees
- Whether a circuit fits on a **planar circuit board**
- Telling apart **chemical compounds** with the same formula but different structures
- Whether two computers are **connected** in a network

## The birth of graph theory — Königsberg

:::example The Königsberg bridge problem
- **Königsberg** (Prussia) lay on the Pregel river, which split the city into **four landmasses** (including the island of Kneiphopf).
- **Seven bridges** linked them.
- Residents asked: *can you leave home, cross **each bridge exactly once**, and return home?*
- **Leonhard Euler (1707–1783)** solved it. He turned each landmass into a **vertex** (A, B, C, D) and each bridge into an **edge**. His method is considered the **birth of graph theory**.
:::

:::tip Euler's answer: no
A closed walk using every edge exactly once needs **every vertex to have even degree** (you leave a landmass as often as you enter it).

In Königsberg the degrees are **A = 5, B = 3, C = 3, D = 3**, all odd, so it's **impossible**. Load the Königsberg preset in the graph lab below to see it.
:::

## What is a graph?

:::key Definition 1
A **graph G = (V, E)** consists of:

- **V**: a **non-empty set of vertices** (nodes)
- **E**: a set of **edges**

Each edge has **one or two vertices** associated with it, called its **endpoints**. An edge **connects** its endpoints.
:::

| Term | Meaning |
|---|---|
| **Infinite graph** | **Infinite** vertex set (or infinitely many edges) |
| **Finite graph** | **Finite** vertex set **and** finite edge set. *This course uses finite graphs only* [[v3 01:24]] |
| **Multiple edges** | Two or more edges joining the **same pair** of vertices |
| **Multiplicity m** | When m different edges join the same unordered pair {u, v}, {u, v} is an **edge of multiplicity m** [[v3 06:43]] |
| **Loop** | An edge that **starts and ends at the same vertex** [[v3 05:20]] |

## The six types of graphs

The PDF builds these types using a **computer network of data centres**: San Francisco, Los Angeles, Denver, Chicago, Detroit, New York, Washington.

### Undirected graphs

| Type | Definition | Network example |
|---|---|---|
| **Simple graph** | Each edge connects **two different vertices**, and **no two edges** connect the same pair. **No multiple edges, no loops** | One link between each pair of connected data centres (Figure 3). Each edge can be named by its unordered pair {u, v} |
| **Multigraph** | **Multiple edges allowed**, **no loops** [[v3 06:09]] | Several links between the same data centres, e.g. two between Los Angeles and Denver (Figure 4) |
| **Pseudograph** | **Multiple edges and loops** allowed [[v4 00:01]] | A link from a data centre to itself, a **diagnostic feedback loop** (Figure 5). Not every vertex needs a loop |

### Directed graphs (digraphs)

Some links work in **one direction only** (single duplex lines), e.g. heavy traffic one way. So we use **directed edges (arcs)**, drawn as **arrows** [[v4 01:42]].

:::key Definition 2 — directed graph
A **directed graph (digraph) G = (V, E)** has a non-empty vertex set V and a set E of **directed edges**. Each directed edge is associated with an **ordered pair (u, v)**: it **starts at u and ends at v**.
:::

:::tip Ordered vs unordered pairs [[v4 03:06]]
- **{u, v}** (undirected): you can travel u → v **or** v → u.
- **(u, v)** (directed): you must start at **u** and end at **v**. San Francisco → Denver does **not** allow Denver → San Francisco.
:::

| Type | Definition |
|---|---|
| **Simple directed graph** | Directed, **no loops, no multiple directed edges**. At most one edge per ordered pair, so (u, v) names the edge |
| **Directed multigraph** | Directed, **multiple directed edges** (and loops) allowed. Formally G = (V, E, f), where f maps each edge to an ordered pair (Figure 7: e₁ v₁→v₂, e₂ v₂→v₃, e₄ v₁→v₃) |
| **Mixed graph** | Has **both directed and undirected** edges, e.g. a network with two-way and one-way links |

### Table 1 — graph terminology (learn this)

| Type | Edges | Multiple edges? | Loops? |
|---|---|---|---|
| Simple graph | Undirected | No | No |
| Multigraph | Undirected | **Yes** | No |
| Pseudograph | Undirected | **Yes** | **Yes** |
| Simple directed graph | **Directed** | No | No |
| Directed multigraph | **Directed** | **Yes** | **Yes** |
| Mixed graph | **Directed and undirected** | **Yes** | **Yes** |

:::tip How to classify any graph [[v5 00:50]]
Ask three questions, in order:

1. **Arrows?** None means undirected; all means directed; some means **mixed**.
2. **Multiple edges** between the same pair?
3. **Loops?**

Then read the type off Table 1.
:::

## Graph models

When building a model, answer the three key questions: **directed or undirected? multiple edges? loops?**

| Model | Vertex | Edge | Type |
|---|---|---|---|
| **Acquaintanceship graph** (social network) | A person | **Undirected**: the two people **know each other** | **Simple graph**: no multiple edges, usually no loops (loops only if you model "self-knowledge"). A worldwide one would have about 7 billion vertices and over a trillion edges [[v6 01:03]] |
| **Influence graph** (social network) | A person | **Directed a → b**: a **influences** b | **Simple directed graph** (no loops or multiple edges). E.g. Deborah influences Brian, Fred and Linda, but no one influences her; Yvonne and Brian influence each other [[v6 03:16]] |
| **Web graph** (information network) | A web page | **Directed a → b** if page a **links to** b | Directed. More than **3 billion vertices and 20 billion edges**, changing constantly [[v6 04:39]] |
| **Citation graph** (information network) | A paper or patent | Directed: a **cites** b | Directed, no loops or multiple edges |
| **Roadmap graph** | An **intersection** | A **road**: undirected = two-way, directed = one-way, multiple = several roads, loop = loop road | Two-way only, no loops or duplicates: **simple**. One-way only: **simple directed**. Both: **mixed** |
| **Airline routes** | An airport | A **directed edge for each flight** | **Directed multigraph** [[v6 06:40]] |
| **Round-robin tournament** | A team | **(a, b)** if team **a beats b** | **Simple directed graph** (each pair plays once). In Figure 10, Team 1 is undefeated and Team 3 is winless [[v6 07:38]] |
| **Single-elimination tournament** (extra) | A game | Directed from a game to the next game | Directed (tree-like) |

:::example The airline exercise, three ways [[v5 02:20]]
Cities: Boston, Newark, Miami, Detroit, Washington.

- **(a)** One edge between cities that have **any** flight between them → **simple graph**.
- **(b)** One edge **for each flight** → **multigraph** (several flights between the same cities).
- **(c)** The same as (b) **plus a loop** for a sightseeing trip that takes off and lands in Miami → **pseudograph**.
:::
